# GUI の保守

`#include "module.vs"` は `export import "module.vs";` と同じ必要性判定を使い、この別名だけではフレームワークを読み込みません。バイナリの include では公開マクロの検査を維持します。GUI を有効にしたルートビルドでは、Core のサンプルとパッケージクライアントの回帰テストにテスト専用ホスト `VeroScriptCliCoreTests` を使います。GUI 統合テストは配布 CLI を使用し、マクロとジェネレーターの保守的な処理を別途検証するため、Core テストの期限を延長しません。

Gui は widget/property/event、scope/Schema、ML/CSS と lifecycle を所有します。Platform/Graphics/Image/Font は公開 service、RmlUi/Stb/FontBackend は別 provider です。module environment、generation root、owner cleanup、type/value parameter、compile identity を保持します。JIT dispatch と明示 cost-model fallback を別に確認し、非対応 fallback だけでは合格にしません。

独立 CMake または VEROSCRIPT_BUILD_GUI、script/compile 統合は VEROSCRIPT_GUI_SCRIPTING を使います。VEROSCRIPT_GUI_USE_VISUAL_SDK は installed foundation、VEROSCRIPT_GUI_BUILD_RESOURCE_BACKENDS は Stb/FontBackend を制御します。ABI/bytecode 変更後は対応 Core/C++ Runtime で再構築します。native lifecycle、script、Schema、ML、installed consumer、描画/入力/フォント/各 platform を個別検証し、静的確認を runtime/IDE 認定にしません。

スクリプトのホストは `FEngineConfig::VmBackendFactory` または `VmBackendPath` で VM を明示的に選択します。マークアップスクリプトは `FMarkupScriptOptions::Engine` を使用します。GUI は既存の設定を保持し、ホストの選択を実行とコンパイルプロセッサへ渡します。公式バイトコード VM は独立した `vs-bytecode` プロバイダーです。Gui のリンクやインストールでは自動選択されません。ネイティブのウィジェットツリーとスクリプトを含まない ML/CSS の解析には VM は不要です。

スクリプト回帰テストは独立したシナリオとして登録します。`ctest --test-dir BUILD -R VeroScriptGuiScriptTests --parallel 4 --output-on-failure` で全シナリオを実行できます。VeroScriptGuiScriptTests の直接実行は既定で全件を実行し、シナリオ名一つも指定できます。既存の検証は保持し、テストの制限時間はアプリの実行期限を変更しません。

コアはコスト、参照、finally の意味を保つため getter を VM に残す場合があります。JitSynchronization は NativeLeafExecutions／NativeCfgExecutions、dispatch、Linear／Bridge／VM trampoline の入口とフォールバックを分け、Session を再利用した連続呼び出しで対応するネイティブ入口と呼び出しごとの計数も検証します。ScalarNativeFastPathCalls はホストのスカラー呼び出しであり、スクリプトの全ネイティブ実行ではありません。入れ子の計数を独立した呼び出しとして加算しないでください。詳細診断は既定で無効です。別の診断実行でのみ FJitPolicy.Diagnostics を設定し GetLastJitDiagnostics() を読み、スループット測定では無効のままにします。

`ApplicationOptions.FontBackend` と `TextLayoutBackend` は別々のサービスを選択します。空フィールドは `FApplicationFactories.DefaultBackend` またはホスト／CLI の選択（`--font-backend`、`--text-layout-backend`）を継承し、`auto` は候補選択、`none` は任意サービスの無効化です。ネイティブホストがそのサービスの既定値を提供しない場合だけ、`FApplication::Create` は従来の代替値 `font-backend` を使います。`FApplicationFactories.Font` / `TextLayout` またはネイティブの `Fonts` / `TextLayouts` を渡します。同時に存続する RmlUi コンテキストは不変のインスタンスを共有し、登録ファクトリは弱いキャッシュを使います。設定変更前にコンテキストを閉じてください。`FTextLayout::Create` は選択したサービスを先頭に受け取り、そのインスタンス ID を段落キャッシュに含めます。GUI `0.1.1`、Font `0.1.2`、text-layout `0.1.0` に一致する提供者と利用者を再ビルドします。`ContractVersion` は Gui の `Version` を参照します。静的レビューは実行検証の代わりにはなりません。

## ソースインポート方針

通常の CLI 設定ではネイティブバインディングを保持し、ソースに応じてフレームワークを読み込みます。GUI 名、注釈、生成 ML が要求し、コメントや文字列だけでは要求しません。.vs で終わるソースインポートも同様に検出します。小さいローカル .vslib は追跡された依存関係として公開マクロを検査し、通常の宣言や引数を持たずリテラルだけを含むマクロはフレームワークを要求しません。数値・文字・文字列の定数マクロや通常の条件ディレクティブだけでは要求しません。引数付きのソース／ホスト／インポートライブラリの公開マクロ、置換内容に名前を含むマクロ、トークン結合、文字列化、未知のディレクティブ、ホストマクロと併用する不透明な暗黙プロバイダー、未解決・エスケープ付き・論理・大容量のインポート、独自プロセッサーは全体インポートを保持します。gui-* タスクと ConfigureGuiScriptEngine は暗黙インポートを維持します。コンパイルメタデータとキャッシュ識別情報を整合させ、GUI を使わないソースとインポートやプロセッサーから GUI を導入するソースを回帰検証してください。

固定プロパティの同期では、コールバック前に入力フィールドのリビジョンを取得し、成功かつ登録が変わっていない場合だけ確定します。評価中の変更は次の同期でも検出され、失敗や再登録で古いスナップショットは確定されません。入力バッファーを再利用し、保持した既定設定は参照元を切り替える際にだけ消去します。動的 getter は引き続き各同期ラウンドで実行されます。

`BakeGuiApplication` は組み込み用の内部 Core イメージ API として維持します。CLI はそのバイト列を直接 `.vsapp` にせず、`Application::BuildApplication` と `WriteArchive` で封入します。アプリケーションの準備フックはパッケージのプロバイダーが利用可能になった後に GUI リソースサービスを復元します。通常の CLI と GUI 対応 Runtime は同じ経路を使います。ZIP 構造、inspect、検査、ソース削除後の移動実行を併せて検証します。Application 非対応でも GUI ソースの検査／プレビューは使えますが、コンテナーの生成／読み込みは不足する機能を報告します。

ソースの `import compiler` ジェネレーターでは、Core の拡張期限に GUI ソースグラフ全体の準備時間も含まれます。大きなグラフには、CLI の `--compiler-timeout 20000` またはネイティブホストの `FCompileOptions::ScriptCompileExtensions.TimeoutMilliseconds` で適切な予算を設定してください。

入力の同一性とリビジョンが不変と確認できた場合、フィールドを再走査せず、コールバック前のスナップショットを再利用します。設定が不変なら参照元の分類は再利用できますが、getter の結果は同期ラウンドを越えて再利用しません。フレームワークの数値コントロール本体は、自身のネイティブコールバック内で getter 実行中以外に限り、同期済みプロパティからネイティブ状態を設定できます。手動同期、派生型、再帰的な問い合わせは通常の getter 経路を使います。継承プロパティの親 getter は各ラウンドで評価し、不変の検証済み値のコピーと再検証を省きます。 ネイティブ属性のディスパッチは有効なマスクのグループを確認し、getter の順序とすべての有効なバインディングを維持します。

ネイティブの数値・真偽値・文字列属性は、同期と取得の両方で値スナップショットと参照出力を使い、一時的な optional オブジェクトを省きます。空の結果はフォールバックを維持し、次の評価世代で再評価します。検証済みのネイティブスコープでは、フレームワークの正確な数値コントロール型に限り、生成された空の変更フックを省略できます。派生型と宣言済みフックは仮想呼び出しを維持します。

固定のネイティブ属性設定は、定期的なスクリプト評価を必要としません。設定変更、ネイティブの変更、再マウントでは同期を再開します。バインドされた getter と optional getter は、空の結果の後も各評価輪で呼び出します。

各ウィジェットは独立したネイティブキャッシュオブジェクトを所有します。内部スナップショットの更新によって入力設定の追跡は変化せず、設定を置き換える setter は引き続き同期を再開します。

基底 Widget の正確な型も同期を休止できます。注釈のない派生型は、従来の保守的なカスタム同期経路を維持します。

attribute 設定の分類は Set/Reset で設定が置き換わるまでだけキャッシュします。分類は getter を評価せず、バインド済み・optional getter は必要な各評価世代で実行します。

置き換え時は新設定とその分類の公開まで旧ペイロードを保持します。デストラクタの再入による新状態の読み取りや置き換えを、外側の処理が上書きしません。

## 変更通知バインディングと一括更新

ネイティブの通知グラフは弱いウィジェット購読を使い、重複通知をまとめます。ウィジェットが購読トークンと通常の attribute 読み取り器を所有し、トークン破棄にはスクリプト終結コールバックが不要です。Bridge 共通の単調カウンターで通知に番号を付けるため、固定依存集合の最大番号で変更を正確に判定できます。ハッシュや毎回のスクリプト配列作成は不要です。共有 Binding は成功した読み取りのみをキャッシュし、optional 無値も保持します。従来の動的 attribute の epoch は変えません。

IFrameBindingService は全 BeginFrame 後に公開段階を追加し、既存の `IFrameService` の仮想インターフェイスは変えません。対象ウィジェットを重複排除して既存のライフサイクル観察者を起動し、属性ごとのスクリプトタスクや強制レイアウト無効化を避けます。既存同期が結果比較、ライフサイクル順序、失敗 Getter の再試行を担当します。スクリプト所有の観察者はホスト直接更新にも対応します。ネイティブのバッチ深度とスクリプトラッパーで中間状態の更新を拒否します。通常の setter と ClearX は購読を解除し、内部インストールは旧キャプチャ解放前に新設定を公開します。 FromAttribute は既定 attribute やネイティブスタイルの独立した変更に対応するためフォールバックのポーリングを維持します。渡された Getter の結果自体は通知リビジョンでキャッシュします。

## 同期結果と描画送信

ネイティブ同期は Getter、継承、変更フックを実行した後に、解決済みプロパティの出力を再利用します。値の変更とアニメーションのサンプリング、停止、終了は出力を更新します。通知は有効な設定スナップショットを保持します。各 Widget は安定したキャッシュコンテナを所有し、ネイティブプロパティのキャッシュを初回使用時に作成します。この出力の書き込みは入力設定のスナップショットを無効にしません。通常の動的 attribute と FromAttribute のフォールバックは、従来の評価・再試行規則を維持します。

RmlUi は任意の IRenderSubmission2D スコープを使って、同じレンダラーの連続パスをまとめて送信します。別レンダラーのコンポジターが読み取る前に生成側を送信し、その後で記録を再開します。失敗や例外では未完了のスコープを取り消します。スワップチェーン画像が取得できない場合、内部一時レイヤーだけに書き込む未送信の処理は取り消せますが、永続キャプチャーは完了させます。SDL_GPU とそのモジュールプロバイダーが対応し、他のレンダラーは従来の経路を維持します。OnPaint は毎回の Render で実行されます。

スクリプトのキャッシュ無効化スタンプはネイティブ通知の公開前に進みます。公開後に実行が中断されても、共有結果を最新と誤認しません。実際の変更は引き続き依存先のリビジョンで判定します。この順序は、中断された実行のトランザクション的なロールバックを保証しません。

Observable.Set は finally 内で通知を公開し、値の書き込み後に実行が中断される場合も対象とします。失敗・中断した代入は安全のためキャッシュを無効化する場合があります。同じ値の設定では引き続き通知しません。復旧には下記の Core RequiresReset 契約が適用されます。

評価・初期化・構築の一時フラグは保護されたスコープ内で変更し、入れ子の評価とバッチは開始前の深さに戻します。購読解除コールバックの失敗後は再試行でき、再帰的な解除は抑止します。制限超過・タイムアウト・キャンセル後の復旧は Core の上限付きクリーンアップに依存します。Core がリセットを要求した場合は、対象の GUI スクリプトセッションとバインドコンテキストを作り直してください。GUI の finally はアプリケーション状態のトランザクション的なロールバックを保証しません。

ネイティブプロパティは元の順序を保った九つのグループで同期し、動的評価と例外後の復旧を維持します。弱参照のコントロールコールバックはスクリプトに入ってから破棄状態を再確認し、破棄済みならホストブリッジへ再入せずに処理を終了します。

ML のキャプチャ初期化式は外側のスコープで書き換え、キャプチャの別名はクロージャ本体内だけで有効になります。属性ソースのスナップショットは Core のアンラップ API を使い、参照または読み取り専用キャプチャの格納先にある属性オブジェクトの識別と更新番号を比較します。通常のオブジェクトフィールドは直接読み取り、キャプチャ内容を追加保持しません。コールバックは引き続き FValueRoot と InvokeCallable を使用し、業務 API は変更しません。

ネイティブのスカラープロパティ同期では、値を取得できなかった場合だけ設定を再確認し、通常の値取得経路の重複照会を省きます。キャッシュと getter のインターフェースは変更しません。順序付きの同期グループではスカラーの管理変数を再利用し、プロパティ値のスコープは独立したままです。共有 Binding は再帰状態を確認してからリビジョンキャッシュを再利用し、キャッシュにヒットした場合は追加の更新メソッド呼び出しを省略します。

ネイティブ要素の検索とスタイルの存在確認には読み取り専用のメンバーメタデータを明示し、Core が const ホストハンドルや値キャプチャから呼び出せるようにします。変更操作のメタデータと公開 GUI API は維持します。

## ネイティブ成果物の保守

ネイティブオプション、公開レイアウト、埋め込みライブラリーを変更したら、GUI プロバイダー、ホスト、スクリプトライブラリー、SDK・パッケージ候補を一緒に再ビルドします。同じ製品バージョン表記だけでは実装の互換性を保証しません。

## バックエンドの既定値と内部分派

実装補助型とスクリプトのディスパッチ入口は `VS::Gui::Internal` を使用します。`NativeAttributeCache<T>` と `NativeValueAttributeCache<T>` はフレームワークの内部実装であり、アプリケーション向け API ではありません。`Vsgui` で始まるメンバーは、名前衝突を避けるため、生成コードと継承フックの予約名として維持します。

インポート検出は名前空間／注釈の利用と、単に `Gui` という名前の変数、フィールド、引数を区別します。検出を変更したら処理器の設定 ID も更新します。ネイティブバインディング、生成呼び出し、両エディターの抽出器を完全修飾された `VS::Gui::Internal` 名に合わせてください。`FContext` は形状変更時に `bLayoutNotificationPending` を設定し、コールバック前に全形状を公開して、配送成功後だけ解除します。失敗または未配送の通知は保留し、成功済み通知は新しい変更まで繰り返しません。マウントフックの変更はレイアウト前、レイアウトフックの変更は次の `Update` で同期します。入力／描画には更新の成功が必要です。失敗と再試行、兄弟への通知、コールバックから見える形状をそれぞれ検証します。

## 同期の実装

静的な高速経路は、実行時型の完全一致、初期化完了、独自のスクリプト同期がないことを条件とします。未知の派生型は保守的な経路を維持します。固定のプリミティブ設定ではポーリングを停止できますが、設定置換、Setter、スタイル、ホスト変更、バインディング設定で再開します。バインド済みおよび optional Getter は空結果でも引き続き評価します。弱い監視はウィジェットを保持してはいけません。

生成されたプリミティブプロパティは、ローカル値、スタイル、出力をボックス化せずに保持します。変更トークンはコールバック成功後だけ確定し、失敗や再登録で古い入力を確定してはいけません。ネイティブ変更トークンは未変更状態の再読取りを減らしますが、動的 Getter と独自 Codec は省略しません。組み込みスタイルリテラルの解析結果は保持し、変数展開、リソース解決、セレクター、テーマは引き続き更新します。共通 Builder メソッドは型とともに出力し、構文を変えずに宣言操作を減らします。

ネイティブ同期中は、現在マウントされたウィジェットの繰り返し検査に、コールバック入口で検証したスコープを使います。成功／失敗後に必ず復元し、他のウィジェットとコールバック外の照会は通常の検査を保ちます。属性評価、optional の代替、安定化、ライフサイクル順序を維持してください。

## Context の代替値と Runtime オプションの振り分け

`Private/Bindings/VeroScriptGuiRuntimeBindings.cpp` の標準 `__NativeContext` コンストラクターブリッジは、引数省略時に `FScriptServices.DefaultBackend("gui")`、次に解決済み `Application.DefaultBackend("gui")` を参照します。`Factories.Gui` 呼び出し前に空結果を再確認し、その場合だけ `rmlui` を使います。明示 ID/auto/none は保持します。`FScriptServices.CreateContext` はこの分岐を通らずホストが管理します。`VeroScriptRuntimeMain.cpp` では VM/JIT を実行設定とパッケージの `SelectedBackends` に保ち、GUI コマンドアダプターへ渡す値から `vm` と `jit` を除きます。コールバックなし、空結果、環境の優先度、明示選択、VM/JIT 指定での GUI コンテナー検査／実行をそれぞれ確認します。

## シーン再利用と同期の境界

スタイル同期では、変化していないシーン構造とセレクターの照合結果を再利用します。通常の形状、テキスト、アニメーションの出力だけでは照合キャッシュを無効化しません。リソース解決、スタイル値のデコード、動的 Getter は従来の同期規則を維持します。生成コードによって周期的な処理が不要と確認できたウィジェットだけがポーリングを停止し、動的バインディングや未知の同期処理は既存の経路を使用します。

`FMarkupRuntime::MatchesScene` はテーマ、ウィジェット、親、名前スコープ、所属、スタイルシートを比較して `FContext::SceneStyles` を再利用します。セレクター結果は適格性、フォーカス／モーダル／ホバー／押下とスタイル入力を追跡し、動的な適格性 getter があれば再利用しません。適用前の入力を記録し、スタイル出力が次の安定化ラウンドを無効化するようにします。ルート交換と破棄でシーンを解放します。`CanSuspendSynchronization` は不明なメソッド／コンストラクター、他プロセッサー生成、codec、ヘルパーのない古いパッケージ基底で保守的に扱います。非公開生成名はモジュールの正規リンケージ識別を保持します。

## GUI コンパイル設定

GUI の `CompilerOptions` は選択 VM をコンパイル拡張へ渡します。明示 VM がなく `bClearVmBackend` が false の場合だけ `FallbackVmBackendFactory`/`FallbackVmBackendPath` を使い、拡張側が未指定の場合だけ `ExecutionControl` を継承します。明示的な無効化と呼出し元独自の制御を維持します。

## レイアウト利用側の不変条件

段落キャッシュの識別には、論理テキストと方向に加え、選択したサービスのインスタンスと不変の設定を含めます。バックエンド ID だけでは不十分です。スタイル範囲をまたぐ論理段落を保持し、折り返しを決めてから行単位の bidi 順序を求め、解決したサービスを通じてモジュールの lease を保持します。元のアドバンスとオフセットを保ち、可視クラスタの最後のグリフの後で一度だけ文字間隔を加え、描画を行幅とキャレット位置に一致させます。有限の負の文字間隔と最終行幅の非負クランプを保持します。クリップボードとオフセットは論理順を保ちます。公開の整形・クラスタ・機能制限は [Font 契約](../../../../../VeroScriptFont/Resources/Docs/User/ja-JP/index.md) を正本とします。
