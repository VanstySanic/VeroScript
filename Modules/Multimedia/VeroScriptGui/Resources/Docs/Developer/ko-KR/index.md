# GUI 유지보수

`#include "module.vs"`는 `export import "module.vs";`와 같은 필요성 판정을 사용하며, 이 별칭만으로 프레임워크를 불러오지 않습니다. 바이너리 include의 공개 매크로 검사는 유지합니다. GUI를 활성화한 루트 빌드에서 Core 예제와 패키지 클라이언트 회귀 테스트는 테스트 전용 호스트 `VeroScriptCliCoreTests`를 사용합니다. GUI 통합 테스트는 배포 CLI로 매크로와 생성기의 보수적 처리 정책을 별도로 검증하며 Core 테스트의 제한 시간을 늘리지 않습니다.

Gui는 widget/property/event, 범위/Schema, ML/CSS와 수명주기를 소유합니다. Platform/Graphics/Image/Font는 공개 서비스, RmlUi/Stb/FontBackend는 별도 공급자입니다. 모듈 환경, 세대 루트, 소유 스레드 정리, 형식/값 매개변수와 컴파일 식별자를 보존합니다. JIT 파견과 명시적 비용 모델 폴백을 별도로 검사하며 미지원 폴백만으로 통과시키지 않습니다.

독립 CMake 또는 VEROSCRIPT_BUILD_GUI, 스크립트/컴파일 통합은 VEROSCRIPT_GUI_SCRIPTING을 사용합니다. VEROSCRIPT_GUI_USE_VISUAL_SDK는 설치 기반 모듈, VEROSCRIPT_GUI_BUILD_RESOURCE_BACKENDS는 Stb/FontBackend를 제어합니다. ABI/바이트코드 변경 후 일치 Core/C++ Runtime으로 재빌드합니다. 네이티브 수명주기, 스크립트, Schema, ML, 설치 소비자 및 렌더링/입력/글꼴/각 플랫폼을 따로 검증하며 정적 검사를 런타임/IDE 인증으로 삼지 않습니다.

스크립트 호스트는 `FEngineConfig::VmBackendFactory` 또는 `VmBackendPath`로 VM을 명시적으로 선택하며 마크업 스크립트는 `FMarkupScriptOptions::Engine`을 사용합니다. GUI는 기존 설정을 유지하고 호스트의 선택을 실행 및 컴파일 처리기에 전달합니다. 공식 바이트코드 VM은 독립 공급자 `vs-bytecode`이며 Gui를 링크하거나 설치해도 자동으로 선택되지 않습니다. 네이티브 위젯 트리와 스크립트 없는 ML/CSS 구문 분석에는 VM이 필요하지 않습니다.

스크립트 회귀는 독립 시나리오로 등록합니다. `ctest --test-dir BUILD -R VeroScriptGuiScriptTests --parallel 4 --output-on-failure`로 전체를 실행합니다. VeroScriptGuiScriptTests 직접 실행은 기본적으로 전체를 실행하며 시나리오 이름 하나도 받습니다. 기존 검증을 유지하고 테스트 제한 시간은 앱 실행 기한을 변경하지 않습니다.

코어는 비용, 참조 또는 finally 의미를 보존하기 위해 getter를 VM에 남길 수 있습니다. JitSynchronization은 NativeLeafExecutions／NativeCfgExecutions, 디스패치, Linear／Bridge／VM trampoline 진입과 폴백을 구분하며 Session을 재사용하는 연속 호출에서 지원되는 네이티브 진입과 호출별 카운터도 검증합니다. ScalarNativeFastPathCalls는 호스트 스칼라 호출이며 모든 스크립트 네이티브 실행을 뜻하지 않습니다. 중첩 카운터를 독립 호출로 합산하지 마세요. 상세 진단은 기본적으로 꺼져 있습니다. 별도 진단 실행에서만 FJitPolicy.Diagnostics를 설정하고 GetLastJitDiagnostics()를 읽으며 처리량 측정에서는 끈 상태를 유지합니다.

`ApplicationOptions.FontBackend`와 `TextLayoutBackend`는 별도 서비스를 선택합니다. 빈 필드는 `FApplicationFactories.DefaultBackend` 또는 호스트／CLI 선택(`--font-backend`, `--text-layout-backend`)을 상속하고, `auto`는 후보 선택, `none`은 선택 서비스 비활성화를 뜻합니다. 네이티브 호스트가 해당 서비스의 기본 선택을 제공하지 않을 때만 `FApplication::Create`가 관례적 대체 값 `font-backend`를 사용합니다. `FApplicationFactories.Font` / `TextLayout` 또는 네이티브 `Fonts` / `TextLayouts` 인스턴스를 전달합니다. 동시에 살아 있는 RmlUi 컨텍스트는 불변 인스턴스를 공유하고 등록 팩터리는 약한 캐시를 사용합니다. 구성 변경 전에 컨텍스트를 닫으세요. `FTextLayout::Create`는 선택한 서비스를 첫 인수로 받고 단락 캐시에 인스턴스 ID를 포함합니다. GUI `0.1.1`, Font `0.1.2`, text-layout `0.1.0`에 맞는 제공자와 소비자를 다시 빌드합니다. `ContractVersion`은 Gui의 `Version`을 참조합니다. 정적 검토는 실행 검증을 대신하지 않습니다.

## 회귀 및 수명주기 세부 사항

직접 활성화, 숫자 포커스 손실 커밋, 중첩 스크롤, Tab 순환과 플로팅 포커스를 테스트합니다.

실제 JIT 디스패치와 폴백 통계를 확인하고 예열 후 업데이트와 렌더링을 컴파일 및 표시 대기와 분리해 측정하세요.

Context.Post는 코어의 프로그램 세대별 값 루트로 콜백을 유지하고, 실행 또는 폐기 후 코어의 안전 지점에서 캡처를 해제합니다. Context.SetFocus는 동기식 컨트롤 알림에 현재 스크립트 호출기를 유지합니다.

## 소스 가져오기 정책

일반 CLI 설정은 네이티브 바인딩을 유지하고 소스에서 요구할 때 프레임워크를 불러옵니다. GUI 이름, 어노테이션과 생성 ML은 이를 요구하지만 주석과 문자열만으로는 요구하지 않습니다. .vs 소스 가져오기에도 같은 검사를 적용합니다. 작은 로컬 .vslib는 추적되는 종속성을 통해 공개 매크로를 검사하며, 일반 선언과 매개변수 없이 리터럴만 포함하는 매크로는 프레임워크를 요구하지 않습니다. 단순 숫자·문자·문자열 상수 매크로와 일반 조건 지시문만으로는 요구하지 않습니다. 매개변수가 있거나 치환 본문에 이름이 있는 소스/호스트/가져온 라이브러리의 공개 매크로, 토큰 결합, 문자열화, 알 수 없는 지시문, 호스트 매크로와 함께 쓰는 불투명한 암시적 공급자, 확인할 수 없거나 이스케이프·논리·큰 가져오기와 사용자 처리기는 전체 가져오기를 유지합니다. gui-* 작업과 ConfigureGuiScriptEngine은 암시적 가져오기를 유지합니다. 컴파일 메타데이터와 캐시 식별자를 일치시키고 GUI 없는 소스 및 가져오기·처리기를 통해 GUI를 사용하는 소스를 회귀 검증하세요.

고정 속성을 동기화할 때 콜백 전에 입력 필드 리비전을 기록하고, 성공했으며 등록이 바뀌지 않은 경우에만 확정합니다. 평가 중 변경은 다음 동기화에서도 감지되며 실패나 재등록으로 오래된 스냅샷을 확정하지 않습니다. 입력 버퍼를 재사용하고 보관한 기본 구성은 소스를 전환할 때만 비웁니다. 동적 getter는 계속 모든 동기화 라운드에서 실행됩니다.

`BakeGuiApplication`은 임베딩용 내부 Core 이미지 API로 유지됩니다. CLI는 바이트를 `.vsapp`로 직접 쓰지 않고 `Application::BuildApplication`과 `WriteArchive`로 감쌉니다. 응용 프로그램 준비 훅은 패키지 제공자를 사용할 수 있게 된 뒤 GUI 리소스 서비스를 복원합니다. 일반 CLI와 GUI 지원 Runtime은 이 경로를 공유합니다. ZIP 구조, inspect, 검사 및 소스 삭제 후 이동 실행을 함께 검증하십시오. Application이 없어도 GUI 소스 검사/미리 보기는 가능하지만 컨테이너 컴파일/로드는 누락된 기능을 보고합니다.

소스의 `import compiler` 생성기를 사용할 때 Core 확장 기한에는 GUI 소스 그래프 준비 시간도 포함됩니다. 큰 그래프에는 CLI의 `--compiler-timeout 20000` 또는 네이티브 호스트의 `FCompileOptions::ScriptCompileExtensions.TimeoutMilliseconds`로 적절한 예산을 설정하세요.

입력의 식별자와 리비전이 그대로임을 확인했다면 필드를 다시 순회하지 않고 콜백 전 스냅샷을 재사용합니다. 구성이 같을 때 소스 분류는 재사용할 수 있지만 getter 결과는 동기화 라운드 사이에 재사용하지 않습니다. 정확한 프레임워크 숫자 컨트롤은 자체 네이티브 콜백에서 getter 실행 중이 아닐 때 방금 동기화된 속성으로 네이티브 상태를 설정할 수 있습니다. 수동 동기화, 파생 컨트롤, 재귀 쿼리는 일반 getter 경로를 유지합니다. 상속 속성의 부모 getter는 매 라운드 평가하고, 변하지 않은 검증된 값의 복사와 반복 검증만 생략합니다. 네이티브 속성 디스패치는 활성 마스크 그룹을 검사하면서 getter 순서와 활성 바인딩 전체를 유지합니다.

네이티브 숫자, 불리언, 문자열 속성은 동기화와 조회에서 값 스냅샷과 참조 출력을 사용하여 임시 optional 객체를 줄입니다. 빈 결과의 폴백을 유지하며 다음 평가 세대에서 다시 조회합니다. 검증된 네이티브 범위에서 프레임워크의 정확한 숫자 컨트롤 형식은 생성된 빈 변경 훅을 생략할 수 있습니다. 파생 컨트롤과 선언된 훅의 가상 호출은 유지됩니다.

고정 네이티브 속성 설정은 주기적인 스크립트 조회가 필요하지 않습니다. 설정 변경, 네이티브 변경 및 다시 마운트할 때 동기화가 재개됩니다. 바인딩된 getter와 optional getter는 빈 결과 뒤에도 계속 조회됩니다.

각 위젯은 독립적인 네이티브 캐시 객체를 소유합니다. 내부 스냅샷 갱신은 입력 설정 추적을 안정적으로 유지하며, 설정을 교체하는 setter는 동기화를 재개합니다.

정확한 기본 Widget 형식도 동기화를 일시 중단할 수 있습니다. 주석이 없는 파생 형식은 기존의 보수적인 사용자 정의 동기화 경로를 유지합니다.

attribute 구성 분류는 Set/Reset이 해당 구성을 교체할 때까지만 캐시합니다. 분류 자체는 getter를 평가하지 않으며 바인딩 및 optional getter는 필요한 각 평가 세대마다 실행됩니다.

교체 시 새 구성과 분류가 모두 게시될 때까지 이전 페이로드를 유지합니다. 소멸자 재진입이 새 상태를 읽거나 교체해도 바깥 호출이 이를 덮어쓰지 않습니다.

## 변경 알림 바인딩과 일괄 업데이트

네이티브 알림 그래프는 약한 위젯 구독으로 반복 알림을 병합합니다. 위젯이 구독 토큰과 일반 attribute 읽기 함수를 소유하고 토큰 소멸에는 스크립트 종료 콜백이 필요하지 않습니다. Bridge의 단조 카운터로 알림에 번호를 매겨 고정 의존 집합의 최대 리비전으로 변화를 정확하게 확인합니다. 해시나 매 읽기마다 스크립트 배열을 만들지 않습니다. 공유 Binding은 optional 빈 결과를 포함한 성공한 읽기만 캐시합니다. 기존 동적 attribute의 epoch 동작은 유지됩니다.

IFrameBindingService는 모든 BeginFrame 이후 게시 단계를 추가하며 기존 `IFrameService`의 가상 인터페이스는 바꾸지 않습니다. 위젯을 중복 제거하고 기존 수명 주기 관찰자를 깨우므로 속성별 스크립트 작업과 강제 레이아웃 무효화를 피합니다. 기존 동기화가 결과 비교, 수명 주기 순서 및 실패 Getter 재시도를 처리합니다. 스크립트 소유 관찰자는 호스트 직접 업데이트도 지원합니다. 네이티브 배치 깊이와 스크립트 래퍼로 중간 상태 업데이트를 거부합니다. 일반 setter와 ClearX는 구독을 끊고 내부 설치는 이전 캡처 해제 전에 새 설정을 게시합니다. FromAttribute는 기본 attribute와 네이티브 스타일의 독립적인 변경을 위해 폴백 폴링을 유지하며 전달된 Getter 결과 자체는 알림 리비전으로 캐시합니다.

## 동기화 출력과 렌더링 제출

네이티브 동기화는 Getter, 상속, 변경 훅을 실행한 뒤 해석된 속성 출력을 재사용합니다. 값 변경과 애니메이션 샘플링, 중지, 종료는 출력을 갱신합니다. 알림은 유효한 구성 스냅샷을 유지합니다. 각 Widget은 안정적인 캐시 컨테이너를 소유하며 네이티브 속성 캐시를 처음 사용할 때 생성합니다. 이러한 출력 쓰기는 입력 구성 스냅샷을 무효화하지 않습니다. 일반 동적 attribute와 FromAttribute의 대체 값 경로는 기존 평가 및 재시도 규칙을 유지합니다.

RmlUi는 선택적 IRenderSubmission2D 범위로 동일 렌더러의 연속 패스를 모아 제출합니다. 다른 렌더러의 합성기가 결과를 읽기 전에 생산 패스를 제출하고 기록을 재개합니다. 실패나 예외에서는 미완료 범위를 취소합니다. 사용 가능한 스왑체인 이미지가 없으면 내부 임시 레이어에만 쓰는 미제출 작업을 취소할 수 있지만 영구 캡처는 완료합니다. SDL_GPU와 모듈 제공자가 이를 지원하며 다른 렌더러는 기존 경로를 유지합니다. Render마다 OnPaint를 계속 실행합니다.

스크립트 캐시 무효화 표시는 네이티브 알림을 게시하기 전에 증가하므로 게시 후 실행이 중단되어도 공유 결과를 최신으로 오인하지 않습니다. 실제 변경은 계속 의존성 리비전으로 판단합니다. 이 순서는 중단된 실행에 트랜잭션 롤백을 보장하지 않습니다.

Observable.Set은 finally에서 알림을 게시하므로 값을 저장한 뒤 실행이 중단되는 경우도 처리합니다. 실패하거나 중단된 대입은 안전을 위해 캐시를 무효화할 수 있으며 같은 값을 설정하면 여전히 알림을 보내지 않습니다. 복구에는 아래 Core RequiresReset 계약이 적용됩니다.

평가·초기화·구성의 임시 표시는 보호 범위 안에서 변경하며, 중첩 평가와 일괄 업데이트는 진입 전 깊이로 복원합니다. 구독 해제 콜백이 실패하면 재시도할 수 있고 재귀적 해제는 억제합니다. 제한 초과·시간 초과·취소 후 복구는 Core의 제한된 정리에 의존합니다. Core가 초기화를 요구하면 해당 GUI 스크립트 세션과 바인딩 컨텍스트를 다시 생성해야 합니다. GUI의 finally는 애플리케이션 상태의 트랜잭션 롤백을 보장하지 않습니다.

네이티브 속성은 원래 순서를 유지하는 아홉 그룹으로 동기화되며 동적 평가와 예외 복구를 유지합니다. 약한 참조의 컨트롤 콜백은 스크립트 진입 후 해제 상태를 다시 확인하고 대상이 해제되었으면 호스트 브리지에 재진입하지 않고 처리를 마칩니다.

ML 캡처 초기화 식은 바깥 스코프에서 다시 작성하며 캡처 별칭은 클로저 본문에서만 유효합니다. 속성 소스 스냅샷은 Core의 언래핑 API로 참조 또는 읽기 전용 캡처 저장소 안의 실제 속성 객체와 변경 번호를 비교합니다. 일반 객체 필드는 직접 읽으며 캡처 데이터를 추가로 보관하지 않습니다. 콜백은 기존 FValueRoot와 InvokeCallable을 사용하고 업무 API는 유지합니다.

네이티브 스칼라 속성 동기화는 값을 얻지 못한 경우에만 설정을 다시 확인하여 일반적인 값 경로의 중복 조회를 줄입니다. 캐시와 getter 인터페이스는 그대로 유지합니다. 순서대로 실행하는 그룹은 스칼라 상태 변수를 재사용하며 속성 값의 범위는 독립적으로 유지합니다. 공유 Binding은 재귀 상태를 먼저 확인한 후 리비전 캐시를 재사용하며, 캐시 적중 시 추가 갱신 메서드 호출을 생략합니다.

네이티브 요소 검색과 스타일 존재 여부 쿼리는 읽기 전용 멤버 메타데이터를 명시하여 Core가 const 호스트 핸들과 값 캡처를 통해 호출할 수 있게 합니다. 변경 작업의 메타데이터와 공개 GUI API는 유지합니다.

## 네이티브 아티팩트 유지 관리

네이티브 옵션, 공개 레이아웃 또는 내장 라이브러리를 변경하면 GUI 공급자, 호스트, 스크립트 라이브러리 및 SDK·패키지 후보를 함께 다시 빌드합니다. 같은 제품 버전 문자열만으로 구현 호환성이 보장되지는 않습니다.

## 백엔드 기본값과 내부 디스패치

구현 보조 형식과 스크립트 디스패치 진입점은 `VS::Gui::Internal`을 사용합니다. `NativeAttributeCache<T>`와 `NativeValueAttributeCache<T>`는 애플리케이션 API가 아닌 프레임워크 내부 구현입니다. `Vsgui`로 시작하는 멤버는 이름 충돌을 피하기 위한 생성 코드 및 상속 훅의 예약 이름으로 유지합니다.

가져오기 감지는 네임스페이스／주석 사용과 단순히 `Gui`로 이름 붙인 변수, 필드, 매개변수를 구분합니다. 감지를 바꾸면 처리기 구성 ID도 갱신하세요. 네이티브 바인딩, 생성 호출, 두 편집기 추출기를 정규화된 `VS::Gui::Internal` 이름과 맞춥니다. `FContext`는 형상 변경 시 `bLayoutNotificationPending`을 설정하고 콜백 전에 전체 형상을 게시하며 성공적으로 전달한 뒤에만 플래그를 지웁니다. 실패하거나 전달하지 못한 알림은 유지하고 성공한 알림은 새 변경 없이는 반복하지 않습니다. 마운트 훅 변경은 레이아웃 전에, 레이아웃 훅 변경은 다음 `Update`에서 동기화합니다. 입력／렌더링에는 성공한 업데이트가 필요합니다. 실패와 재시도, 형제 알림 전달, 콜백에서 보는 형상을 각각 검증하세요.

## 동기화 구현

정적 빠른 경로는 정확한 런타임 형식, 초기화 완료, 사용자 스크립트 동기화가 없음을 요구합니다. 알 수 없는 파생 형식은 보수적인 경로를 유지합니다. 고정 기본 형식 구성은 폴링을 중지할 수 있지만 구성 교체, Setter, 스타일, 호스트 변경, 바인딩 설치가 이를 재개합니다. 바인딩 및 optional Getter는 빈 결과도 계속 평가합니다. 약한 관찰이 위젯을 소유해서는 안 됩니다.

생성된 기본 형식 속성은 로컬 값, 스타일, 출력 스냅샷을 박싱 없이 보존합니다. 변경 토큰은 콜백 성공 후에만 확정하며 실패나 재등록으로 오래된 입력을 확정하면 안 됩니다. 네이티브 변경 토큰은 바뀌지 않은 상태의 재조회를 줄이지만 동적 Getter와 사용자 Codec을 생략하지 않습니다. 스타일은 분석된 내장 리터럴을 보존하고 변수 확장, 리소스 해석, 선택자 상태, 테마는 계속 갱신합니다. 공통 Builder 메서드는 형식과 함께 출력하여 구문 변경 없이 선언 작업을 줄입니다.

네이티브 동기화 중 현재 마운트된 위젯의 반복 검사는 콜백 진입 시 검증한 범위를 공유합니다. 성공과 실패 후 모두 복원하고 다른 위젯과 콜백 밖 조회는 네이티브 검사를 유지합니다. 속성 평가, optional 대체, 안정화, 수명 순서를 보존하세요.

## Context 대체 값과 Runtime 옵션 전달

`Private/Bindings/VeroScriptGuiRuntimeBindings.cpp`의 표준 `__NativeContext` 생성자 브리지는 인수를 생략하면 `FScriptServices.DefaultBackend("gui")`를 조회한 뒤 해석된 `Application.DefaultBackend("gui")`를 조회합니다. `Factories.Gui` 호출 전에 빈 결과를 다시 확인하고 그때만 `rmlui`를 사용합니다. 명시적 ID/auto/none은 유지합니다. `FScriptServices.CreateContext`는 이 분기를 우회하며 호스트가 담당합니다. `VeroScriptRuntimeMain.cpp`에서 VM/JIT는 실행 구성과 패키지 `SelectedBackends`에 유지하고 GUI 명령 어댑터에 전달하는 값에서는 `vm`과 `jit`를 제외합니다. 콜백 생략, 빈 결과, 환경 우선순위, 명시적 선택, VM/JIT 옵션을 사용하는 GUI 컨테이너 검사／실행을 각각 확인하세요.

## 장면 재사용과 동기화 경계

스타일 동기화는 변경되지 않은 장면 구조와 선택자 일치 결과를 재사용합니다. 일반적인 기하, 텍스트 및 애니메이션 출력만으로 선택자 캐시를 무효화하지 않습니다. 리소스 해석, 스타일 값 디코딩 및 동적 Getter는 기존 동기화 규칙을 유지합니다. 생성 코드에서 주기적인 작업이 필요 없다고 확인된 위젯만 폴링을 중지하며, 동적 바인딩과 알 수 없는 동기화 동작은 기존 경로를 유지합니다.

`FMarkupRuntime::MatchesScene`은 테마, 위젯, 부모, 이름 범위, 소속 및 스타일시트를 비교한 뒤 `FContext::SceneStyles`를 재사용합니다. 선택자 결과는 적격성, 포커스/모달/호버/누름 상태와 스타일 입력을 추적하며 동적 적격성 getter는 재사용을 끕니다. 적용 전 입력을 기록하여 스타일 출력이 다음 안정화 단계를 무효화하도록 합니다. 루트 교체와 폐기 시 장면 상태를 해제합니다. `CanSuspendSynchronization`은 알 수 없는 메서드/생성자, 다른 처리기의 생성 코드, codec 및 도우미 없는 이전 패키지 기반 타입에 보수적입니다. 비공개 생성 이름은 모듈의 정규 링크 식별자를 유지합니다.

## GUI 컴파일 구성

GUI `CompilerOptions`는 선택한 VM을 컴파일 확장으로 전달합니다. 명시 VM이 없고 `bClearVmBackend`가 false일 때만 `FallbackVmBackendFactory`/`FallbackVmBackendPath`를 사용하며 확장 옵션에 없을 때만 `ExecutionControl`을 상속합니다. 명시적 비활성화와 호출자별 제어가 우선합니다.

## 텍스트 레이아웃 소비자의 불변 조건

문단 캐시 식별에는 논리 텍스트와 방향뿐 아니라 선택한 서비스 인스턴스 및 불변 설정을 포함합니다. 백엔드 ID만으로는 부족합니다. 스타일 구간을 가로질러 논리 문단을 유지하고 줄바꿈을 정한 뒤 줄별 bidi 순서를 구하며 해결된 서비스를 통해 모듈 lease를 보존합니다. 원래 advance와 offset을 유지하고 각 보이는 클러스터의 마지막 글리프 뒤에만 자간을 한 번 더해 그리기 결과를 줄 너비와 캐럿 위치에 맞춥니다. 유한한 음수 자간을 허용하며 최종 너비가 음수가 되지 않도록 제한합니다. 클립보드와 offset은 논리 순서를 유지합니다. 공개 셰이핑·클러스터·기능 제한의 정본은 [Font 계약](../../../../../VeroScriptFont/Resources/Docs/User/ko-KR/index.md)입니다.
