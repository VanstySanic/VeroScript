# Multipart upload and parsing

FMultipartReader::TryCreate(content_type,out,error,options,context) parses the boundary and preserves out on failure. Context is optional natively; when supplied, bounded storage and retained immutable event data count against it even after delivery. Copies share data, delivered events survive context close, but the reader accepts no new work. Feed(bytes,final,event,work) returns consumed bytes, at most one event; resubmit suffix with the same final flag. Only EventReady changes event. final means EOF, not temporary absence; borrowed work checks cancellation/budgets only during the call.

States: 0 NeedInput, 1 EventReady, 2 Done, 3 Failed (new reader needed). Events: 0 PartBegin (zero-based PartIndex and owned Head), 1 Data (nonempty ≤16 KiB/context buffer cap), 2 PartEnd, 3 End. End does not replace draining HTTP epilogue to EOF. Head preserves ordered duplicate headers/name/optional filename/content type, including absent versus empty filename. form-data requires one unambiguous Content-Disposition/form-data/name (empty name allowed). Other subtypes may omit name; nested multipart remains raw bytes for an explicit nested reader. Header names are case-insensitive, folding becomes spaces; duplicate metadata parameters/ambiguous disposition/type fail. NUL/encoding/order are preserved without charset/percent/transfer decoding. Filename never creates or reads files; preamble/epilogue/empty/cross-chunk boundaries/padding are parsed.

Defaults: 256 parts, 64 KiB part headers, 1 MiB total headers, 64 MiB part body, 256 MiB total body, 272 MiB total input including framing, 64 KiB each preamble/epilogue. Limits are independent; bodies are emitted incrementally, retained events remain charged and can cause Limit. Script multipart_options exposes max_parts/max_header_bytes/max_total_header_bytes/max_part_body_bytes/max_total_body_bytes/max_input_bytes/max_preamble_bytes/max_epilogue_bytes. Reader feed/state/event/error_code/error; event kind/part_index/name/has_filename/filename/content_type/header_count/header/data reject wrong-kind payload access. Drain EventReady/suffix before new input and final parser state after HTTP End. VM cancellation fails the native call; ordinary format failure stays in reader state.

Upload parts use owned Body, one-shot Upload or native UploadFactory, mutually exclusive per nonempty source. Known UploadLength bounds what is sent; short input is Protocol, excess is not transmitted and source ends. Unknown length needs Finish; WouldBlock is not EOF. Mixed/repeated/binary parts preserve order. Retries/redirects require a fresh factory per stream, on the I/O executor without script/blocking work, with consistent rewind length. Sources are single-consumer and unused sources cancel on all terminal outcomes. MaxUploadBytes/MaxTotalUploadBytes count source payload per attempt/all replays, excluding MIME framing; buffered input prepays, streams charge on acceptance. Context counts metadata/buffered parts; streams use bounded pipes. Backend owns Content-Type/Length/Transfer-Encoding. Script begin_multipart, add_field/add_file/add_field_stream/add_file_stream use length=-1 unknown; ≤256 parts and ≤16 MiB metadata/buffered data. One-shot script streams cannot provide I/O-thread replay callbacks. File path adapters are available through the file-transfer API; filename metadata itself never accesses disk.
