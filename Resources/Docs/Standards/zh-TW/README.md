# VeroScript 專案開發與貢獻規範

本規範公開可讀，**僅適用於 VeroScript 本專案的開發與貢獻**。它不是語言規格、SDK 使用要求或 MIT 授權條款的附加條件。使用、整合或在其他專案中修改 VeroScript，不要求採用本專案的程式碼風格，也不要求將本專案權利人寫成自己程式碼的著作權人。既有著作權與授權聲明仍依 [MIT 授權條款](../../../../LICENSE)及適用的第三方授權條款保留。

Standards 保留在原始碼儲存庫，並作為開發者資料隨 `All` 完整文件出版。`User` 使用者文件、Resources 中的使用者文件，以及 Runtime、SDK、擴充套件發行包和安裝程式均不附帶 Standards。

本組文件儲存本專案的**人工維護程式碼與發行規範**。程式碼規則適用於倉庫自有、手工維護的原始碼，包括 VeroScript 核心、工具、各語言擴充及其他原生和應用模組；[PACKAGING.md](PACKAGING.md) 適用於官方發行集合及其驗收。

規範的唯一維護源為 `Resources/Docs/Standards/`。`zh-CN` 是規則制定正本，其他語言是等價譯本；翻譯不新增或改變規則。
規範以專案維護者明確給出的決定為準，而不是從既有程式碼、第三方習慣或工具預設行為中反推。
舊規範由版本控制保留供比較；新增或實質修改的程式碼僅採用目前已確認的規範。

當前規範處於持續建設階段：已經確認的規則應直接遵守；尚未寫明的部分不應擅自擴充為
硬性要求。新增規則時，應補充到最貼近其適用語言或主題的檔案中。

## 規範用語

- **必須**：新增程式碼和被實質修改的程式碼必須滿足。
- **推薦**：預設採用；因語言限制、相容性或可讀性偏離時，應保持區域一致並說明原因。
- **按需**：僅在能改善結構辨識、維護性或呼叫者理解時使用；不能形成機械、重複的樣板。
- **暫定**：當前的推薦預設值，維護者可以隨時補充或替換。

## 適用與遷移

- 程式碼規則適用於倉庫自有、手工維護的原始碼和程式碼註解；打包與發行遵循 [PACKAGING.md](PACKAGING.md)。
- `ThirdParty/`、生成目錄、自動生成檔案，以及用於測試解析器的原始輸入夾具不強制遷移。
- 新檔案應完整遵守對應規範；修改舊檔案時，優先讓新增和相關程式碼遵守，不在功能變更中
  順帶大範圍重排無關程式碼。
- 有效的語言、ABI、協議或構建契約高於格式規則。遇到衝突時，保留契約並在相應規範中
  記錄例外。

## 維護方式

規範變更應是小而明確的文件變更：寫明規則、適用範圍、必要的例子和例外。不要把單一
歷史檔案的偶然寫法自動升級為全域性規範。

- 先修改 `zh-CN` 正本，在同一變更中同步其他五種語言；規則等級、適用範圍、例外和“暫定”狀態必須保持一致。
- 在本目錄相應語言中維護正文；規範變更時審查示例，不從既有程式碼反推新規則。
- 規範維護在 `Resources/Docs/Standards/<locale>`：`zh-CN` 定義規則，其他五語言保持等價。修改後執行 `python Resources/Tools/Packaging/veroscript_docs.py check` 和 `check-collection`。規範正本僅作為開發者資料進入 `All`，不進入 `User` 或功能發行包。
- 程式碼、API、協議欄位、命令和兩行 SPDX 宣告不翻譯；程式碼示例中的註解仍使用英語。
