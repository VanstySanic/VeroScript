# 通用程式碼規範

適用範圍：[VeroScript 本專案開發與貢獻](README.md)。

本檔案只記錄所有語言共用的規則。語言專屬的縮排、花括號、型別佈局和語法細節以各自
規範為準。

## 結構與層級

- 程式碼按職責分塊；一個分塊只表達一個容易命名的概念，例如繼承介面、內部型別、公開方法、
  私有輔助方法或成員資料。
- 分塊之間空一行。不要用連續空行、長分隔線或無意義的區域標題代替清晰結構。
- 巢狀作用域、命名空間、型別、方法、條件和迴圈必須體現真實層級；不得為了壓縮行數而
  損失層次。
- 如果某項規則未定義，優先選擇最接近程式碼的既有一致寫法，而不是在一個變更中引入新風格。

## 縮排

- 自有、手工維護的原始碼、測試、示例及建置/工具指令碼統一每個邏輯層級使用一個真實 Tab，預設顯示寬度為四欄；不使用純空格代替層級縮排。
- Tab 表達邏輯層級；續行需要欄位對齊時，可在語言語法允許的位置使用對齊空格，不將兩者混作程式碼區塊的層級縮排。
- 語言或檔案格式的語法要求優先。[YAML 的層級縮排必須使用空格](https://yaml.org/spec/1.2.2/#61-indentation-spaces)，屬於本規則的明確例外；Python 的解析規則見 [PYTHON.md](PYTHON.md)。
- 保留 Markdown 的文件結構，程式碼區塊內部按對應語言規範縮排。字串、測試輸入、第三方原文和生成結果不作機械轉換；生成原始碼的格式透過所屬範本按需調整。

## 檔案換行符

- 本儲存庫自有文字檔案統一使用 LF（`\n`），包括原始碼、測試程式碼、範例、文件、設定和建置/工具指令碼；Windows、Linux 和 macOS 簽出及編輯時採用相同規則。Tab 縮排規則不變。
- `.editorconfig` 與 `.gitattributes` 必須保持一致；維護本儲存庫檔案的生成工具應明確使用 LF。僅轉換實際行結束符，保留編碼和 BOM；特別保留 Windows PowerShell 5.1 所需的 UTF-8 BOM。不改寫字串中的 `\r\n` 跳脫、協定分隔符、使用者輸入或字面值資料，也不縮減語言和工具對 CRLF 輸入的支援。
- 第三方原文、外部匯入的授權/建置工具檔案、二進位資源和對位元組敏感的測試輸入不參與機械轉換，保留其內容及自身或既有的 Git 換行政策；專案自行撰寫的授權導覽與說明仍使用 LF。不因目錄名含 Tests 就跳過一般測試程式碼。
- Windows `.bat`、`.cmd` 啟動指令碼使用 CRLF。其他依賴實際換行值的多行字面值或測試輸入須按具體路徑保留既有位元組，並在 Git 與編輯器設定中宣告有依據的例外；確認不再依賴原換行後再移除例外。不得為滿足 LF 規則而改變測試輸入、輸出內容或執行行為。

## 命名

- 名稱必須說明物件的職責、狀態或值，不使用 `New`、`Old`、`Temp`、`Final`、`v2` 等階段性名稱。
- 同一概念在同一模組中只能有一種穩定命名；跨語言邊界的協議名稱保持原契約拼寫。
- 布林名稱應表達肯定語義，讓條件可直接閱讀。
- 新縮寫必須在區域上下文中易懂；已有公共縮寫的大小寫和拼寫保持一致。

## 註解

- 所有自有、手工維護原始碼中的註解必須使用英語，包括單行註解、塊註解、文件註解和區域註解。
  外部協議原文、第三方許可證或自動生成內容不按此規則翻譯。
- 註解解釋**為什麼**、不變數、邊界、所有權、執行緒要求、相容性或非直觀選擇；不逐句翻譯
  顯而易見的程式碼。
- 型別、成員方法和成員變數按需提供必要註解。公共表面、複雜狀態、資源所有權和容易誤用的
  介面優先說明；名稱已經充分表達的簡單成員不寫重複註解。
- 單行說明使用該語言慣用的單行註解語法（例如 C 系語言的 `//`、Python 的 `#`）。連續的
  說明性文字、參數/返回語義或格式化文件使用語言慣用的文件註解。
- 多行塊註解只用於確實需要整體閱讀的說明、許可證或嵌入文字；不要用它包裹普通程式碼。
- 註解與所描述程式碼保持相鄰；程式碼變更時同步修改或刪除過期註解。

- 自有、手工維護且採用 MIT 許可證的原始碼、測試、示例及建置/工具指令碼統一使用下列兩行 SPDX 宣告。新檔案必須新增；舊的自有宣告在統一遷移或相關修改時替換為新格式。
- 使用範本前，將 `<copyright-holder>` 替換為根目錄 `LICENSE` 中權利人的準確寫法；檔案頭不寫年份和網址。兩行順序固定，欄位名稱、版權人和許可證識別碼不翻譯。
- C 系語言、C#、VeroScript、TypeScript/JavaScript、Java 和 Kotlin 使用 `//`：

```cpp

// SPDX-License-Identifier: MIT
```

- Python、CMake、PowerShell 和 Shell 指令碼使用 `#`：


- 宣告位於首個普通原始碼行之前，宣告後空一行。shebang、編碼宣告、PowerShell `#requires`、XML 宣告等有位置要求的指令保留在前，隨後放置這兩行宣告。
- 生成原始碼和型別宣告按需透過所屬生成範本輸出宣告；不手改生成結果來滿足檔案頭格式。

## 換行與可讀性

- 換行應服務於語義層級、參數分組和閱讀方向，而不是機械湊行寬。
- 參數、範本參數、初始化器或條件過長時，按邏輯單元換行，並讓續行明顯屬於同一表示式。
- 不要求在每個左花括號後或右花括號前插入空行；是否留空行取決於第一個/最後一個邏輯分塊。
- 一行只承載一個主要意圖。簡單衛語句、空函式或語言慣用的簡寫是否可作為例外，以對應語言
  規範的明確規定為準；未規定時不使用簡寫。
- 在語言支援對應語法時，`else`、`else if`（PowerShell 為 `elseif`）、`catch`、`finally` 和 `do…while` 尾部的 `while` 必須另起一行，與前一區塊的右花括號對齊，不得寫成 `} else` 等同行形式。
  子句若有區塊本體，其左花括號也必須另起一行並與子句對齊，區塊內語句和右花括號分別獨立成行。
  不要為機械滿足排版而改寫字串、測試輸入或第三方原文；巨集中的換行必須保留續行語義。

- 格式化器、輸出原始碼的程式碼生成範本和現行文件範例也必須遵循上述子句布局；測試輸入保留其原有覆蓋目的。

```cpp
if (bPrimary)
{
	HandlePrimary();
}
else
{
	HandleFallback();
}
```

## 修改原則

- 只改變當前任務需要的內容；不刪除、覆蓋或重排無關的使用者修改。
- 行為、公共介面、序列化格式或跨語言邊界變化時，必須同步維護宣告、實作、呼叫方和測試。
- 需要拒絕、恢復或降級的情況必須對呼叫者可觀察；不能把失敗偽裝成成功。
- 外部輸入、檔案路徑、程序參數和資源生命週期應在其所屬邊界完成校驗和清理。


## 編輯器與嵌入平台

Core 管理語言語意、執行服務及通用 VM／JIT 契約。位元組碼解譯迴圈歸 `Modules/Execution/VeroScriptBytecodeVm`；具體 JIT 編譯、IR、原生生成和第三方後端相依歸 `Modules/Execution`。後端使用公開契約，在實體、工作執行緒和保留程式碼存續期間維持模組所有權。動態選擇先驗證 ABI 再呼叫工廠；失敗保留先前後端，執行期間不得更換後端或變更其組態。

編輯器客戶端管理設定與協定展示。Mobile/Android/iOS 適配使用公開 C ABI，明確提供資源並記錄實際平台驗收。遵守建立執行緒所有權、回呼壽命及取消/reset 契約；配額不能描述為完整沙箱。Kotlin/Java 的命名和結構遵循模組慣例，縮排遵循本檔案的統一規則；Objective-C/Objective-C++ 遵循平台所有權與原生邊界規則。協定識別子保持穩定。

User 面向操作、可觀察行為和公開 API；Developer 面向原始碼架構、建置、測試門檻與出版；歷史版本及環境驗收記錄保留在版本控制或被忽略的證據中，不屬於出版文件。介面變更同步六語言現行文件，介面驗證與診斷透過所屬目錄翻譯，保留 ID、選項鍵與預留位置。檢查原始碼連結與 All/User 出版；略過的平台或 IDE 測試不能支撐發行認證。
