# Python 程式碼規範（暫定）

適用範圍：[VeroScript 本專案開發與貢獻](README.md)。

Python 遵循 [GENERAL.md](GENERAL.md) 的結構、註解和最小必要說明原則。Python 沒有花括號和
訪問修飾符，因此以模組與類的宣告順序表達對應層級。

## 格式

- 每個邏輯層級使用一個真實 Tab，預設顯示寬度為四欄；遵循 [GENERAL.md](GENERAL.md) 的縮排規則。
- [Python 解析器按八欄邊界展開 Tab](https://docs.python.org/3/reference/lexical_analysis.html#indentation)，不受編輯器顯示寬度影響。程式碼區塊的層級縮排統一使用 Tab；遷移時保持原有區塊邊界，不能按畫面欄寬機械替換。
- 每個 `class`、`def`、條件、迴圈、`try` 和上下文管理器的執行體必須正確縮排；不使用單行
  複合語句壓縮邏輯。
- `if`、`for`、`while`、`try` 等分支的執行體必須使用獨立的縮排塊；Python 不使用 C++ 的
  單行 `return` 衛語句例外。
- 使用 `match` 表達 `switch` 式分支時，必須包含 `case _` 作為預設分支；該分支應明確處理
  未知或不支援的輸入。
- 條件匯入或版本分支保持在其所控制程式碼的同一邏輯區域，不拆散一個完整語義分塊。

## 模組與型別佈局

模組推薦按以下順序：

1. 模組文件字串和 `__future__` 匯入；
2. 標準庫、第三方、本專案匯入；
3. 常量、型別別名和協議；
4. `Enum`；
5. `dataclass` 或其他資料型別；
6. 其他輔助型別；
7. 類；
8. 模組函式和命令列入口。

類推薦按以下順序：

1. 類常量和類級型別；
2. 繼承/協議要求的方法；
3. 內部 `Enum`、資料型別、其他型別、類；
4. `__init__`、替代構造器、公開方法和屬性；
5. 受保護和私有輔助方法；
6. 類變數；例項狀態在 `__init__` 中集中建立，不在方法之間零散新增。

- 多個基類/協議的實作按繼承列表順序分組；需要時使用配對 `#~ Begin <Name> Interface` /
  `#~ End <Name> Interface` 風格註解，或 Python 更慣用的短註解。
- 命名採用 Python 慣例：模組/函式/變數 `snake_case`，類 `PascalCase`，常量 `UPPER_SNAKE_CASE`，
  內部實作以前導下劃線標識。

## 註解

- 模組、公共類和公共函式的非直觀契約使用 docstring。
- 區域原因說明使用 `#`，不對名稱已說明的變數、函式重複註解。
- 型別註解用於表達公共輸入、輸出和複雜資料結構；後續可單獨補充嚴格程度。
