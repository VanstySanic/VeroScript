# C# 程式碼規範（暫定）

適用範圍：[VeroScript 本專案開發與貢獻](README.md)。

C# 遵循 [GENERAL.md](GENERAL.md) 的通用原則，並參照 [CPP.md](CPP.md) 的“先關係、後型別、
再方法、最後資料”結構思想；C# 語法無法對應的部分以本檔案為準。

## 格式

- `else`、`else if`、`catch`、`finally` 和 `do…while` 尾部的 `while` 依 [GENERAL.md](GENERAL.md)
  的換行規則另起一行；區塊本體的左花括號也另起一行，與子句對齊。
- 每個邏輯層級使用一個真實 Tab，預設顯示寬度為四欄；遵循 [GENERAL.md](GENERAL.md) 的縮排規則。
- 使用塊體的型別、方法、屬性、控制分支和 `switch` 使用與 C++ 相同的 Allman 花括號佈局。
- 僅含一個直接、可讀表示式的成員、屬性訪問器和區域對映可以使用表示式體 `=>`；表示式體不能
  隱藏多步邏輯、資源管理、日誌或複雜控制流。包含多步邏輯時改用 Allman 塊體。
- 所有有執行體的 `if`、`else`、迴圈、`using`、`lock`、`try`、`catch` 和 `finally` 使用花括號。
- 唯一例外是分支體僅有一條直接 `return` 或 `return <表示式>` 的單行衛語句；該例外不得與
  `else` 鏈、日誌、清理或其他語句組合。`break`、`continue`、`throw` 和其他分支一律使用花括號。
- 每個 `switch` 語句必須有 `default`。`switch` 表示式必須完整處理其輸入：前序模式不能被編譯器
  證明窮盡時，必須使用 `_` 兜底臂；若前序模式已經窮盡（繼續新增 `_` 會成為不可達模式），不得
  為形式強行新增。未知值的處理必須明確，不能依賴不清晰的執行時失敗。
- 每個 `case` 和 `default` 標籤的執行內容使用獨立花括號作用域；不依賴隱式貫穿。確有意共享
  處理邏輯時，使用緊鄰的說明註解表達該意圖。唯一例外是該標籤唯一執行路徑為直接結束當前方法的
  `return` 或 `return <表示式>`；其中不得混入日誌、清理、區域宣告、條件或其他語句。
- `#if` 等預處理指令與其包裹程式碼保持同一邏輯層級，不額外增加縮排層級。

## 型別佈局

型別推薦按以下順序組織：

1. 特性始終緊鄰其目標；基類和介面列表緊鄰型別宣告；
2. 具有訪問修飾符的成員按 `public` → `protected internal` → `protected` → `internal` →
   `private protected` → `private` 的總體順序排列；同一可訪問級別儘量只保留一個連續區域；
3. 每個區域中，先放 `override` 和介面實作；顯式介面實作不能寫訪問修飾符，按其介面繼承順序
   放在對應實作分塊的開頭；
4. 再放巢狀型別，順序為 `enum` → `struct`/`record struct` → 其他型別 → `class`/`record`；
5. 然後放本型別成員：建構函式、方法、屬性、事件；
6. 最後放欄位。欄位不得夾在方法、屬性或巢狀型別之間。

- 顯式介面實作按介面分組；有多個成員或不易辨認時使用配對的 `//~ Begin <Name> Interface` 和
  `//~ End <Name> Interface` 註解。
- 介面、基類和本型別的實作塊不交錯排列。
- 成員宣告與較長實作檔案中的實作順序應保持可追蹤；區域輔助型別或私有靜態輔助方法可以
  放在最適合閱讀的位置。
- `file` 僅適用於檔案區域頂層型別，不是成員訪問區域；它不參與上述成員排序。泛型類和泛型
  結構分別按 `class`、`struct` 類別排列，而不是籠統歸入“其他型別”。

## 註解與命名

- 型別、方法、屬性和欄位只在呼叫者需要了解語義、所有權、執行緒、異常或協議約束時註解。
- 公共 API 使用 XML 文件註解說明非直觀契約；內部短說明使用 `//`。
- 保持現有 .NET 命名：型別/成員 PascalCase，參數和區域變數 camelCase，私有欄位 `_camelCase`。
- 原生 ABI、JSON 和協議欄位保留其外部契約名稱，不為內部命名一致性而破壞相容性。
