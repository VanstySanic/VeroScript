# VeroScript 程式碼規範（暫定）

適用範圍：[VeroScript 本專案開發與貢獻](README.md)。

VeroScript 的型別佈局和邏輯分塊參照 [CPP.md](CPP.md)。本檔案只定義當前可以直接確定的
VeroScript 寫法；語言或 formatter 的專屬細節可後續補充。

## 格式

- `else`、`else if`、`catch`、`finally` 和 `do…while` 尾部的 `while` 依 [GENERAL.md](GENERAL.md)
  的換行規則另起一行；區塊本體的左花括號也另起一行，與子句對齊。
- 每個邏輯層級使用一個真實 Tab，預設顯示寬度為四欄；遵循 [GENERAL.md](GENERAL.md) 的縮排規則。
- 命名空間、型別、方法、條件、迴圈和區域作用域每進入一層增加一級縮排。
- 左花括號獨佔一行，右花括號與對應宣告或控制語句對齊。
- 具有執行體的條件和迴圈使用花括號。唯一例外是分支體僅有一條直接 `return` 的單行衛語句；它不得與 `else` 鏈、日誌、清理或其他語句組合。
- 所有 `switch` 必須有 `default`。每個 `case`、`default` 的一般執行內容放在獨立花括號作用域內；分支只有一條直接結束當前方法的 `return` 且不包含其他語句時，可以省略該區塊。
- 明確貫穿的 `fallthrough;` 必須是標籤下最後一條直接語句，放在該分支花括號之後，不得嵌入區塊、條件或迴圈。此處遵循語言約束；其他執行內容仍放在獨立作用域內。
- 型別宣告 `class`、`struct`、`interface` 和 `enum` 以結尾分號結束。

## 型別佈局

型別內按以下順序安排：

1. 型別關係和別名；
2. `public`、`protected`、`private` 區域，按此順序；
3. 每個區域中的繼承方法；
4. 內部型別，順序為 `enum` → `struct` → 其他型別 → `class`；
5. 本型別方法；
6. 成員變數。

- 繼承/介面方法按基類或介面繼承順序組織；需要時使用配對 `//~ Begin <Name> Interface` /
  `//~ End <Name> Interface` 說明分塊。
- 同檔案多個頂層型別在無完整型別依賴衝突時也按 `enum` → `struct` → 其他 → `class` 排列。
- 本規範當前不規定 VeroScript 的前向宣告：尚未確認其原生語言語法支援該能力。不得僅因 C++
  規範存在此規則而在 VeroScript 中引入前向宣告；確認語法後再單獨補充。

## 命名與註解

- 型別和介面使用 PascalCase；函式、欄位、參數和區域變數使用 lowerCamelCase。
- 註解遵循 [GENERAL.md](GENERAL.md)：說明語言特性、約束、所有權或示例目的，不重複程式碼表面含義。
- 公開標準庫和宿主繫結名稱屬於相容性表面，改名需單獨評估。

## 長度與索引

集合長度、線性索引、切片起點與數量、容量使用 `int64`。Map 鍵和工作 ID 維持其宣告型別，數量改為 64 位元不應連帶擴大無關 API 的型別。轉換為原生 `size_t` 或較窄的後端索引前，先檢查正負號及範圍。需要 `int` 時使用有範圍檢查的縮限轉換，並保留配置限制及已公開的無結果哨兵值。修改這些契約時，同步更新標準庫宣告、文件和回歸測試。
