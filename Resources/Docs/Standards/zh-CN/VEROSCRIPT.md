# VeroScript 代码规范（暂定）

适用范围：[VeroScript 本项目开发与贡献](README.md)。

VeroScript 的类型布局和逻辑分块参照 [CPP.md](CPP.md)。本文件只定义当前可以直接确定的
VeroScript 写法；语言或 formatter 的专属细节可后续补充。

## 格式

- `else`、`else if`、`catch`、`finally` 和 `do…while` 的尾部 `while` 按 [GENERAL.md](GENERAL.md)
  的换行规则另起一行；块体左花括号也另起一行，与子句对齐。
- 每个逻辑层级使用一个真实 Tab，默认显示宽度为四列；遵循 [GENERAL.md](GENERAL.md) 的缩进规则。
- 命名空间、类型、方法、条件、循环和局部作用域每进入一层增加一级缩进。
- 左花括号独占一行，右花括号与对应声明或控制语句对齐。
- 具有执行体的条件和循环使用花括号。唯一例外是分支体仅有一条直接 `return` 的单行卫语句；它不得与 `else` 链、日志、清理或其他语句组合。
- 所有 `switch` 必须有 `default`。每个 `case`、`default` 的普通执行内容放在独立花括号作用域内；分支只有一条直接结束当前方法的 `return` 且不包含其他语句时，可以省略该块。
- 显式贯穿的 `fallthrough;` 必须是标签下最后一条直接语句，放在该分支花括号之后，不得嵌入块、条件或循环。此处遵循语言约束；其他执行内容仍放在独立作用域内。
- 类型声明 `class`、`struct`、`interface` 和 `enum` 以结尾分号结束。

## 类型布局

类型内按以下顺序安排：

1. 类型关系和别名；
2. `public`、`protected`、`private` 区域，按此顺序；
3. 每个区域中的继承方法；
4. 内部类型，顺序为 `enum` → `struct` → 其他类型 → `class`；
5. 本类型方法；
6. 成员变量。

- 继承/接口方法按基类或接口继承顺序组织；需要时使用配对 `//~ Begin <Name> Interface` /
  `//~ End <Name> Interface` 说明分块。
- 同文件多个顶层类型在无完整类型依赖冲突时也按 `enum` → `struct` → 其他 → `class` 排列。
- 本规范当前不规定 VeroScript 的前向声明：尚未确认其原生语言语法支持该能力。不得仅因 C++
  规范存在此规则而在 VeroScript 中引入前向声明；确认语法后再单独补充。

## 命名与注释

- 类型和接口使用 PascalCase；函数、字段、参数和局部变量使用 lowerCamelCase。
- 注释遵循 [GENERAL.md](GENERAL.md)：说明语言特性、约束、所有权或示例目的，不重复代码表面含义。
- 公开标准库和宿主绑定名称属于兼容性表面，改名需单独评估。

## 长度与索引

集合长度、线性索引、切片起点与数量、容量使用 `int64`。Map 键和任务 ID 保持其声明类型，数量改为 64 位不应连带扩大无关 API 的类型。转换为原生 `size_t` 或较窄的后端索引前，先检查符号及范围。需要 `int` 时使用有范围检查的收窄转换，并保留分配限制及已公开的无结果哨兵值。修改这些契约时，同步更新标准库声明、文档和回归测试。
