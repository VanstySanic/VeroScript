# VeroScript 项目开发与贡献规范

本规范公开可读，**仅适用于 VeroScript 本项目的开发与贡献**。它不是语言规范、SDK 使用要求或 MIT 许可证的附加条件。使用、集成或在其他项目中修改 VeroScript，不要求采用本项目的编码风格，也不要求将本项目权利人写成自己代码的版权人。已有版权与许可声明仍按 [MIT 许可证](../../../../LICENSE)及适用的第三方许可保留。

Standards 保留在源码仓库，并作为开发者资料随 `All` 完整文档出版。`User` 用户文档、Resources 中的用户文档，以及 Runtime、SDK、扩展发行包和安装器均不附带 Standards。

本组文档保存本项目的**人工维护代码与发行规范**。代码规则适用于仓库自有、手工维护的源代码，包括 VeroScript 核心、工具、各语言扩展及其他原生和应用模块；[PACKAGING.md](PACKAGING.md) 适用于官方发行集合及其验收。

规范的唯一维护源为 `Resources/Docs/Standards/`。`zh-CN` 是规则制定正本，其他语言是等价译本；翻译不新增或改变规则。
规范以项目维护者明确给出的决定为准，而不是从既有代码、第三方习惯或工具默认行为中反推。
旧规范由版本控制保留供比较；新增或实质修改的代码仅采用当前已确认的规范。

当前规范处于持续建设阶段：已经确认的规则应直接遵守；尚未写明的部分不应擅自扩展为
硬性要求。新增规则时，应补充到最贴近其适用语言或主题的文件中。

## 规范用语

- **必须**：新增代码和被实质修改的代码必须满足。
- **推荐**：默认采用；因语言限制、兼容性或可读性偏离时，应保持局部一致并说明原因。
- **按需**：仅在能改善结构辨识、维护性或调用者理解时使用；不能形成机械、重复的样板。
- **暂定**：当前的推荐默认值，维护者可以随时补充或替换。

## 适用与迁移

- 代码规则适用于仓库自有、手工维护的源代码和代码注释；打包与发行遵循 [PACKAGING.md](PACKAGING.md)。
- `ThirdParty/`、生成目录、自动生成文件，以及用于测试解析器的原始输入夹具不强制迁移。
- 新文件应完整遵守对应规范；修改旧文件时，优先让新增和相关代码遵守，不在功能变更中
  顺带大范围重排无关代码。
- 有效的语言、ABI、协议或构建契约高于格式规则。遇到冲突时，保留契约并在相应规范中
  记录例外。

## 维护方式

规范变更应是小而明确的文档变更：写明规则、适用范围、必要的例子和例外。不要把单一
历史文件的偶然写法自动升级为全局规范。

- 先修改 `zh-CN` 正本，在同一变更中同步其他五种语言；规则等级、适用范围、例外和“暂定”状态必须保持一致。
- 在本目录相应语言中维护正文；规范变更时审查示例，不从既有代码反推新规则。
- 规范维护在 `Resources/Docs/Standards/<locale>`：`zh-CN` 定义规则，其他五语言保持等价。修改后运行 `python Resources/Tools/Packaging/veroscript_docs.py check` 和 `check-collection`。规范正本仅作为开发者资料进入 `All`，不进入 `User` 或功能发行包。
- 代码、API、协议字段、命令和两行 SPDX 声明不翻译；代码示例中的注释仍使用英语。
