# Python 代码规范（暂定）

适用范围：[VeroScript 本项目开发与贡献](README.md)。

Python 遵循 [GENERAL.md](GENERAL.md) 的结构、注释和最小必要说明原则。Python 没有花括号和
访问修饰符，因此以模块与类的声明顺序表达对应层级。

## 格式

- 每个逻辑层级使用一个真实 Tab，默认显示宽度为四列；遵循 [GENERAL.md](GENERAL.md) 的缩进规则。
- [Python 解析器按八列边界展开 Tab](https://docs.python.org/3/reference/lexical_analysis.html#indentation)，不受编辑器显示宽度影响。代码块的层级缩进统一使用 Tab；迁移时保持原有代码块边界，不能按屏幕列宽机械替换。
- 每个 `class`、`def`、条件、循环、`try` 和上下文管理器的执行体必须正确缩进；不使用单行
  复合语句压缩逻辑。
- `if`、`for`、`while`、`try` 等分支的执行体必须使用独立的缩进块；Python 不使用 C++ 的
  单行 `return` 卫语句例外。
- 使用 `match` 表达 `switch` 式分支时，必须包含 `case _` 作为默认分支；该分支应明确处理
  未知或不支持的输入。
- 条件导入或版本分支保持在其所控制代码的同一逻辑区域，不拆散一个完整语义分块。

## 模块与类型布局

模块推荐按以下顺序：

1. 模块文档字符串和 `__future__` 导入；
2. 标准库、第三方、本项目导入；
3. 常量、类型别名和协议；
4. `Enum`；
5. `dataclass` 或其他数据类型；
6. 其他辅助类型；
7. 类；
8. 模块函数和命令行入口。

类推荐按以下顺序：

1. 类常量和类级类型；
2. 继承/协议要求的方法；
3. 内部 `Enum`、数据类型、其他类型、类；
4. `__init__`、替代构造器、公开方法和属性；
5. 受保护和私有辅助方法；
6. 类变量；实例状态在 `__init__` 中集中建立，不在方法之间零散新增。

- 多个基类/协议的实现按继承列表顺序分组；需要时使用配对 `#~ Begin <Name> Interface` /
  `#~ End <Name> Interface` 风格注释，或 Python 更惯用的短注释。
- 命名采用 Python 惯例：模块/函数/变量 `snake_case`，类 `PascalCase`，常量 `UPPER_SNAKE_CASE`，
  内部实现以前导下划线标识。

## 注释

- 模块、公共类和公共函数的非直观契约使用 docstring。
- 局部原因说明使用 `#`，不对名称已说明的变量、函数重复注释。
- 类型注解用于表达公共输入、输出和复杂数据结构；后续可单独补充严格程度。
