# C# 代码规范（暂定）

适用范围：[VeroScript 本项目开发与贡献](README.md)。

C# 遵循 [GENERAL.md](GENERAL.md) 的通用原则，并参照 [CPP.md](CPP.md) 的“先关系、后类型、
再方法、最后数据”结构思想；C# 语法无法对应的部分以本文件为准。

## 格式

- `else`、`else if`、`catch`、`finally` 和 `do…while` 的尾部 `while` 按 [GENERAL.md](GENERAL.md)
  的换行规则另起一行；块体左花括号也另起一行，与子句对齐。
- 每个逻辑层级使用一个真实 Tab，默认显示宽度为四列；遵循 [GENERAL.md](GENERAL.md) 的缩进规则。
- 使用块体的类型、方法、属性、控制分支和 `switch` 使用与 C++ 相同的 Allman 花括号布局。
- 仅含一个直接、可读表达式的成员、属性访问器和局部映射可以使用表达式体 `=>`；表达式体不能
  隐藏多步逻辑、资源管理、日志或复杂控制流。包含多步逻辑时改用 Allman 块体。
- 所有有执行体的 `if`、`else`、循环、`using`、`lock`、`try`、`catch` 和 `finally` 使用花括号。
- 唯一例外是分支体仅有一条直接 `return` 或 `return <表达式>` 的单行卫语句；该例外不得与
  `else` 链、日志、清理或其他语句组合。`break`、`continue`、`throw` 和其他分支一律使用花括号。
- 每个 `switch` 语句必须有 `default`。`switch` 表达式必须完整处理其输入：前序模式不能被编译器
  证明穷尽时，必须使用 `_` 兜底臂；若前序模式已经穷尽（继续添加 `_` 会成为不可达模式），不得
  为形式强行添加。未知值的处理必须明确，不能依赖不清晰的运行时失败。
- 每个 `case` 和 `default` 标签的执行内容使用独立花括号作用域；不依赖隐式贯穿。确有意共享
  处理逻辑时，使用紧邻的说明注释表达该意图。唯一例外是该标签唯一执行路径为直接结束当前方法的
  `return` 或 `return <表达式>`；其中不得混入日志、清理、局部声明、条件或其他语句。
- `#if` 等预处理指令与其包裹代码保持同一逻辑层级，不额外增加缩进层级。

## 类型布局

类型推荐按以下顺序组织：

1. 特性始终紧邻其目标；基类和接口列表紧邻类型声明；
2. 具有访问修饰符的成员按 `public` → `protected internal` → `protected` → `internal` →
   `private protected` → `private` 的总体顺序排列；同一可访问级别尽量只保留一个连续区域；
3. 每个区域中，先放 `override` 和接口实现；显式接口实现不能写访问修饰符，按其接口继承顺序
   放在对应实现分块的开头；
4. 再放嵌套类型，顺序为 `enum` → `struct`/`record struct` → 其他类型 → `class`/`record`；
5. 然后放本类型成员：构造函数、方法、属性、事件；
6. 最后放字段。字段不得夹在方法、属性或嵌套类型之间。

- 显式接口实现按接口分组；有多个成员或不易辨认时使用配对的 `//~ Begin <Name> Interface` 和
  `//~ End <Name> Interface` 注释。
- 接口、基类和本类型的实现块不交错排列。
- 成员声明与较长实现文件中的实现顺序应保持可追踪；局部辅助类型或私有静态辅助方法可以
  放在最适合阅读的位置。
- `file` 仅适用于文件局部顶层类型，不是成员访问区域；它不参与上述成员排序。泛型类和泛型
  结构分别按 `class`、`struct` 类别排列，而不是笼统归入“其他类型”。

## 注释与命名

- 类型、方法、属性和字段只在调用者需要了解语义、所有权、线程、异常或协议约束时注释。
- 公共 API 使用 XML 文档注释说明非直观契约；内部短说明使用 `//`。
- 保持现有 .NET 命名：类型/成员 PascalCase，参数和局部变量 camelCase，私有字段 `_camelCase`。
- 原生 ABI、JSON 和协议字段保留其外部契约名称，不为内部命名一致性而破坏兼容性。
