# 通用代码规范

适用范围：[VeroScript 本项目开发与贡献](README.md)。

本文件只记录所有语言共用的规则。语言专属的缩进、花括号、类型布局和语法细节以各自
规范为准。

## 结构与层级

- 代码按职责分块；一个分块只表达一个容易命名的概念，例如继承接口、内部类型、公开方法、
  私有辅助方法或成员数据。
- 分块之间空一行。不要用连续空行、长分隔线或无意义的区域标题代替清晰结构。
- 嵌套作用域、命名空间、类型、方法、条件和循环必须体现真实层级；不得为了压缩行数而
  损失层次。
- 如果某项规则未定义，优先选择最接近代码的既有一致写法，而不是在一个变更中引入新风格。

## 缩进

- 自有、手工维护的源码、测试、示例和构建/工具脚本统一每个逻辑层级使用一个真实 Tab，默认显示宽度为四列；不使用纯空格代替层级缩进。
- Tab 表达逻辑层级；续行需要列对齐时，可在语言语法允许的位置使用对齐空格，不将两者混作代码块的层级缩进。
- 语言或文件格式的语法要求优先。[YAML 的层级缩进必须使用空格](https://yaml.org/spec/1.2.2/#61-indentation-spaces)，属于本规则的明确例外；Python 的解析规则见 [PYTHON.md](PYTHON.md)。
- 保留 Markdown 的文档结构，代码块内部按对应语言规范缩进。字符串、测试输入、第三方原文和生成结果不作机械转换；生成源码的格式通过所属模板按需调整。

## 文件换行符

- 本仓库自有文本文件统一使用 LF（`\n`），包括源码、测试代码、样例、文档、配置和构建/工具脚本；Windows、Linux 和 macOS 检出及编辑时采用相同规则。Tab 缩进规则不变。
- `.editorconfig` 与 `.gitattributes` 必须保持一致；维护本仓库文件的生成工具应显式使用 LF。仅转换实际行结束符，保留编码和 BOM；特别保留 Windows PowerShell 5.1 所需的 UTF-8 BOM。不改写字符串中的 `\r\n` 转义、协议分隔符、用户输入或字面量数据，也不缩减语言和工具对 CRLF 输入的支持。
- 第三方原文、外部导入的许可/构建工具文件、二进制资源和字节敏感夹具不参与机械转换，保留其内容及自身或既有的 Git 换行策略；项目自写的许可导航与说明仍使用 LF。不因目录名含 Tests 就跳过普通测试代码。
- Windows `.bat`、`.cmd` 启动脚本使用 CRLF。其他依赖物理换行值的多行字面量或夹具须按具体路径保留现有字节，并在 Git 与编辑器配置中声明有依据的例外；核实不再依赖原换行后再移除例外。不得为满足 LF 规则而改变测试输入、输出内容或运行行为。

## 命名

- 名称必须说明对象的职责、状态或值，不使用 `New`、`Old`、`Temp`、`Final`、`v2` 等阶段性名称。
- 同一概念在同一模块中只能有一种稳定命名；跨语言边界的协议名称保持原契约拼写。
- 布尔名称应表达肯定语义，让条件可直接阅读。
- 新缩写必须在局部上下文中易懂；已有公共缩写的大小写和拼写保持一致。

## 注释

- 所有自有、手工维护源码中的注释必须使用英语，包括单行注释、块注释、文档注释和区域注释。
  外部协议原文、第三方许可证或自动生成内容不按此规则翻译。
- 注释解释**为什么**、不变量、边界、所有权、线程要求、兼容性或非直观选择；不逐句翻译
  显而易见的代码。
- 类型、成员方法和成员变量按需提供必要注释。公共表面、复杂状态、资源所有权和容易误用的
  接口优先说明；名称已经充分表达的简单成员不写重复注释。
- 单行说明使用该语言惯用的单行注释语法（例如 C 系语言的 `//`、Python 的 `#`）。连续的
  说明性文字、参数/返回语义或格式化文档使用语言惯用的文档注释。
- 多行块注释只用于确实需要整体阅读的说明、许可证或嵌入文本；不要用它包裹普通代码。
- 注释与所描述代码保持相邻；代码变更时同步修改或删除过期注释。

- 自有、手工维护且采用 MIT 许可证的源码、测试、示例和构建/工具脚本统一使用下面的两行 SPDX 声明。新文件必须添加；旧的自有声明在统一迁移或相关修改时替换为新格式。
- 使用模板前，将 `<copyright-holder>` 替换为根目录 `LICENSE` 中权利人的准确写法；文件头不写年份和网址。两行顺序固定，字段名、版权人和许可证标识不翻译。
- C 系语言、C#、VeroScript、TypeScript/JavaScript、Java 和 Kotlin 使用 `//`：

```cpp
// SPDX-FileCopyrightText: <copyright-holder>
// SPDX-License-Identifier: MIT
```

- Python、CMake、PowerShell 和 Shell 脚本使用 `#`：

```python
# SPDX-FileCopyrightText: <copyright-holder>
# SPDX-License-Identifier: MIT
```

- XML、XAML 和 Avalonia `.axaml` 源码分别使用两行 XML 注释：

```xml

```

- 声明位于首个普通源码行之前，声明后空一行。shebang、编码声明、PowerShell `#requires`、XML 声明等有位置要求的指令保留在前，随后放置这两行声明。
- 生成源码和类型声明按需通过所属生成模板输出声明；不手改生成结果来满足文件头格式。
- 第三方或外部引入代码保留原有版权及许可证声明，不统一替换为本项目的名称或 MIT 标识。
- 不要求为 Markdown 文档、JSON/YAML 配置、图片和其他资源逐文件添加代码文件头。
- 两行 SPDX 声明不能替代完整许可文本。根目录 `LICENSE` 保留版权年份和完整 MIT 正文，保留原权利人；发行物按许可要求保留完整版权与许可声明。

## 换行与可读性

- 换行应服务于语义层级、参数分组和阅读方向，而不是机械凑行宽。
- 参数、模板参数、初始化器或条件过长时，按逻辑单元换行，并让续行明显属于同一表达式。
- 不要求在每个左花括号后或右花括号前插入空行；是否留空行取决于第一个/最后一个逻辑分块。
- 一行只承载一个主要意图。简单卫语句、空函数或语言惯用的简写是否可作为例外，以对应语言
  规范的明确规定为准；未规定时不使用简写。
- 在语言支持相应语法时，`else`、`else if`（PowerShell 为 `elseif`）、`catch`、`finally` 和 `do…while` 的尾部 `while` 必须另起一行，与前一块的右花括号对齐，不得写成 `} else` 等同行形式。
  子句若有块体，其左花括号也必须另起一行并与子句对齐，块内语句和右花括号分别独立成行。
  不要改写字符串、测试输入或第三方原文来机械满足排版；宏中的换行必须保留续行语义。

- 格式化器、输出源码的代码生成模板和现行文档示例也必须遵循上述子句布局；测试输入保留其原有覆盖目的。

```cpp
if (bPrimary)
{
	HandlePrimary();
}
else
{
	HandleFallback();
}
```

## 修改原则

- 只改变当前任务需要的内容；不删除、覆盖或重排无关的用户修改。
- 行为、公共接口、序列化格式或跨语言边界变化时，必须同步维护声明、实现、调用方和测试。
- 需要拒绝、恢复或降级的情况必须对调用者可观察；不能把失败伪装成成功。
- 外部输入、文件路径、进程参数和资源生命周期应在其所属边界完成校验和清理。


## 编辑器与嵌入平台

Core 管理语言语义、执行服务及通用 VM／JIT 契约。字节码解释循环归 `Modules/Execution/VeroScriptBytecodeVm`；具体 JIT 编译、IR、原生发射和第三方后端依赖归 `Modules/Execution`。后端使用公开契约，在实例、工作线程和保留代码存续期间保持模块所有权。动态选择先验证 ABI 再调用工厂；失败保留先前后端，执行期间不得更换后端或修改其配置。

编辑器客户端管理设置和协议展示。Mobile/Android/iOS 适配使用公开 C ABI，显式提供资源，并记录实际平台验收。遵守创建线程所有权、回调寿命和取消/reset 契约；配额不能描述为完整沙箱。Kotlin/Java 的命名和结构遵循模块惯例，缩进遵循本文件的统一规则；Objective-C/Objective-C++ 遵循平台所有权约定及原生边界规则。协议标识符保持稳定。

User 面向任务、可观察行为和公开 API 使用；Developer 面向源码架构、构建、测试门禁和出版；历史版本及环境验收记录保留在版本控制或被忽略的证据中，不属于出版文档。接口变化同步六语言现行文档，界面验证和诊断通过所属目录翻译，保留 ID、选项键和占位符。检查源码链接及 All/User 出版；跳过的平台或 IDE 测试不能支撑发行认证。
