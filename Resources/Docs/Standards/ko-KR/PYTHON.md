# Python 코드 규약(잠정)

적용 범위: [VeroScript 프로젝트 개발 및 기여](README.md).

Python은 [GENERAL.md](GENERAL.md)의 구조, 주석, 최소한의 필요한 설명 원칙을 따릅니다. Python에는 중괄호와 접근 제한자가 없으므로 모듈과 클래스의 선언 순서로 해당 계층을 표현합니다.

## 형식

- 논리 계층마다 실제 Tab 하나를 사용하고 기본 표시 너비는 네 칸으로 하며 [GENERAL.md](GENERAL.md)의 들여쓰기 규칙을 따릅니다.
- [Python은 Tab을 여덟 칸 경계로 해석](https://docs.python.org/3/reference/lexical_analysis.html#indentation)하며 편집기 표시 너비와 무관합니다. 블록 계층은 Tab으로 통일하고 이전 시 화면 열 수에 따른 기계적 교체 대신 기존 블록 경계를 유지합니다.
- 각 `class`, `def`, 조건문, 반복문, `try`, 컨텍스트 관리자의 실행 본문은 올바르게 들여써야 합니다. 한 줄 복합문으로 로직을 압축하지 않습니다.
- `if`, `for`, `while`, `try` 등의 실행 본문은 별도의 들여쓰기 블록이어야 합니다. Python에는 C++의 한 줄 `return` 가드문 예외를 적용하지 않습니다.
- `match`로 `switch` 형태의 분기를 표현할 때는 기본 분기로 `case _`를 반드시 포함하고, 알 수 없거나 지원하지 않는 입력을 명확히 처리해야 합니다.
- 조건부 import와 버전 분기는 제어하는 코드와 같은 논리 영역에 유지하여 완전한 의미 단위를 분리하지 않습니다.

## 모듈과 타입 배치

모듈의 권장 순서는 다음과 같습니다.

1. 모듈 docstring과 `__future__` import
2. 표준 라이브러리, 외부 라이브러리, 프로젝트 import
3. 상수, 타입 별칭, 프로토콜
4. `Enum`
5. `dataclass` 또는 기타 데이터 타입
6. 기타 보조 타입
7. 클래스
8. 모듈 함수와 명령줄 진입점

클래스의 권장 순서는 다음과 같습니다.

1. 클래스 상수와 클래스 수준 타입
2. 상속 또는 프로토콜에서 요구하는 메서드
3. 내부 `Enum`, 데이터 타입, 기타 타입, 클래스
4. `__init__`, 대체 생성자, 공개 메서드와 속성
5. 보호 및 비공개 보조 메서드
6. 클래스 변수. 인스턴스 상태는 `__init__`에서 집중적으로 구성하며 메서드 사이에서 산발적으로 추가하지 않습니다.

- 여러 기반 클래스나 프로토콜의 구현은 상속 목록 순서로 묶습니다. 필요하면 `#~ Begin <Name> Interface` / `#~ End <Name> Interface` 쌍 형식의 주석이나 Python에 더 자연스러운 짧은 주석을 사용합니다.
- 이름은 Python 관례를 따릅니다. 모듈, 함수, 변수는 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`를 사용하며 내부 구현은 앞에 밑줄을 붙입니다.

## 주석

- 모듈, 공개 클래스, 공개 함수의 직관적이지 않은 계약은 docstring으로 설명합니다.
- 지역적인 이유 설명에는 `#`를 사용하며, 이름으로 설명된 변수나 함수에 같은 설명을 반복하지 않습니다.
- 타입 주석으로 공개 입력, 출력, 복잡한 데이터 구조를 표현합니다. 엄격성 수준은 추후 별도로 보완할 수 있습니다.
