# TypeScript 및 JavaScript 코드 규약(잠정)

적용 범위: [VeroScript 프로젝트 개발 및 기여](README.md).

TypeScript/JavaScript는 [GENERAL.md](GENERAL.md)의 구획, 주석, 최소한의 필요한 설명 원칙을 따릅니다. 아래 절의 줄바꿈 규칙은 필수이며, 다른 중괄호 배치는 잠정적으로 해당 모듈의 기존 스타일을 따릅니다.

## 현재 잠정 규칙

- `else`, `else if`, `catch`, `finally`, `do…while` 끝의 `while`은 [GENERAL.md](GENERAL.md)에 따라
  새 줄에 둡니다. 블록의 여는 중괄호도 절에 맞춘 독립된 줄에 둡니다.
- 논리 계층마다 실제 Tab 하나를 사용하고 기본 표시 너비는 네 칸으로 하며 [GENERAL.md](GENERAL.md)의 들여쓰기 규칙을 따릅니다.
- 타입, 함수, 조건문, 반복문, `switch`를 의미에 따라 구획하며 불필요한 한 줄 압축을 피합니다.
- 모든 `switch`에는 `default`가 있어야 합니다. TypeScript의 완전성 검사는 `default`에서 구현할 수 있지만 정적 검사를 이유로 `default`를 생략해서는 안 됩니다. 이 분기는 알 수 없는 값을 명확히 처리해야 합니다.
- 각 `case`와 `default`의 실행 내용은 독립적인 중괄호 스코프에 넣으며 암묵적인 fallthrough에 의존하지 않습니다. 의도적으로 처리 로직을 공유한다면 바로 옆의 설명 주석으로 의도를 나타냅니다. 유일한 예외는 해당 레이블의 유일한 실행 경로가 현재 함수를 바로 종료하는 `return`이며 다른 문장이 전혀 없는 경우입니다.
- 모든 제어 분기에 중괄호를 사용해야 합니다. 유일한 예외는 본문이 직접적인 `return` 또는 `return <표현식>` 하나뿐인 한 줄 가드문입니다. `else` 체인, 로그, 정리 작업 또는 다른 문장과 조합해서는 안 됩니다.
- TypeScript 모듈 수준 타입은 `enum` → `interface` → `type`/기타 타입 별칭 → `class` 순서로 배치합니다. 제네릭 인터페이스와 클래스는 각각 자신의 분류에 속합니다. JavaScript에 대응하는 타입 선언이 없다면 export 관계와 의존성에 따라 같은 수준으로 명확한 순서를 유지합니다.
- 클래스 내용은 C++의 전체 순서를 참고합니다. 관련 별칭/상수, 상속 또는 인터페이스 구현, 내부 타입, 메서드, 필드 순서이며 필드는 해당 접근 의미 영역의 마지막에 둡니다.
- 여러 인터페이스 구현이나 어댑터 구획은 필요할 때 `//~ Begin <Name> Interface` / `//~ End <Name> Interface` 쌍 주석을 사용합니다.
- export 타입, 인터페이스, 클래스는 PascalCase를, 함수, 필드, 매개변수, 지역 변수는 camelCase를 사용합니다. 외부 프로토콜 필드는 계약상의 이름을 유지합니다.
- 외부에 공개되는 데이터, 오류, 자원 해제 의미는 타입이나 필요한 주석으로 표현해야 합니다.
