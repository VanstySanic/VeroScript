# 패키징 및 배포 규범

범위: [VeroScript 프로젝트 개발 및 기여](README.md). 공식 배포 모음, 후보 빌드와 배포 검증을 규정하며 외부 프로젝트의 라이선스나 패키징 방식은 변경하지 않는다.

## 규범과 구현 상태

공통 등록부와 배포 스크립트가 분류 경로와 새 형식을 구현한다. 순수 계획과 정적 회귀는 성공한 실제 빌드와 페이로드 무결성 검사를 대체하지 않는다. 대상 실행과 설치 수명주기 검증 결과는 실패와 미실시를 포함해 별도로 기록한다. 새 계약만 수락하며 구형 형식 호환·변환·이중 쓰기·이관을 제공하지 않고 기존 결과물을 정리한 뒤 재빌드한다.

제품 등록, 버전, 순수 계획, 생성기, 페이로드, 매니페스트, 검사, 트랜잭션, 정리와 CI를 함께 맞춘다. schemaVersion을 명시하고 새 리더는 새 계약만 수락하며 구형 형식은 안전하게 거부한다. 호환 분기는 유지하지 않는다. 형식·제품 버전은 독립이며 제품 버전은 등록 정보를 따른다. [배포 구조](../../../../VeroScriptInstaller/Resources/Docs/Developer/ko-KR/release-layout.md)를 참고하며 기존 `migrate-layout`은 새 절차에서 제외한다.

## 디렉터리와 책임

정식 루트는 소스 루트의 `Release/`이며 바깥 폴더 이름 `Script`, `VeroScript`에 의존하지 않는다. 체크아웃 이동 시 내부 상대 경로를 유지하고 컴파일 경로에 의존하는 캐시는 재빌드한다. 후보, 빌드 캐시와 검증 로그는 Release 밖의 전용 임시 영역에 둔다.

```text
Release/
  release-index.json
  indexes/<target>.json
  Runtime/<target>/<version>/
  CoreSDK/<target>/<version>/
  Interop/<target>/<version>/
  Resources/any/<version>/Resources/
  Modules/
    Execution/{Jit,Vm}/<target>/<version>/
    Network/{Json,Network,Http,WebSocket}/<target>/<version>/
    Network/Backend/{Boost,Curl}/<target>/<version>/
    Multimedia/{Platform,Graphics,Audio,Image,Font,Gui}/<target>/<version>/
    Multimedia/Backend/{Sdl3,Stb,FontBackend,RmlUi}/<target>/<version>/
  Extensions/
    Language/{Cpp,CSharp,Python}/<target>/<version>/
    Editor/VSCode/{VSCode,GuiVSCode}/<target>/<version>/
    Editor/JetBrains/{JetBrains,GuiJetBrains}/<target>/<version>/
    Platform/Mobile/{Android,iOS}/<target>/<version>/
    Platform/WebAssembly/<target>/<version>/
```

`<business-route>`는 등록된 분류 경로와 제품 이름을 포함한다. `<target>`은 빌드 호스트가 아닌 네이티브/모바일 대상, `any` 또는 `wasm32` 배포 범위를 뜻한다. `{A,B}`는 별도 디렉터리를 뜻한다.

버전 폴더에는 필요한 분류만 만들고 매니페스트와 체크섬은 버전 루트에 둔다.

| 경로 | 용도 |
| --- | --- |
| `archives/` | 압축 해제하여 배치하는 런타임 배포 |
| `sdks/` | 개발 인터페이스, 빌드 내보내기와 필수 의존성을 포함하는 SDK 아카이브 |
| `packages/` | `.vspkg`, `.vsix`, 플러그인 ZIP, `.nupkg`, wheel, sdist, AAR |
| `installers/` | 지원되는 제품 설치 프로그램과 선택한 다운로드 형식 |
| `symbols/` | 소유 제품의 심벌 배포, `.snupkg` 포함 |
| `Resources/` | Resources 전용의 느슨한 Assets, Docs, Scripts, Examples 트리 |
| `release-manifest.json`, `checksums.txt` | 제품, 범위와 버전의 목록 및 해시 |

확장자만으로 판단하지 않고 용도와 매니페스트 역할로 분류한다. 생태계 패키지를 같은 내용의 ZIP으로 기계적으로 다시 포장하지 않는다. 추가 헤더·빌드 자원이 필요한 SDK는 완전한 아카이브를 유지할 수 있다. Unix 컨테이너는 실행 권한과 필수 라이브러리 링크를 보존한다. 설치 프로그램 다운로드 형식은 기본 한 종류이며 독립적 사용 목적이 있을 때만 원본과 압축본을 함께 제공한다. 배포 분류가 설치 경로를 자동 변경하지 않는다.

Runtime, CoreSDK, Interop, Resources는 루트, Cpp, CSharp, Python, WebAssembly, 네 편집기 제품과 Android/iOS는 Extensions, 실행·네트워크·멀티미디어 모듈은 Modules에 속한다. 패키지 클라이언트는 Runtime/CoreSDK에 포함하고 별도 제품을 만들지 않는다. 등록은 신규 제품, 의존성, 역할, 대상 기능과 제외 사유를 다룬다. 완전성은 선택 대상과 배포 프로필에 따라 판단하고 모든 플랫폼에 모든 제품을 요구하지 않는다.

집합 이름은 `archives`, `sdks`, `packages`, `installers`, `symbols`, `indexes`의 복수형으로 고정한다. Modules와 Extensions 아래 Execution, Network, Multimedia, Language, Editor, Platform, Backend는 소스 철자를 유지하고 제품 ID와 패키지 이름은 바꾸지 않는다.

## 대상 범위와 공유 결과물

네이티브 배포는 OS/아키텍처별로 구분한다. 예: `win-x64`, `win-arm64`, `linux-x64`, `linux-arm64`, `macos-x64`, `macos-arm64`. 다른 등록 아키텍처도 실제 지원 프로필을 명시하며 등록만으로 전체 배포를 보장하지 않는다. `android`는 다중 ABI이고 `ios`는 실제 기기와 시뮬레이터를 포함하며 iPadOS도 같은 SDK를 사용한다. WebAssembly SDK는 `wasm32`, 네이티브 설치 프로그램은 호스트 대상으로 분류한다.

`any`는 단일 네이티브 대상으로 나누지 않는 공유 배포 위치이다. 플랫폼 중립 파일 또는 여러 대상을 지원하는 같은 패키지에 사용할 수 있으나 `supportedTargets`, ABI, TFM, 런타임 의존성과 제한을 정확히 선언한다. 모든 플랫폼 지원을 뜻하지 않으며 Android 다중 ABI AAR와 iOS XCFramework는 각 플랫폼 범위를 유지한다.

공유 배포는 제품/버전별 한 번 저장하고 매니페스트 참조로 재사용한다. 기존 네 편집기 플러그인, 중립 Resources, 정리된 Python sdist, 같은 Android/iOS C# NuGet은 공유 위치를 사용한다. 정규 JS/WASM SDK를 한 번 생성하고 네이티브 설치 프로그램을 범용으로 표시하지 않는다. 혼합 제품은 `any`와 네이티브 폴더를 함께 가질 수 있다. Python sdist는 `any`, wheel은 실제 플랫폼/ABI별이다.

제품, 버전, 용도, 지원, 의존성, ABI 계약과 최종 해시가 모두 일치할 때만 통합한다. 같은 이름·확장자만으로는 부족하다. 명확한 생성 계약에 따라 정규 바이트를 먼저 만든 뒤 매니페스트, 서명과 해시를 생성한다. 자체 텍스트는 UTF-8/LF를 쓰되 필수 BOM·batch 예외를 보존한다. 바이너리, 서명, 제삼자 원문과 바이트 민감 입력은 기계적으로 변환하지 않는다. 정식 공유 참조는 디렉터리 간 심벌릭·하드 링크에 의존하지 않는다.

독립 설치 프로그램, wheel, 오프라인 SDK는 선언한 필수 런타임 의존성을 포함한다. 독립 사용 가능성이 디스크 중복 제거보다 우선한다. 필수 라이브러리를 인접 Release 폴더로 옮기고 다운로드 사용자가 이를 보유한다고 가정하지 않는다.

`supportedTargets`는 실제 페이로드 대상을, `consumerTargets`는 참조 가능한 배포 대상을 기록한다. wasm32 SDK는 네이티브 호스트 인덱스에서 참조할 수 있다. 공통·네이티브 조합은 실제 생태계 버전을 일치시킨다.

## 독립 버전과 의존성

제품과 대상은 독립 버전을 허용한다. `ReleaseVersions.json`은 기본값이며 모음 전체 제품 버전이 아니다. 공유 배포도 명시적 버전을 갖고 다른 대상이 참조하는 내용을 플랫폼 갱신으로 조용히 덮어쓰지 않는다. 인덱스는 선택 버전과 매니페스트 해시를 고정하며 최신 버전을 암묵적으로 선택하지 않는다. NuGet, wheel, sdist, 플러그인과 바이너리는 실제 버전을 유지하고 이름 변경·허위 태그를 금지한다.

네이티브 버전, 제품 버전, 공개 ABI, 빌드 식별자와 형식 버전을 분리 기록한다. Cpp/Core, GUI 추가/기본 플러그인, 모듈 의존성을 실제 버전·ABI·식별자·라이브러리 해시로 검증한다. 외부 배포된 동일 패키지 식별자의 내용을 조용히 바꾸지 않는다. 미공개 로컬 후보 재빌드는 해시를 갱신하고 영향받은 검증을 무효화하며 제품 버전 정책도 명시한다.

동일 생태계 패키지 식별자는 유일한 내용에 대응해야 한다. 같은 ID/버전의 서로 다른 NuGet·sdist를 여러 플랫폼 폴더에 두고 경로로 구분하지 않는다. 차이는 TFM, RID, ABI나 플랫폼 태그로 표현하며 합칠 수 없으면 기존 ID/버전 계약을 지키면서 다른 배포 식별자를 명시한다.

공유 `any`/`wasm32` 매니페스트를 관리 컬렉션에 게시한 뒤에는 제품/범위/버전 식별자를 변경하지 않는다. 선택적 심볼과 선언된 지원 범위도 포함되므로 전체 공유 목록을 수집한 뒤 확정하고, 변경 시 새 제품 버전을 사용한다. 게시되지 않은 로컬 출력을 명시적으로 삭제한 클린 재빌드만 설정 버전을 유지할 수 있다. 로컬 파일을 삭제해도 사용자에게 이미 배포한 식별자의 내용을 변경할 수는 없다.

`any`/`wasm32` 매니페스트에는 배포 호스트의 네이티브 버전을 기록하지 않는다. C# 네이티브 버전 문맥은 각 소비 대상 인덱스의 제품 항목에 기록하고 공통 패키지 식별은 내용과 계약으로 결정한다.

## 인덱스, 매니페스트와 참조

`release-index.json`은 형식 버전 **1**과 제품 식별자 `VeroScript Release Set`을, `indexes/<target>.json`은 **5**, 제품 매니페스트는 **3**을 사용한다. 임시 후보 매니페스트는 **2**와 `VeroScript Release Candidate`를 사용한다. `checksums.txt`는 제품·범위·버전별로 생성한다. 인덱스의 `manifests[]`는 범위, 실제 버전, 상대 경로와 SHA-256을 기록하며 분류와 역할은 공통 등록부를 따른다.

루트 `release-index.json`은 모음 진입점으로 구조/형식 버전, 세대, `indexes/<target>.json` 상대 경로와 SHA-256을 기록한다. 모든 제품의 가상 공통 버전을 만들지 않는다. 대상 인덱스는 각 선택을 독립 관리하고 공유 인덱스는 공유 배포를 관리한다.

한 대상의 한 제품이 여러 매니페스트를 참조할 수 있다. 예: Python 대상 wheel과 `any` sdist. 각 참조는 `target`, `version`, 상대 매니페스트 경로와 SHA-256을 포함한다. 제품당 같은 대상 매니페스트 하나라는 구형 가정을 제거한다. 제품과 대상별로 독립적인 버전을 선택할 수 있지만, 한 대상 인덱스에서 동일 제품을 구성하는 공유·네이티브 구성요소는 생태계/제품 버전이 일치해야 하며 호환성과 완전성을 함께 검증해야 한다.

제품 매니페스트는 제품, 범위, 실제 버전, 빌드/소스 식별자, `supportedTargets`, 의존성, 역할과 전체 파일 목록을 기록한다. 파일별 분류 후 상대 경로, 크기와 SHA-256을 기록한다. 네이티브에는 OS, 아키텍처, ABI, 최소 OS/API, 도구 체인과 슬라이스, 생태계 패키지에는 Python ABI·TFM 등을 추가한다. 같은 목록으로 `checksums.txt`를 만들고 선택, 경로, 메타데이터와 바이너리 식별자를 일치시킨다.

매니페스트 파일은 제품 버전 루트, 인덱스의 매니페스트 경로는 Release 기준으로 해석한다. 경로 순회, 절대 경로, 링크 탈출, 대소문자/예약명 별칭, 중복, 알 수 없는 파일과 순환 참조를 거부한다. 범위 간 참조는 관리되고 대상을 지원하는 매니페스트로 제한한다. 전체 의존/참조 폐쇄를 검증하고 디렉터리 이름으로 내용을 추측하지 않는다.

목록은 실제 결과물과 느슨한 자원을 다루며 자신의 매니페스트와 `checksums.txt`는 빼서 자기 참조 해시를 피한다. 상위 인덱스는 매니페스트 해시, 루트는 인덱스 해시를 고정한다. 형식별 파일 유형, 실행 권한과 안전한 상대 라이브러리 링크를 기록·검사하며 일반 파일 바이트만 비교해 실행 가능성을 잃지 않는다. 해시 검증은 게시자 신원이나 실제 서명 정책을 대체하지 않는다.

인덱스는 선택 구성요소 배포와 전체 플랫폼 완료를 구분하고 프로필 필수 제품, 누락, partial과 미검증을 기록한다. 구성요소 성공으로 전체를 인증하지 않는다. 정식 결과물 없는 대상에 성공 인덱스를 만들지 않고 빌드/검증 부족은 후보 보고서에 남긴다.

## 기능 페이로드와 소스 배포

Runtime, SDK, Extensions, Modules와 설치 프로그램은 기능, 실행 자원, 메타데이터와 법적 고지만 포함하고 README, 설명서, 자습서, 예제, 테스트, 벤치마크와 이력을 제외한다. Resources가 통합 User 문서와 관련 자원을 제공한다. Standards는 개발·기여용 All에만 포함하고 User·기능 패키지에는 넣지 않는다. 라이선스, NOTICE, 필수 현지화, 아이콘, 문법, 코드 조각과 실행 데이터를 보존한다. 개발용 Node.js/Sharp를 Runtime/SDK 의존성으로 만들지 않는다.

VS Code VSIX 루트의 `extension/readme.md`는 확장 세부 정보 페이지의 메타데이터입니다. 이 특정 표시 파일은 모듈 README 정본의 텍스트와 일치하고 패키지 안의 리소스나 온라인 가이드를 연결할 때 포함할 수 있습니다. 다른 README, 설명서 및 Developer/Tutorials 트리는 기능 패키지에서 계속 제외합니다.

Jit와 미래 모듈을 포함한 모든 Modules는 독립 제품 설치 프로그램을 제공하지 않고 심벌은 소유 제품에서 별도 배포한다. 설치 프로그램은 문서/예제 선택을 제공하지 않고 고정 페이지 마법사와 소유권 규칙을 유지한다. 연결, 아이콘, PATH 선택 해제·제거는 해당 설치 소유 설정만 정리한다.

sdist는 빌드 가능한 소스의 명시적 예외로, 독립 압축 해제 후 빌드하는 데 필요한 최소 소스, 헤더, 스크립트, 메타데이터와 법적 고지를 포함하며 무관한 설명/예제는 제외한다. `.cxx`, `.gradle`, `.externalNativeBuild`, CMake 캐시, 오브젝트, 컴파일 결과와 로컬 경로를 배제·검사한다. `.gitignore`나 우연히 깨끗한 호스트에만 의존하지 않는다. 실제 아카이브 구성원을 검사하고 필요하면 격리 sdist에서 소비자를 재빌드한다.

모듈 설치, 패키지 활성화, 실행 백엔드/서비스 공급자 선택은 별개다. 호스트 설정은 생략/auto/none/명시 선택의 공통 규칙을 따르며 auto는 설치되고 활성화된 호환 후보를 선택할 수 있다. 배포·설치는 호스트의 백엔드 설정과 비활성 선택을 보존하고 선택적 Jit/공급자를 Runtime/CoreSDK 기본 페이로드에 조용히 추가하지 않는다.

아이콘은 공식 Assets와 자동 자원 목록을 기준으로 하며 새 파일을 버전 관리·CI 입력에 추가하고 과거 개수를 고정하지 않는다. SVG/PNG/ICO/ICNS 등 원시/바이너리 자원을 소스와 개별 비교하고 설치 참조는 안정된 제품 경로로 해석한다. 내장 아이콘 변경 시 참조 프로그램/설치 프로그램을 재빌드하고 외부 ICO 교체로 EXE 재빌드를 대신하지 않는다. 연결, 새로 고침과 제거는 설치 소유권 계약을 유지한다.

소스 기반 검증은 재사용 빌드를 포함하여 Windows CLI, Runtime, launcher, LSP, DAP 및 설치 프로그램 EXE의 내장 아이콘 프레임도 확인합니다. VS Code에 선언된 제품 PNG는 관리되는 공식 리소스와 직접 비교합니다.

## Android, iOS와 모듈 SDK

Android 주 SDK는 Core/Interop, 공통 Mobile 계층, JNI, AAR, 표준 라이브러리, 필수 자원과 라이선스를 통합한다. iOS는 정적 어댑터와 XCFramework를 통합한다. 공통 Mobile 계층은 사용자가 별도로 설치할 제품이 아니다. 주 SDK가 모든 선택 모듈을 자동 포함하는 것은 아니다.

`Modules/<category-route>/<business>/<android|ios>/<version>/sdks/`는 선택적 네이티브 CMake 개발 배포이며 또 다른 주 SDK나 데스크톱 `.vspkg`가 아니다. 필수 헤더, CMake 내보내기와 선언한 의존 폐쇄를 보존하고 내장/외부 의존성을 구분하여 충돌·중복 링크를 막는다. 주 AAR가 있다고 독립 제공이 필요한 C++ API나 모듈 개발 지원을 삭제하지 않는다.

완전한 모바일 배포는 플랫폼 어댑터, CoreSDK, Cpp, Interop, Vm, CSharp, Python과 선택 모듈의 계약을 충족한다. 일반 앱은 주 SDK와 필요한 모듈만 쓰며 모든 개발 키트를 내려받을 필요가 없다. Android는 현재 arm64-v8a/x86_64, iOS는 device-arm64, simulator-arm64, simulator-x86_64를 포함한다. 실제 바이너리와 소비자 링크를 슬라이스별 검증하며 같은 CPU가 같은 OS나 기기/시뮬레이터 ABI를 뜻하지 않는다. iOS에서 불가능한 네이티브 JIT는 명시 제외하고 이름 변경으로 지원을 가장하지 않는다.

C#은 실제 TFM·네이티브 라이브러리·자원으로, Python은 선언된 CPython 행렬과 모바일 슬라이스로 선택한다. .NET, Xcode, NDK와 대상 의존성을 일치시키며 SDK 컴파일 버전과 최소 실행 OS를 따로 기록한다.

## 교차 빌드와 검증

소스/설정 사전 검사, 실제 빌드, 후보 조립, 정적 검증, 대상 실행, 배포와 최종 검증을 구분한다. 교차 컴파일 가능한 대상은 실제 대상 산출물을 만들며, 로컬 실행 환경 부족을 컴파일 불가로 판단하지 않는다. 빌드와 무결성 검증을 통과한 패키지는 실행 검증이 미실행 또는 실패인 경우에도 Release에 포함할 수 있다. 상태를 명시하고 빌드 성공을 실행 검증 통과로 간주하지 않는다.

빌드 호스트와 대상 식별자를 분리 기록한다. 대상 컴파일러, sysroot, 헤더와 전체 의존성을 사용하며 실행하는 생성기는 호스트 버전을 쓴다. 네이티브, C# AOT, wheel, 설치 프로그램과 제삼자 라이브러리를 개별 검증하고 RuntimeIdentifier·이름·태그만 바꾸지 않는다. 데스크톱 ARM64는 모바일 ARM64 검증을 상속하지 않는다.

검증은 `passed`, `failed`, `not-run`, `not-applicable`로 구분하며 이유, 환경, 도구, 설정과 증거 해시를 기록한다. 교차 컴파일/링크, 에뮬레이터, 실기기, 그래픽, 설치 수명 주기, 서명/공증, C# AOT/트리밍, Python을 별도로 관리한다. 실제 빌드와 내용·아키텍처·소스·의존성·목록·SHA-256 검증은 배포 전 필수다. 실행/기기 검증의 공백은 빌드된 산출물의 배포를 막지 않는다. 미실행, 실패, 미서명 또는 도구 부족을 통과로 기록하지 않는다. 업무 `qualification` 버전 1은 `manifests[]`의 정확한 경로와 해시에 검사를 연결하며 내용 변경 시 이전 증거는 무효다. `complete`는 필수 산출물 목록의 완전성만 뜻하고 `qualificationStatus`는 검증 상태를 집계한다. 목록이 완전하고 모든 필수 검사가 통과해야 `qualified`가 true다. 증거가 없으면 `not-recorded`이며 성공으로 추정하지 않는다.

macOS 설치기는 공식 ICNS, Info.plist와 실행 파일을 갖춘 표준 `.app`을 `.dmg`으로 제공한다. Linux는 실행 권한을 유지하는 `.tar.gz`, Windows는 `.exe`를 사용하며 SDK 압축 형식은 별개다. 서명 후 이미지를 만들고 검증한다. ad-hoc 서명은 Developer ID나 공증이 아니다. 다른 OS에서 DMG를 감사할 때는 빌드 도구 7-Zip(`VEROSCRIPT_7ZIP` 또는 PATH)을 사용하며 제품 실행 의존성은 추가하지 않는다.

데스크톱 교차 조립은 `Resources/Tools/Packaging/package-veroscript-desktop-cross.py`를 사용한다. 대상 컴파일러가 공식 헤더 식을 평가해 ABI를 만들며 호스트 ABI를 복사하지 않는다. 대상을 실행할 수 없다면 전체 선언 소스가 같고 두 개 이상 네이티브 플랫폼의 카탈로그가 일치할 때만 중립 카탈로그를 재사용한다. 32비트 대상은 자체 카탈로그를 내보내야 한다. 대상 도구/에뮬레이터는 `--target-tool`로 지정하며 카탈로그 조회를 전체 실행 검증으로 간주하지 않는다. 호스트 설치 도구는 타 대상의 조립, 해시 검사와 압축을 수행할 수 있지만 실제 설치는 OS와 아키텍처가 일치해야 한다.

서명, 공증과 바이트 변경 후처리를 끝낸 뒤 최종 배포 해시와 검증 증거를 연결하고 내부 목록도 따로 검증한다. 서명 전 해시로 서명된 파일을 인증하지 않는다. 배포 후 최종 디렉터리, 아카이브, 참조 경로와 내장 내용을 다시 검사하며 바이트 변경은 해당 증거를 무효화한다.

## 배포, 취소 및 정리

배포와 정리는 모음 잠금을 공유한다. 후보, 지원, 참조 폐쇄와 출처를 검증한 뒤 관리 임시 영역에 파일/매니페스트/인덱스를 준비하고 제품, 대상 인덱스, 마지막으로 루트 진입점을 복구 가능한 트랜잭션으로 커밋한다. 실패하면 내용과 참조를 복원한다. 리더는 잠금 또는 세대/해시 재검사를 사용하고 갱신 중 불일치는 재시도한다. 모음 전체의 단일 원자적 교환이라 주장하지 않는다.

취소는 해당 작업의 빌드 하위 프로세스·전송만 멈추고 미완료 후보를 배포하거나 정식 결과물을 덮어쓰지 않는다. 필수 진단을 보존하고 임시 환경을 복구한다. 재개 전 소스, 설정, 도구와 후보 해시를 확인하고 오래된 검증을 재사용하지 않는다.

모든 대상 인덱스·매니페스트 의존성의 참조 폐쇄로 정리한다. 기본은 참조 없는 구버전 삭제이며 다른 대상, Cpp, GUI 추가 플러그인이 사용하는 버전은 보존한다. 공유 패키지는 마지막 참조가 없어져야 삭제할 수 있다. 알 수 없는/비관리 파일이나 경로 검사 실패 시 중단하고 나이·이름으로 소유권을 판단하지 않는다. 검증된 전용 임시 폴더만 삭제하며 소스, 사용자 파일과 외부 의존성은 삭제하지 않는다.

구형 결과 제거 전에 소유권, 소스 보호, 사용 프로세스와 재사용 도구를 확인한다. 이전 Release·불필요 후보/캐시를 지우고 필수 진단만 보존하며 구형 패키지 복구 사본이나 구형 인덱스 의존성으로 이전 모음을 유지하지 않는다. 깨끗한 임시 영역에서 새 규칙으로 재빌드·검증·배포하고 제품 버전은 등록 정보를 따른다. 새 모음 내부 현재 참조된 유효 버전은 폐쇄로 보호하며 이는 구형 규범 호환이 아니다.

## 구현 조건

실제 생성기와 공유하는 순수 계획, 공유 참조/버전, 분류/메타데이터 검증, 범위 간 의존성·잠금·복구·참조 정리 테스트, 오염 소스/구형 형식 거부, 대상 기능/증거, 깨끗한 재빌드와 실패 복구를 제공한다. 완료 전 배포하지 않고 구형 계획으로 새 구조를 인증하지 않는다.

규범만 갱신할 때는 컴파일, 설치 프로그램 생성이나 배포 패키징을 시작하지 않는다. 여섯 언어, 탐색과 기존 구현 설명을 맞추고 Release에 게시하지 않는 임시 문서 검사를 실행한다.

```text
python Resources/Tools/Packaging/veroscript_docs.py check
python Resources/Tools/Packaging/veroscript_docs.py check-collection
```
