# C# 코딩 규칙(잠정)

적용 범위: [VeroScript 프로젝트 개발 및 기여](README.md).

C#은 [GENERAL.md](GENERAL.md)의 원칙과 [CPP.md](CPP.md)의 관계 → 타입 → 메서드 → 데이터 구조를 따릅니다. C# 구문에 대응하지 않는 부분은 이 파일을 우선합니다.

## 형식

- `else`, `else if`, `catch`, `finally`, `do…while` 끝의 `while`은 [GENERAL.md](GENERAL.md)에 따라
  새 줄에 둡니다. 블록의 여는 중괄호도 절에 맞춘 독립된 줄에 둡니다.
- 논리 계층마다 실제 Tab 하나를 사용하고 기본 표시 너비는 네 칸으로 하며 [GENERAL.md](GENERAL.md)의 들여쓰기 규칙을 따릅니다.
- 블록 본문 타입, 메서드, 속성, 제어 분기 및 `switch`는 C++와 같은 Allman 중괄호 배치를 사용합니다.
- 직접적이고 읽기 쉬운 표현식 하나뿐인 멤버, 접근자 및 지역 매핑은 `=>`를 사용할 수 있습니다. 여러 단계, 자원 관리, 로그 또는 복잡한 제어를 숨기지 않으며 다단계 논리는 Allman 블록으로 작성합니다.
- 본문이 있는 모든 `if`, `else`, 루프, `using`, `lock`, `try`, `catch`, `finally`는 중괄호를 사용합니다.
- 유일한 예외는 직접적인 `return` 또는 `return <표현식>` 하나뿐인 한 줄 가드입니다. `else` 연결, 로그, 정리 또는 다른 문장과 결합하지 않습니다. `break`, `continue`, `throw` 등에는 항상 중괄호가 필요합니다.
- 모든 `switch` 문에 `default`가 필요합니다. `switch` 표현식은 입력을 완전히 다루며 앞선 패턴의 완전성을 증명할 수 없으면 `_` 대체 항목을 둡니다. 이미 완전하여 `_`가 도달 불가능하다면 형식상 추가하지 않습니다. 알 수 없는 값 처리를 명확하게 하며 불분명한 실행 실패에 의존하지 않습니다.
- 각 `case`/`default` 본문은 독립 중괄호 범위를 사용하고 암묵적 통과를 사용하지 않습니다. 의도적 공유 처리는 인접 주석으로 설명합니다. 유일한 예외는 단일 경로가 직접 `return` 또는 `return <표현식>`으로 메서드를 끝내고 로그, 정리, 선언, 조건 및 다른 문장을 포함하지 않는 경우입니다.
- `#if` 같은 전처리 지시문은 감싼 코드와 같은 논리 계층에 놓고 추가 들여쓰기를 하지 않습니다.

## 타입 배치

권장 순서:

1. 특성은 대상에, 기반 타입·인터페이스 목록은 타입 선언에 인접;
2. 접근 수정자가 있는 멤버는 `public` → `protected internal` → `protected` → `internal` → `private protected` → `private` 순서이며 가능하면 수준마다 연속 영역 하나;
3. 각 영역에서 `override`와 인터페이스 구현 먼저. 명시적 인터페이스 구현에는 접근 수정자를 쓸 수 없으며 인터페이스 상속 순서로 해당 구현 구역 앞에 배치;
4. 내부 타입은 `enum` → `struct`/`record struct` → 기타 타입 → `class`/`record`;
5. 자체 생성자, 메서드, 속성 및 이벤트;
6. 필드 마지막. 메서드, 속성 또는 내부 타입 사이에 섞지 않음.

- 명시적 인터페이스 구현은 인터페이스별로 나누며 멤버가 여럿이거나 구역이 불명확하면 짝을 이루는 `//~ Begin <Name> Interface`와 `//~ End <Name> Interface`를 사용합니다.
- 인터페이스, 기반 타입, 자체 구현 구역을 교차 배치하지 않습니다.
- 긴 구현 파일에서 선언 순서를 추적 가능하게 유지합니다. 지역 보조 타입과 비공개 정적 보조 메서드는 가장 읽기 좋은 위치에 둘 수 있습니다.
- `file`은 파일 지역 최상위 타입에만 적용하고 멤버 접근 순서에 포함하지 않습니다. 제네릭 클래스와 구조체는 각 타입 범주에 두며 기타 타입으로 묶지 않습니다.

## 주석과 이름

- 호출자가 의미, 소유권, 스레드, 예외 또는 프로토콜 제약을 알아야 하는 타입, 메서드, 속성과 필드에만 주석을 답니다.
- 명확하지 않은 공개 API 계약은 XML 문서 주석, 짧은 내부 설명은 `//`를 사용합니다.
- 기존 .NET 이름 규칙을 유지합니다. 타입·멤버는 PascalCase, 매개변수·지역 변수는 camelCase, 비공개 필드는 `_camelCase`입니다.
- 네이티브 ABI, JSON 및 프로토콜 필드의 외부 계약 이름을 유지하며 내부 이름 통일을 위해 호환성을 깨지 않습니다.
