# VeroScript コーディング規約（暫定）

適用範囲：[VeroScript 本プロジェクトの開発・貢献](README.md)。

型配置と論理区分は [CPP.md](CPP.md) を参考にします。本ファイルは現在直接確定できる VeroScript の書き方だけを定義し、言語・formatter 固有の詳細は後で補足できます。

## 書式

- `else`、`else if`、`catch`、`finally`、`do…while` 末尾の `while` は [GENERAL.md](GENERAL.md)
  に従って改行します。ブロックの開始波括弧も独立行で節に揃えます。
- 論理階層ごとに実際の Tab を一つ使い、既定の表示幅を 4 桁とします。[GENERAL.md](GENERAL.md) の字下げ規則に従います。
- 名前空間、型、メソッド、条件、ループ、局所スコープごとに一段字下げします。
- 開始波括弧は単独行、終了波括弧は対応する宣言・制御文に揃えます。
- 本体のある条件とループは波括弧を使います。唯一の例外は直接 `return` だけの一行ガードで、`else` 連鎖、ログ、解放、他の文と組み合わせません。
- すべての `switch` に `default` が必要です。各 `case`/`default` の通常の実行文は波括弧による独立スコープに置きます。現在のメソッドを終了する直接 `return` 一つだけの分岐は、このブロックを省略できます。
- 明示的な `fallthrough;` はラベル直下の最後の文として、その分岐のブロックの後に置きます。ブロック、条件、ループ内に入れてはいけません。これは言語の制約に従う例外です。他の実行文は独立スコープ内に置きます。
- `class`、`struct`、`interface`、`enum` の型宣言はセミコロンで終わります。

## 型配置

次の順に置きます。

1. 型の関係と別名；
2. `public`、`protected`、`private` の順の領域；
3. 各領域で継承メソッドを先に；
4. 内部型は `enum` → `struct` → その他 → `class`；
5. 独自メソッド；
6. メンバー変数。

- 継承・インターフェースメソッドは基底・インターフェースの継承順に区分します。必要に応じて対の `//~ Begin <Name> Interface` / `//~ End <Name> Interface` を使います。
- 同じファイルの複数トップレベル型も、完全型の依存が許す場合は `enum` → `struct` → その他 → `class` の順です。
- VeroScript の前方宣言は現時点で規定しません。言語の構文対応が未確認のため、C++ に規則があるだけの理由で導入せず、確認後に別途追加します。

## 命名とコメント

- 型・インターフェースは PascalCase、関数、フィールド、引数、局所変数は lowerCamelCase を使います。
- コメントは [GENERAL.md](GENERAL.md) に従い、言語機能、制約、所有権、例の目的を説明し、コードの表面を繰り返しません。
- 公開標準ライブラリ・ホストバインディング名は互換性に関わり、改名は別途評価します。

## 長さとインデックス

コンテナーの長さ、線形インデックス、スライスの位置と個数、容量には `int64` を使います。map のキーとタスク ID は宣言した型を保持し、個数の 64 ビット化で無関係な API の型まで広げないでください。ネイティブの `size_t` や狭いバックエンドのインデックスに変換する前に、符号と範囲を検査します。`int` が必要な場合は範囲検査付き変換を使い、確保上限と文書化された結果なしの値を維持してください。契約を変更するときは標準ライブラリの宣言、文書、回帰テストを一緒に更新します。
