# パッケージ化と公開の規約

対象：[VeroScript 本プロジェクトの開発と貢献](README.md)。公式配布集合、候補ビルドと公開前検証を定め、外部プロジェクトのライセンスや配布方法は変更しない。

## 規約と実装状況

共有レジストリと配布スクリプトが分類パスと新形式を実装する。純計画・静的回帰は、成功した実ビルドと配布内容の完全性検査の代わりにはならない。対象上の実行とインストーラーのライフサイクル検証は、失敗や未実施も含めて結果を別途記録する。 新契約のみ受け付け、旧形式の互換読取・変換・二重書込・移行は提供せず、旧出力を削除して再構築する。

製品登録、版解決、純計画、生成器、内容、マニフェスト、検証、取引、削除、CI を同期する。schemaVersion を明記し、新読取器は新契約のみ受け付け旧形式を安全に拒否する。互換分岐は不要。形式版と製品版は独立し、製品バージョンは登録情報に従います。[配布配置](../../../../VeroScriptInstaller/Resources/Docs/Developer/ja-JP/release-layout.md)を参照し、旧 `migrate-layout` は新手順に含めない。

## ディレクトリと責務

正式ルートはソースルート配下の `Release/` で、外側の `Script`、`VeroScript` という名前に依存しない。チェックアウトの移動時は内部相対パスを維持し、コンパイル済みパスに依存するキャッシュを再構築する。候補、ビルドキャッシュ、検証ログは Release 外の専用ステージに置く。

```text
Release/
  release-index.json
  indexes/<target>.json
  Runtime/<target>/<version>/
  CoreSDK/<target>/<version>/
  Interop/<target>/<version>/
  Resources/any/<version>/Resources/
  Modules/
    Execution/{Jit,Vm}/<target>/<version>/
    Network/{Json,Network,Http,WebSocket}/<target>/<version>/
    Network/Backend/{Boost,Curl}/<target>/<version>/
    Multimedia/{Platform,Graphics,Audio,Image,Font,Gui}/<target>/<version>/
    Multimedia/Backend/{Sdl3,Stb,FontBackend,RmlUi}/<target>/<version>/
  Extensions/
    Language/{Cpp,CSharp,Python}/<target>/<version>/
    Editor/VSCode/{VSCode,GuiVSCode}/<target>/<version>/
    Editor/JetBrains/{JetBrains,GuiJetBrains}/<target>/<version>/
    Platform/Mobile/{Android,iOS}/<target>/<version>/
    Platform/WebAssembly/<target>/<version>/
```

`<business-route>` は登録された分類パスと製品名を含む。`<target>` はビルドホストではなく、ネイティブ／モバイル対象、`any`、`wasm32` のいずれかの配布範囲を表す。`{A,B}` は別々のディレクトリを示す。

製品版ディレクトリには必要な分類だけを作り、マニフェストとチェックサムは版のルートに置く。

| パス | 用途 |
| --- | --- |
| `archives/` | 展開して配置するランタイム配布 |
| `sdks/` | 開発 API、ビルドエクスポート、必要依存関係を含む SDK アーカイブ |
| `packages/` | `.vspkg`、`.vsix`、プラグイン ZIP、`.nupkg`、wheel、sdist、AAR |
| `installers/` | 対応製品のインストーラーと選択されたダウンロード形式 |
| `symbols/` | 所有製品のシンボル配布、`.snupkg` を含む |
| `Resources/` | Resources 専用の展開済み Assets、Docs、Scripts、Examples |
| `release-manifest.json`、`checksums.txt` | 製品、範囲、版の一覧とハッシュ |

拡張子だけでなく用途と役割で分類する。既存のパッケージを機械的に同内容の ZIP へ包み直さない。追加ヘッダーやビルド資源が必要な SDK は一式のアーカイブを保持できる。Unix 形式は実行権限と必要なライブラリリンクを保つ。インストーラーの公開形式は原則一種類とし、独立した利用目的がある場合のみ裸ファイルと圧縮版を併存させる。配布分類はインストール先を自動変更しない。

Runtime、CoreSDK、Interop、Resources はルート直下、Cpp、CSharp、Python、WebAssembly、四種のエディター製品と Android/iOS は Extensions、実行・ネットワーク・マルチメディアモジュールは Modules に属する。パッケージクライアントは Runtime/CoreSDK の一部で、別製品を追加しない。新製品、依存、役割、機能、除外理由を登録し、完全性は対象と配布プロファイルで判定する。全対象に全製品を要求しない。

集合名は `archives`、`sdks`、`packages`、`installers`、`symbols`、`indexes` の複数形に固定する。Modules、Extensions 配下の Execution、Network、Multimedia、Language、Editor、Platform、Backend はソースの綴りを維持し、業務 ID とパッケージ名は変更しない。

## 対象範囲と共有成果物

ネイティブ配布は OS と CPU で分ける。例は `win-x64`、`win-arm64`、`linux-x64`、`linux-arm64`、`macos-x64`、`macos-arm64`。他の登録済み CPU も対応プロファイルを明示し、登録だけで完全配布可能とはしない。`android` は複数 ABI、`ios` は実機とシミュレーターを含み iPadOS も同じ SDK を使う。WebAssembly SDK は `wasm32`、そのネイティブインストーラーはホスト対象に置く。

`any` は単一ネイティブ対象に分割しない共有配布の場所で、プラットフォーム中立ファイルや複数対象を含む同一パッケージに使用できる。ただし `supportedTargets`、ABI、TFM、実行依存、制約を正確に宣言する。全プラットフォーム対応を意味せず、Android AAR と iOS XCFramework は各プラットフォームの範囲を保つ。

共有配布は製品・版ごとに一つだけ保存し、マニフェスト参照で再利用する。現行四種のエディタープラグイン、中立 Resources、清掃済み Python sdist、同一 Android/iOS C# NuGet は共有位置を使う。JS/WASM SDK は一つの正規成果物を生成し、ネイティブインストーラーを通用版としない。混在製品は `any` とネイティブディレクトリを持てる。Python sdist は `any`、wheel は実際のプラットフォーム/ABI に従う。

製品、版、用途、対応範囲、依存、ABI が一致し、最終ハッシュも同じ場合のみ統合する。同名や同拡張子だけでは不十分。明示した生成契約に従い正規バイトを確定してからマニフェスト、署名、ハッシュを生成する。自有テキストは UTF-8/LF と必要な BOM・batch 例外を保つ。バイナリ、署名、第三者原文、バイト依存の入力を機械変換しない。正式配布の共有参照はディレクトリ間のシンボリック/ハードリンクに依存しない。

独立インストーラー、wheel、オフライン SDK は宣言した必須実行依存を同梱する。単独利用をディスク重複排除より優先し、必要なライブラリを隣の Release ディレクトリへ移して利用者が持つと仮定しない。

`supportedTargets` は実ペイロードの対象、`consumerTargets` は参照可能な配布対象を示す。wasm32 SDK はネイティブホスト索引から参照できる。共有・原生の合成では実際のエコシステム版を一致させる。

## 独立した版と依存

製品と対象は独立した版を持てる。`ReleaseVersions.json` は既定値で、集合全体の製品版ではない。共有配布も版を明示し、他対象が参照する内容を対象更新で黙って上書きしない。索引は版とマニフェストハッシュを固定し、暗黙の最新版を解決しない。NuGet、wheel、sdist、プラグイン、バイナリの実版を保持し、改名や架空タグを禁止する。

ネイティブ版、製品版、公開 ABI、ビルド識別、形式版は別記する。Cpp/Core、GUI 追加/基本プラグイン、モジュール依存を実版、ABI、識別、ライブラリハッシュで検証する。外部公開済みの同一識別を別内容に黙って置換しない。未公開のローカル候補の再構築はハッシュを更新し、影響する検証を無効にする。製品の版方針も明示する。

同一パッケージ識別は一つの内容に対応する。同 ID/版の異なる NuGet や sdist を複数の対象フォルダーに置いて名前で区別しない。差は TFM、RID、ABI、プラットフォームタグで表し、統合不能なら既存 ID/版契約を破らず別の配布識別を明示する。

共有 `any`／`wasm32` マニフェストを管理コレクションへ公開した後は、その製品・範囲・版の識別を変更しない。任意のシンボルや対応範囲も含め、共有在庫をすべて揃えてから確定し、変更時は製品版を上げる。未公開のローカル出力を明示的に削除したクリーン再構築に限り設定済みの版を維持できる。ローカルファイルを削除しても、利用者へ配布済みの識別を異なる内容に変更してはならない。

`any`／`wasm32` のマニフェストに配布元ホストの原生版を記録しない。C# の原生版の文脈は各利用対象索引の業務項目に保存し、共有パッケージの識別は内容と契約から決定する。

## 索引、マニフェスト、参照

`release-index.json` は形式版 **1** と製品識別子 `VeroScript Release Set`、`indexes/<target>.json` は版 **5**、業務マニフェストは版 **3** を使う。一時候補マニフェストは版 **2** と識別子 `VeroScript Release Candidate` を使う。`checksums.txt` は業務・範囲・版ごとに生成する。索引の `manifests[]` は範囲、実際の版、相対パス、SHA-256 を記録し、分類と役割は共有登録表から取得する。

ルート `release-index.json` は集合入口であり、配置/形式版、世代、`indexes/<target>.json` の相対パスと SHA-256 を記録する。共通の製品版を捏造しない。対象索引は各選択を独立管理し、共有索引は共有配布を管理する。

一対象の一製品が複数マニフェストを参照できる。例は Python の対象 wheel と `any` sdist。各参照に `target`、`version`、相対マニフェストパス、SHA-256 を含め、一製品一同対象マニフェストという旧前提を廃止する。製品や対象ごとに独立した版を選べるが、一つの対象索引で同一製品を構成する共有部品とネイティブ部品はエコシステム／製品版を一致させ、互換性と完全性を共同検証する。

製品マニフェストは製品、範囲、実版、ビルド/ソース識別、`supportedTargets`、依存、役割、全ファイル一覧を持つ。各ファイルは分類後相対パス、サイズ、SHA-256 を持つ。ネイティブは OS、CPU、ABI、最低 OS/API、ツール、スライスを、パッケージは Python ABI、TFM 等を補う。同一覧から `checksums.txt` を生成し、選択、パス、メタデータ、バイナリ識別を一致させる。

ファイルパスは製品版ルートから、索引のマニフェストパスは Release から解決する。走査、絶対パス、リンク脱出、大文字小文字/予約名の別名、重複、未知ファイル、参照循環を拒否する。範囲間参照は対応対象を宣言した管理下マニフェストに限定し、依存/参照閉包全体を検証する。ディレクトリ名から内容を推測しない。

一覧は実成果物と展開資源を対象とし、自身のマニフェストと `checksums.txt` を除いて自己参照ハッシュを避ける。上位索引がマニフェスト、ルートが索引のハッシュを固定する。形式ごとにファイル種別、実行権限、安全な相対ライブラリリンクを記録/検査し、通常ファイルのバイト比較だけで実行可能性を失わない。ハッシュは公開者識別や実際の署名方針の代わりにならない。

索引は選択部品の公開と全プラットフォームの完了を区別し、必要製品集合、不足、partial、未検証を記録する。部品の成功で全体を認証しない。正式成果物のない対象に成功索引を捏造せず、ビルド/検証不足は候補レポートに保つ。

## 機能内容とソース配布

Runtime、SDK、Extensions、Modules、インストーラーは機能、実行資源、メタデータ、法的表示のみを含み、README、手引き、チュートリアル、例、テスト、ベンチマーク、履歴を付けない。Resources が統合 User 文書と関連資源を提供し、Standards は開発者向け All のみで User や機能パッケージに含めない。ライセンス、NOTICE、必要な翻訳、アイコン、構文、スニペット、実行データを保つ。開発用 Node.js/Sharp を Runtime/SDK の依存にしない。

VS Code の VSIX ルートにある `extension/readme.md` は拡張の詳細ページ用メタデータです。この特定の表示ファイルは、モジュールの README 正本とテキストが一致し、パッケージ内リソースまたはオンラインガイドにリンクする場合に含められます。その他の README、マニュアル、Developer/Tutorials ツリーは機能パッケージの対象外です。

Jit と将来のものも含め全 Modules は独立製品インストーラーを持たず、シンボルは所有製品の独立配布とする。インストーラーは文書/例の選択を設けず、固定ページのウィザードと所有権規則を保つ。関連付け、アイコン、PATH の解除/アンインストールは当該インストール所有設定のみを清掃する。

sdist はビルド可能ソースの明示例外として、独立展開後のビルドに必要な最小ソース、ヘッダー、スクリプト、メタデータ、法的表示を含め、無関係な説明/例を除く。`.cxx`、`.gradle`、`.externalNativeBuild`、CMake キャッシュ、オブジェクト、ビルド済み出力、ローカルパスを除外し検査する。`.gitignore` や偶然きれいなホストだけに頼らず、実際のアーカイブ一覧を調べ、必要に応じ隔離 sdist から利用者を再ビルドする。

モジュールのインストール、パッケージの有効化、実行バックエンド／サービス提供者の選択は別操作である。ホスト設定は省略／auto／none／明示指定の共通規則に従い、auto はインストール済みで有効な互換候補を選択できる。公開・導入はホストのバックエンド設定や無効化の選択を保持し、任意の Jit／提供者を Runtime/CoreSDK の基本内容に黙って追加しない。

アイコンは正式 Assets と自動一覧を正本とし、新ファイルを版管理と CI 入力へ加え、過去の個数に固定しない。SVG/PNG/ICO/ICNS 等の原始/バイナリ資源を個々のソースと照合し、インストール参照は安定した製品内パスへ解決する。埋込アイコン変更時は利用プログラム/インストーラーを再ビルドし、外部 ICO 交換を EXE 再構築の代わりにしない。関連付け、更新、削除は引き続き所有権契約に従う。

ソース検証では、再利用ビルドを含め Windows CLI、Runtime、launcher、LSP、DAP とインストーラー EXE の埋め込みアイコンをフレームごとに照合します。VS Code が宣言する製品 PNG も正式なリソースと直接照合します。

## Android、iOS とモジュール SDK

Android 主 SDK は Core/Interop、共通 Mobile 層、JNI、AAR、標準ライブラリ、必須資源とライセンスを統合する。iOS 主 SDK は静的適応と XCFramework を統合する。共通 Mobile 層は利用者が追加インストールする別製品ではない。主 SDK が全オプションモジュールを含むとはしない。

`Modules/<category-route>/<business>/<android|ios>/<version>/sdks/` は任意のネイティブ CMake 開発配布で、別の主 SDK やデスクトップ `.vspkg` ではない。必要なヘッダー、CMake 出力、宣言済み依存閉包を保ち、同梱/外部依存を区別し、競合や二重リンクを避ける。主 AAR の存在を理由に独立提供が必要な C++ API やモジュール開発機能を削除しない。

完全なモバイル配布はプラットフォーム適応、CoreSDK、Cpp、Interop、Vm、CSharp、Python と選択モジュールの契約を満たす。通常アプリは主 SDK と必要モジュールを使い、全開発キットをダウンロードする必要はない。Android は現在 arm64-v8a/x86_64、iOS は device-arm64、simulator-arm64、simulator-x86_64 を含む。実バイナリと利用者リンクを各スライスで検証し、同 CPU を同 OS/実機・シミュレーター ABI と扱わない。iOS で利用不可のネイティブ JIT は明示除外し、改名で対応を装わない。

C# は実 TFM、ネイティブライブラリ、資源で、Python は宣言済み CPython 行列とスライスで選択する。.NET、Xcode、NDK、対象依存を適合させ、SDK コンパイル版と最低実行 OS は分けて記録する。

## クロスビルドと検証

ソース/設定事前検査、実ビルド、候補組立、静的検証、対象実行、公開、最終検査を区別する。クロスコンパイル可能な対象は実際の対象成果物を生成し、ローカル実行環境の不足をコンパイル不能と混同しない。ビルドと完全性検証が成功したパッケージは、実行検証が未実施または失敗でも Release に含められる。ただし状態を明記し、ビルド成功を実行検証成功と扱わない。

ビルドホストと対象の識別を別記する。対象コンパイラー、sysroot、ヘッダー、完全な依存を使い、実行する生成器はホスト版を使う。ネイティブ、C# AOT、wheel、インストーラー、第三者ライブラリを個別に確認し、RuntimeIdentifier、名前、タグの変更だけで済ませない。デスクトップ ARM64 はモバイル ARM64 の検証を継承しない。

`passed`、`failed`、`not-run`、`not-applicable` を理由、環境、ツール、設定、証拠ハッシュとともに記録する。クロスコンパイル/リンク、エミュレーター、実機、画面、インストール生命周期、署名/公証、C# AOT/トリミング、Python を個別管理する。実ビルド、および内容、アーキテクチャ、ソース、依存、一覧、SHA-256 の検証は配布前に必須。実行/実機検証の不足はビルド済み成果物の配布を妨げない。未実施、失敗、未署名、ツール不足を成功と記録しない。業務の `qualification` はバージョン 1 で、`manifests[]` の正確なパスとハッシュに結び付け、内容変更で失効する。`complete` は必須成果物の在庫完全性のみを示し、`qualificationStatus` が検証を集約する。在庫が完全で全必須検査が成功した場合だけ `qualified` が true となる。証拠不足は `not-recorded` とする。

macOS は正式 ICNS、Info.plist、実行ファイルを備えた標準 `.app` を `.dmg` で配布する。Linux は実行権限を保つ `.tar.gz`、Windows は `.exe` を使う。SDK の圧縮形式は別に決める。署名を完了してから映像を作成・検証し、ad-hoc を Developer ID や公証と同一視しない。他 OS で DMG を監査する場合はビルドツール 7-Zip（`VEROSCRIPT_7ZIP` または PATH）を使い、製品の実行依存は増やさない。

デスクトップのクロス組立は `Resources/Tools/Packaging/package-veroscript-desktop-cross.py` を使う。対象コンパイラーが正式ヘッダーの式を評価して ABI を生成し、ホスト ABI を流用しない。実行できない対象では、ソースが全ファイル一致し、二つ以上のネイティブ環境の宣言カタログが一致する場合のみ中立カタログを再利用する。32 ビット対象は自身のカタログを生成する。対象ツール/エミュレーターは `--target-tool` で指定し、カタログ取得を完全な実行検証と扱わない。ホストのインストーラーツールは他対象の組立・ハッシュ検証・圧縮が可能だが、実際のインストールは OS とアーキテクチャ一致が必要。

署名、公証、バイトを変える後処理を終えてから最終配布ハッシュと検証証拠を確定し、内部内容一覧も別途検証する。署名前ハッシュで署名後ファイルを認証しない。公開後に最終ディレクトリ、アーカイブ、参照先、埋込内容を再検査し、バイト変更は該当証拠を無効にする。

## 公開、中止、削除

公開と削除は集合ロックを共有する。候補、対応、閉包、由来を先に検証し、管理ステージにファイル/マニフェスト/索引を準備して製品、対象索引、最後にルート入口を復旧可能な取引で確定する。失敗時は変更内容と参照を復元する。読者はロックまたは世代/ハッシュ再確認を行い、更新中の不一致は再試行する。集合全体の一回の原子的交換とは主張しない。

中止は当該タスクのビルド子プロセスと転送だけを止め、未完候補を公開せず正式成果物を上書きしない。必要な診断を保ち、一時設定を戻す。再開時はソース、設定、ツール、候補ハッシュを調べ、古い検証を再利用しない。

全索引とマニフェスト依存の参照閉包で削除を判断する。原則は未参照旧版を削除し、他対象、Cpp、GUI 追加プラグインが使う版を保つ。共有包は最後の参照消滅後のみ削除可。未知/未管理ファイルやパス検証失敗で停止し、年齢や名前を所有根拠にしない。検証した専用一時ディレクトリだけを削除し、ソース、利用者ファイル、外部依存を削除しない。

旧形式削除前に所有権、ソース保護、使用中プロセス、再利用ツールを調べる。旧 Release と不要候補/キャッシュを削除し、必要な診断のみ保ち旧包の復旧コピーは残さず、旧索引の依存で旧集合を延命しない。クリーンなステージから新規則で再構築・検証・公開し、製品バージョンは登録情報に従います。新形式内で参照される有効版は閉包で保護するが、旧規約互換ではない。

## 実装の条件

実生成器と共通の純計画、共有参照/版、分類/メタデータ検証、範囲間依存・ロック・復旧・参照削除テスト、汚染ソース/旧形式拒否、対象能力/証拠、クリーン再構築と失敗復旧を実装する。完了前は公開せず旧計画で新配置を認証しない。

規約更新だけではコンパイル、インストーラー生成、配布パッケージ化を始めない。六言語、ナビゲーション、現行実装説明を同期し、Release に公開しない一時文書検査を実行する。

```text
python Resources/Tools/Packaging/veroscript_docs.py check
python Resources/Tools/Packaging/veroscript_docs.py check-collection
```
