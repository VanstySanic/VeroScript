# Python コーディング規約（暫定）

適用範囲：[VeroScript 本プロジェクトの開発・貢献](README.md)。

Python は [GENERAL.md](GENERAL.md) の構造、コメント、必要最小限の説明に従います。波括弧やアクセス修飾子がないため、モジュールとクラスの宣言順で対応する階層を表します。

## 書式

- 論理階層ごとに実際の Tab を一つ使い、既定の表示幅を 4 桁とします。[GENERAL.md](GENERAL.md) の字下げ規則に従います。
- [Python は Tab を 8 桁境界で解釈](https://docs.python.org/3/reference/lexical_analysis.html#indentation)し、エディターの表示幅には依存しません。ブロックの階層は Tab で統一し、移行時は表示上の桁数で機械的に置換せず、元のブロック境界を保持します。
- `class`、`def`、条件、ループ、`try`、コンテキストマネージャーの本体を正しく字下げし、一行の複合文に論理を圧縮しません。
- `if`、`for`、`while`、`try` などの本体は独立した字下げブロックにします。C++ の一行 `return` ガード例外は適用しません。
- `match` で switch 相当の分岐を行う場合は `case _` を既定分岐として置き、未知・未対応入力を明確に処理します。
- 条件付き import やバージョン分岐は制御対象の論理領域に置き、完全な意味上の区画を分割しません。

## モジュールと型の配置

モジュールの推奨順：

1. モジュール docstring と `__future__` import；
2. 標準ライブラリ、第三者、プロジェクトの import；
3. 定数、型別名、プロトコル；
4. `Enum`；
5. `dataclass` などのデータ型；
6. その他の補助型；
7. クラス；
8. モジュール関数とコマンドライン入口。

クラスの推奨順：

1. クラス定数とクラスレベル型；
2. 継承・プロトコルが要求するメソッド；
3. 内部 `Enum`、データ型、その他の型、クラス；
4. `__init__`、代替コンストラクター、公開メソッド、プロパティ；
5. 保護・非公開補助メソッド；
6. クラス変数。インスタンス状態は `__init__` に集中し、メソッド間で散発的に追加しない。

- 複数の基底・プロトコル実装は継承リスト順に区分します。必要に応じて対の `#~ Begin <Name> Interface` / `#~ End <Name> Interface`、または Python に適した短い説明を使います。
- モジュール・関数・変数は `snake_case`、クラスは `PascalCase`、定数は `UPPER_SNAKE_CASE`、内部実装は先頭アンダースコアで示します。

## コメント

- モジュール、公開クラス、公開関数の自明でない契約は docstring に記載します。
- 局所的な理由は `#` で説明し、名前で分かる変数・関数を重複説明しません。
- 型注釈は公開入力・出力と複雑なデータ構造を表し、厳格さは後で別途定義できます。
