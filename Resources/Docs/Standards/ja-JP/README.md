# VeroScript プロジェクトの開発・貢献規約

本規約は公開で閲覧でき、**VeroScript 本プロジェクトの開発と貢献にのみ適用します**。言語仕様、SDK の利用要件、MIT ライセンスの追加条件ではありません。他のプロジェクトで VeroScript を利用、統合、変更する際に、本規約のコーディングスタイルを採用したり、自分のコードの著作権者を本プロジェクトの権利者としたりする必要はありません。既存の著作権表示とライセンス表示は、[MIT ライセンス](../../../../LICENSE)および適用される第三者ライセンスに従って保持します。

Standards はソースリポジトリに保持し、完全版 `All` 文書に開発者向け資料として含めます。`User` 文書、Resources 内の利用者向け文書、Runtime/SDK/拡張の配布物、インストーラーには Standards を含めません。

この文書群は、本プロジェクトの**手動で保守するコーディング規約と公開規約**です。コードの規則は、リポジトリ所有の手動保守ソースに適用し、VeroScript のコア、ツール、言語拡張、その他のネイティブ・アプリケーションモジュールを含みます。[PACKAGING.md](PACKAGING.md) は公式配布集合とその公開前検証を定めます。

唯一の保守元は `Resources/Docs/Standards/` です。規則を定める正本は `zh-CN`、他言語は同等の翻訳です。翻訳で規則を追加・変更してはいけません。規則は保守者の明示的な決定に従い、既存コード、外部の慣習、ツールの既定値から推測しません。旧規則は比較用にバージョン管理で保持し、新規または実質的に変更するコードには現行の承認済み規約だけを適用します。

規約は整備中です。確認済みの規則は守り、未記載の事項を独自に必須条件へ拡張しません。新しい規則は、その言語や主題に最も近いファイルに追加します。

## 規則の強さ

- **必須**：新規コードと実質的に変更するコードは満たす必要があります。
- **推奨**：通常採用します。言語制約、互換性、読みやすさのために外れる場合は、局所的な一貫性を保ち理由を説明します。
- **必要に応じて**：構造の理解、保守性、呼び出し側の理解を改善する場合だけ使用し、機械的で重複した定型を増やしません。
- **暫定**：現在の推奨既定値であり、保守者が補足または置換できます。

## 適用範囲と移行

- コードの規則はリポジトリ所有の手動保守ソースと、そのコメントに適用します。パッケージ化と公開には [PACKAGING.md](PACKAGING.md) を適用します。
- `ThirdParty/`、生成ディレクトリ・ファイル、パーサーテスト用の生の入力フィクスチャは強制移行の対象外です。
- 新規ファイルは対応する規約全体に従います。既存ファイルでは追加部分と関連部分を優先し、機能変更に無関係な大規模整形を混ぜません。
- 有効な言語、ABI、プロトコル、ビルド契約は書式より優先します。競合する場合は契約を維持し、対応する規約に例外を記録します。

## 保守

規則変更は小さく明確にし、規則、範囲、必要な例、例外を記載します。過去の一つのファイルの偶然の書き方を全体の規則へ昇格させません。

- 先に `zh-CN` 正本を変更し、同じ変更で他の五言語を同期します。規則の強さ、範囲、例外、暫定状態を一致させます。
- 各言語の本文をここで保守します。規則変更時に例を確認し、既存コードから新規則を推測しません。
- 規約は `Resources/Docs/Standards/<locale>` で管理します。`zh-CN` が規則を定義し、他の五言語は等価に保ちます。変更後に `python Resources/Tools/Packaging/veroscript_docs.py check` と `check-collection` を実行します。規約原本は開発者向け資料として `All` にのみ含め、`User` や機能配布物には含めません。
- コード、API、プロトコルフィールド、コマンド、2 行の SPDX ヘッダーは翻訳しません。コード例のコメントも英語を維持します。
