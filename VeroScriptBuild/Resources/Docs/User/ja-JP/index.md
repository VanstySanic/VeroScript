# アプリケーションのビルドと配布

`--build-file <ファイル>` で任意の設定ファイル名を指定でき、絶対パスとコマンド開始ディレクトリー基準の相対パスを受け付けます。`--path` がなければ設定ファイルの親がプロジェクトルートになり、指定した場合はそのルートを入力パスの基準にします。既定名は `veroscript-build.json` です。

省略可能な `VeroScriptBuild` は厳密な `veroscript-build.json` を読み取ります。設定内のパスは指定したプロジェクトルート、CLI のパスは起動ディレクトリを基準に解決します。

`--profile <名前>` で `profiles` に宣言されたプロファイルを選択します。既定は `release` です。`--target <名前>` は対象を選択し、繰り返し指定できます。対象を明示しない場合は設定の `defaultTargets` を使用します。

```sh
veroscript build --path /absolute/project --plan --json
veroscript build --path /absolute/project --build-file /absolute/config/release.json --plan --json
```

これらのコマンドはユーザーコードを実行せずに計画を検証します。実行時は `--plan` を外し、ターゲット名または `--target` を指定できます。依存パッケージは事前にインストールしてロックしてください。

library、application、distribution、deployment、bundle、custom、group は、`.vslib`、`.vsapp`、`.vspkg/.zip`、配備済み環境、配布構成、カスタム処理、ターゲット群を扱います。成果物参照は `{ "target": "library", "output": "main" }`、ソースツリー内のファイルには `path` を追加します。

ビルド中のアプリ検証は、ビルドマシンではなく、選択したターゲットのプラットフォームと ABI を使用します。宣言されたコンポーネントがあれば別ターゲット向けに準備できますが、ネイティブコンポーネントの検証と実行は対象環境で別途行う必要があります。

Runtime、依存環境、ランチャーは個別に省略できます。ソースアプリには runtime と compile の両用途が必要です。PE/ELF 単一ファイルは同じ ZIP 内容を使い、それ以外のプラットフォーム包装はカスタムプロバイダーで処理します。所有権レシート、ハッシュ、リースにより外部変更を保護し、ターゲットごとに原子的に公開します。

プロセス／スクリプト処理は明示的な許可が必要です。スクリプトは宣言入力の読み取り、ステージ出力、ログ用の build 関数と VM 制限を使います。ネイティブ処理は OS サンドボックスではありません。鍵ファイルを配布物に含めないでください。

ソースアプリは実際の梱包内容で事前検証し、マクロと設定を保存します。開発機の検索パスを埋め込まず、files/modules と明示的な環境を使用します。エディターの上書きは生成ソースへ変換してください。`Resources/Examples/generated` に生成器の例があります。ディレクトリーと単一実行ファイルは内容署名を使用します。

署名済みアプリを再構成する場合、新しい内容の署名ポリシーを明示してください。

## ステップ、出力とキャッシュ

`--allow-process` と `--allow-script` は実行時の該当ステップを許可します。`--plan` はプロセッサー、カスタム処理、インストールフック、子プロセスを実行しません。プロセスにはシェルを介さず実行ファイルと引数配列を渡します。スクリプトは `build_read_text(input, relative)`、`build_write_text(output, relative, text)`、`build_message(text)` を使います。インポートはスクリプトのディレクトリー、宣言済み入力、明示的な標準ライブラリールートに制限されます。標準のファイル、環境、コンソール、タスク、アドレス、非決定性サービスは無効で、命令数、時間、深さ、メモリー、数値の制限が適用されます。ネイティブプロバイダー／プロセスは信頼する機能であり、OS サンドボックスではありません。

`Resources/Examples/hello` は書き込み可能な場所へコピーします。出力は `dist/<profile>/<target-identity>/<target>/` にあり、移植可能な識別は `portable` です。他者のファイルや変更済み出力は置換しません。同一ボリューム上でターゲットごとにアトミック公開し、後続の失敗でも独立した公開済みターゲットは戻しません。成果物の利用中は返されたリースを保持します。キャッシュは設定、凍結入力、上流内容、プロバイダー識別、出力ハッシュに依存します。カスタムステップには決定性とツールチェーン識別が必要です。動的プロセッサーや信頼に依存するコンパイルは保守的に再実行します。入力変更後は再計画してください。

埋め込みホストで `script` ステップを実行する場合は、`FServices::Compile.ScriptCompileExtensions.VmBackendFactory` または `VmBackendPath` で VM を明示的に指定します。両者は排他的で、未指定なら `script-vm` を返します。デスクトップの `veroscript build` は製品に組み込まれた VM を使い、権限、命令数、期限、キャンセル、メモリーの制限を維持します。VM のパスと内容が変わるとキャッシュは無効になります。カスタムファクトリーでスクリプトステップのキャッシュを再利用するには、安定した `FServices::Identity` が必要です。

## コンポーネントと保護

ソースには `["runtime", "compile"]`、コンパイル済みアプリには通常 `["runtime"]` の用途が必要です。`bundle.runtime` は検証済み `veroscript-runtime.json` の記載ファイルだけをコピーし、SDK 全体はコピーしません。ランチャーは明示的な互換テンプレートを使い、PATH 検索やコンパイラー呼び出しを行いません。テンプレートは計画時に凍結し、変更は計画／キャッシュを無効化します。PE/ELF はネイティブ部品を検証済みキャッシュに配置し、Mach-O などの形式はカスタムプロバイダーで扱います。ネイティブ依存が異なる場合はプラットフォーム／ABI 別の出力が必要です。

成果物参照は宣言済み入力フィールドのみで解釈し、プロバイダーの `options` は不透明な JSON です。入力を再報告しても凍結ダイジェストを置換しません。ホストの import/stdlib ルートはプロジェクト基準で、ターゲット側のルートより先に検索します。保護方針は変換前に既存リソース署名を検証します。再暗号化では既存エンベロープを一度復号し、署名対象の変更には新方針が必要です。新署名は既存署名を置換し、未変更コピーは署名を保持します。失敗時は公開しません。`--crypto-library <absolute-library> --keyring <absolute-file>` を使い、鍵ファイルは配布物に含めません。レジストリーの `publish` はインストール用配布物だけを受け付けます。`Resources/Schemas/veroscript-build.schema.json` と Application ガイドを参照してください。

Windows Runtime の一覧には、配置済みの MSVC 再頒布可能ライブラリとライセンス通知が含まれます。Runtime を同梱するディレクトリ／ZIP アプリでは、これらをランチャーの隣にも配置します。単一ファイルのランチャーにもネイティブローダーの前提条件が適用されます。動的 CRT ビルドでは対象システムに対応する VC++ Redistributable が必要です。この前提条件をなくす場合は、関連するネイティブコンポーネントを一貫した静的 CRT 設定でソースからビルドしてください。
