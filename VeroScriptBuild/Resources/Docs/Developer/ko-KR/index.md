# Build 서비스 유지 관리

## 계획과 실행

`FBuilder::Plan`은 프로세서, 팩터리, 하위 프로세스를 실행하지 않고 그래프, 소스/아티팩트 식별자, 공급자, 실행기 템플릿을 고정합니다. `FBuildRequest` 경로는 절대 경로이며 설정 경로는 선택한 프로젝트 루트에서 해석하고 프로세스 디렉터리는 바꾸지 않습니다. `FServices`는 호스트 카탈로그, 콜백, 명시적 도구 체인/환경 식별자를 유지합니다. 공급자 `Plan`에는 실행 부작용이 없어야 합니다.

`FBuilder::Execute`는 고정 입력을 재검증하며 변경 시 새 계획이 필요합니다. 추가 입력은 기존 다이제스트를 바꾸지 않고 `FStepContext::TrackInput`으로 보고합니다. 아티팩트 참조는 선언된 입력 필드에서만 해석하며 공급자 `options`는 불투명 JSON으로 유지합니다. 캐시 식별자는 설정, 상위 콘텐츠, 공급자 식별자, 출력 해시를 포함합니다. 사용자 지정 캐시는 명시적 결정성과 도구 체인 식별자가 필요합니다. 동적 프로세서 및 암호/신뢰에 민감한 컴파일은 보수적으로 다시 실행합니다.

## 게시와 대상 정책

각 대상을 같은 볼륨에서 소유 기록과 함께 원자적으로 게시합니다. 외부 또는 수정된 출력을 덮어쓰지 마세요. 이후 대상의 실패가 독립적으로 게시된 대상을 되돌리지는 않습니다. 콘텐츠 사용 중 아티팩트 소유자와 배포 임대를 유지합니다. `Deploy`와 `LeaseDeployment`는 설치된 고정 환경을 소비하며 설치로 대체하지 않습니다.

앱 콘텐츠는 빌드 호스트가 아닌 선택 대상의 플랫폼/ABI로 검증합니다. 실제 네이티브 실행은 대상 환경 검증이 별도로 필요합니다. 소스 앱은 이식 가능한 기본값 및 runtime+compile 용도를 유지하고 개발 전용 검색 경로는 거부합니다. 런타임과 부트스트랩 템플릿은 명시적으로 검증된 입력이며 템플릿 변경은 계획/캐시를 무효화합니다. 네이티브 래퍼와 플랫폼 서명은 콘텐츠 조립과 분리합니다.

프로세스에는 셸 없이 실행 파일과 인수 배열을 전달합니다. 제한 스크립트는 선언한 입출력 도우미와 한도를 사용하며 신뢰하는 네이티브 공급자/프로세스는 OS 샌드박스가 아닙니다. 리소스 변환 전에 기존 서명을 검사합니다. 재암호화는 기존 봉투를 한 번 복호화하며 서명 콘텐츠 변경에는 새 정책이 필요합니다. 변경 없는 복사는 서명을 유지합니다. 검증 실패 시 게시하지 말고 비밀 키를 설정이나 결과에 직렬화하지 마세요.

## 통합과 검증

`Public/VeroScriptBuild.h`, 계획/실행, `Resources/Schemas/veroscript-build.schema.json`, CLI 및 Application/패키지 어댑터를 일치시키세요. 루트 빌드는 `VeroScriptBuildTests`를 활성화하며 `Resources/Examples/hello`와 `Resources/Examples/generated`는 각 출력과 생성기를 다룹니다. 오래된 계획, 캐시 무효화, 소유 임대, 대상 선택, 서명 실패, 원자적 게시를 확인하세요. CLI 절차와 예제는 사용자 가이드에 두고 플랫폼 실행과 서명은 별도 검증을 기록하세요.
