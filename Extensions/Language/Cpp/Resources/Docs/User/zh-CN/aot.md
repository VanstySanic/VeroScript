# C++ AOT

AOT 后端把 VeroScript 转换为用于本机构建的 C++17 源代码，适合运行时不需要动态加载脚本的部署场景。

## 命令行生成

```powershell
veroscript aot script.vs -o generated.cpp
```

输出是 C++ 翻译单元，不是已经链接的可执行文件。生成结果包含所需的兼容支持代码；目标项目使用兼容的 C++17 工具链和所需系统库编译、链接。使用宿主绑定时，还需提供对应宿主实现。

## 编程 API

`VeroScriptCppAot` 提供 `EmitCppFromSource`、`EmitCppFromFile`、从已编译 `FProgram` 生成的 `EmitCppFromProgram`、生成 `FCppAotSourceBundle` 的 `EmitCppSourceBundleFromProgram`，以及从生成源码构建 bundle 的 `BuildCppSourceBundle`。`FCppCodegenBackend` 的名称为 `cpp`，扩展名为 `.cpp`。文件写入是事务性的，源路径和输出路径不能相同。

bundle 名称允许 ASCII 字母、数字、`_` 和 `-`。为保证生成文件可跨平台使用，所有平台均不区分大小写地拒绝 Windows 设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`）；`CON_model`、`COM10` 等名称仍可使用。

环境不提供绑定目录时，仍可通过 `FCodegenOptions::Bindings` 显式提供宿主绑定。准备和校验使用同一目录；生成的自由函数声明需要由目标项目提供相应实现。需要运行时原生包契约的程序仍会被独立 AOT 明确拒绝。

## 源码 bundle 与边界

`FCppAotSourceBundle` 包含 `Files` 和 `ManifestJson`。入口 `.cpp` 会把运行时和程序的 `.generated.inl` 片段重建为一个翻译单元；manifest 声明最低 C++ 标准和线程库要求。不要把这些片段作为独立翻译单元链接。

脚本顶层全局变量和类静态字段仍按原生工作线程隔离。AOT 会在访问器后生成使用函数局部
`thread_local` 状态的全局存储。某个工作线程第一次访问时，会按脚本声明顺序初始化全局变量；
生成的入口点会在调用 `main` 前建立这份状态。需要在线程间显式共享数据时，应使用通道或同步的宿主状态。

成员函数中的 lambda 使用接收者时，生成的 C++ 会保持语言语义：类接收者会作为共享
对象保留，并能观察后续的字段修改；结构体接收者则按值捕获为快照。嵌套 lambda 会
继续保留已经捕获的接收者。无捕获 lambda 不能使用 `this`；析构函数中的 lambda
如果捕获类接收者会被拒绝，因为接收者已经进入析构过程。

如果分析能够证明类局部变量不会逃逸其词法作用域，生成器可能为它使用自动存储。
返回对象、取得对象成员的引用，或会逃逸的闭包则会保持共享所有权。这是生成存储层面的
优化，不会改变类的身份、析构行为或语言规定的生命周期。

当前后端覆盖类、结构体、接口、继承、虚派发、泛型、接口约束、容器、重载、默认和可变参数、引用、lambda、枚举、运算符、`nullptr`、`switch`、`foreach`、标签、跳转以及文档化的字符串、数学、文件和路径库。

标量数值的 `++`、`--` 只求值目标一次，操作期间保留临时所有者，并保持 VM 的数值提升、窄化检查和溢出语义。当前不支持用户类型重载的 `++`、`--`，请对这些类型使用显式更新方法。

在开放泛型类型的构造函数字段初始化列表中，C++ 目标仅支持 `T` 到 `T` 的直接初始化。用零个或多个参数构造无约束字段类型参数的形式会在 AOT 发射阶段被拒绝；请改用具体字段类型，或先构造值再将其作为 `T` 传入。

VM 更适合动态加载、调试和热重载。AOT 生成代码的并发使用宿主线程；宿主绑定、回调生命周期和同步规则必须在目标项目中单独验证。

## 当前语法覆盖范围

C++ AOT 还会发射有符号 8 位 `char` 字面量、同类型局部声明组、`do`/`while`，以及经典
`for` 的初始化器或步进表达式列表。它保留词法遮蔽：每个声明初始化器都先在新绑定可见前的
VeroScript 环境中求值。为保持这一源码规则，生成的 C++ 可以使用卫生临时变量或不同的局部名；
这些实现名称不是 AOT ABI 的一部分，也不表示源码级行为发生改变。

## 运行时内存支持

独立 AOT 当前不支持 `std::memory` 的查询、缓冲区、视图及相关类型。实际调用或使用这些类型时，生成器会报告明确错误；仅导入未使用的 `memory.vs` 或 `core.vs` 仍可生成。

## 引用返回与求值生命周期

<a id="reference-return-lifetime"></a>

返回引用的调用用于值读取时，AOT 会在释放保存的接收者之前复制该值，无参数调用也遵循此规则。引用绑定与值转换、泛型推导保持分离。数值引用采用与普通值相同的提升、窄化检查和溢出检查。通过返回引用的方法赋值时，先求值接收者及参数，再调用方法一次，最后求值右侧。

通过直接访问类字段，或调用直接返回自身非静态、非引用字段的不可覆盖方法，局部别名可保留接收者存储。接收者、基类、字段及已知派生类必须无需脚本清理且不持有不透明资源。重新绑定原接收者不会使该别名失效。普通全局存储和直接结构体接收者的引用仍受支持。

VM 中保留字段存储不会推迟脚本析构。因此，需要托管清理的上述类引用路径会被 AOT 明确拒绝。返回局部保留的别名、无法证明来源的引用，或从保留的 callable 存储中逃逸的引用也需要使用 VM 后端；生成器会报告不支持的情况。

长期索引别名和索引引用返回需要托管存储路径。从临时值接收者取得的长期引用也需要托管所有者。这些情况会被 AOT 明确拒绝，请使用 VM 后端。

隐式结构体字段（包括泛型字段及默认初始化的定长数组元素）按正常规则选择默认构造函数并执行其正文。显式字段初始化器直接构造字段值，不先执行默认构造。

## 编译处理与源码元数据

通过 `FCodegenOptions::CompileProcessing` 配置源码和声明处理器。准备阶段保留跨阶段处理器实例；生成已准备程序时不会再次运行处理器。编译期源码元数据与生成声明可用于 C++ AOT。运行时源码元数据查询（注解、注释、声明／源码节点、注解定义）需要 VM，独立 C++ 生成会明确报错。

## 脚本扩展与源码覆盖

`FCppCodegenBackend` 将 `FCodegenOptions::ScriptCompileExtensions`、`SourceOverlays` 和 `StdlibSearchPaths` 传递给核心加载器。`EmitFromFile` 使用与 Core/Session 相同的入口覆盖解析，支持完全来自内存的入口；空路径会被拒绝。`EmitFromSource` 的显式源码参数作为入口，覆盖用于依赖模块。

编译脚本仅在生成期间执行，输出的业务 C++ 不保留其 VM，也不需要运行时提供仅供编译使用的绑定。业务宿主绑定仍需对应的目标实现。编译绑定、控制器、限制和依赖的配置见[宿主集成](embedding.md)；运行时源码元数据查询仍需 VM。

## 用户 pair 模板

用户自定义的 `pair<T, U>` 使用普通泛型字段和方法。该双参数模板替代软内置类型时，独立 AOT 会明确拒绝映射的 `entries()` 和键值条目遍历；这些操作请使用 VM 后端。映射值本身是用户 pair 类型时，普通值遍历仍受支持。

<a id="cleanup-container-operations"></a>

当结构体 `T` 需要脚本清理（包括字段或基类带来的清理需求）时，独立 C++ AOT 会明确拒绝 `array<T>.remove` / `remove_at` 以及 `map<K,T>` / `ordered_map<K,T>` 的索引赋值。此限制针对上述操作；VM、Mixed 和 JIT 完整支持这些操作。

独立 C++ AOT 支持在成功的构造过程中保留或向外发布该类对象的 `this`。如果构造失败且其他引用仍保留该对象，生成的程序会报告致命错误，避免脚本从 catch 继续执行时子对象尚未清理。如需对此情况进行托管恢复，请使用 VM 或 Core AOT 后端。异常展开期间已释放的临时引用不触发此限制。

<a id="standalone-file-io"></a>

受支持的独立 C++ 文件操作接受 UTF-8 路径并拒绝嵌入 NUL。Windows 长绝对路径（包括完整 UNC）使用原生长路径处理；相对路径仍保持相对，不会自动增加扩展路径前缀。文件系统、权限和操作系统限制仍适用。这与 [基础参考](../../../../../../../VeroScript/Resources/Docs/User/zh-CN/standard-library/foundation.md)中的词法路径查询规则分开。

将容器元素作为引用实参也需要 Core 维护元素身份。独立 C++ 源码 AOT 会明确拒绝这类调用，避免引用随容器改绑，或在后续实参执行后才接受原本不存在的元素。此类调用请使用 Core AOT、VM、Mixed 或 JIT；普通索引读取和赋值继续支持。
