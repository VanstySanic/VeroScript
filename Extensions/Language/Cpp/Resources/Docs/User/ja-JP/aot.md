# C++ AOT

AOT backend は VeroScript をネイティブ ビルド用の C++17 ソースに変換します。
実行時の動的ロードを必要としないデプロイに適しています。

## コマンドライン

```powershell
veroscript aot script.vs -o generated.cpp
```

出力はリンク済みの実行ファイルではなく C++ 翻訳単位です。必要な互換サポート
コードが含まれます。対応する C++17 ツールチェーンと必要なシステムライブラリで
コンパイル、リンクしてください。ホストバインディングには対応するホスト実装も必要です。

## API

`VeroScriptCppAot` は `EmitCppFromSource`、`EmitCppFromFile`、コンパイル済み
`FProgram` 用の `EmitCppFromProgram`、`FCppAotSourceBundle` 用の
`EmitCppSourceBundleFromProgram`、生成ソースから bundle を作る
`BuildCppSourceBundle` を提供します。`FCppCodegenBackend` の名前は `cpp`、
拡張子は `.cpp` です。ファイル出力はトランザクションで、入力と出力のパスは
同一にできません。

bundle 名には ASCII の英字、数字、`_`、`-` を使用できます。生成ファイルの移植性を保つため、Windows のデバイス名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`～`COM9`、`LPT1`～`LPT9`）は全プラットフォームで大文字と小文字を区別せず拒否します。`CON_model` や `COM10` は使用できます。

環境がバインディングカタログを持たない場合も、`FCodegenOptions::Bindings` でホストバインディングを明示できます。準備と検証は同じカタログを使用します。生成された自由関数の宣言に対応する実装はターゲットプロジェクトで提供してください。実行時のネイティブパッケージ契約が必要なプログラムは、引き続きスタンドアロン AOT で拒否されます。

## Bundle と範囲

`FCppAotSourceBundle` は `Files` と `ManifestJson` を持ちます。エントリの
`.cpp` は `.generated.inl` の runtime/program fragment を一つの翻訳単位として
再構成し、manifest は必要な C++ 標準と thread library を宣言します。fragment
を独立した翻訳単位としてリンクしてはいけません。

スクリプトのトップレベル グローバルとクラスの static field は、native worker
ごとの分離を維持します。AOT のグローバル ストレージは関数ローカルな
`thread_local` 状態を持つアクセサーの背後に生成されます。worker が初めてアクセス
したとき、スクリプトの宣言順に初期化され、生成されたエントリ ポイントは `main` の
前にこの状態を確立します。worker 間で値を共有する場合は、channel または同期された
host 状態を明示的に使用してください。

メンバー関数の lambda がレシーバーを使用する場合、生成された C++ は言語の
意味論を保持します。class のレシーバーは共有オブジェクトとして保持され、
後のフィールド変更を観測します。struct のレシーバーは値のスナップショット
としてキャプチャーされます。ネストした lambda もこのレシーバーを引き継ぎます。
キャプチャーなしの lambda は `this` を使用できず、デストラクターから class の
レシーバーをキャプチャーする lambda は、レシーバーが破棄中のため拒否されます。

解析によってクラスのローカル変数が字句スコープの外へエスケープしないと
証明できる場合、エミッターは自動ストレージを使用することがあります。
返されるオブジェクト、メンバーへの参照、またはエスケープするクロージャーでは
共有所有権が維持されます。これは生成ストレージの最適化であり、クラスの同一性、
デストラクターの動作、言語のライフタイム規則は変更しません。

クラス、構造体、interface、継承、virtual dispatch、ジェネリック、制約、
コンテナ、オーバーロード、既定値・可変長引数、参照、lambda、enum、演算子、
`nullptr`、`switch`、`foreach`、label、jump、および文書化された標準ライブラリ
をサポートします。

数値スカラーの `++` と `--` は対象を一度だけ評価し、操作中は一時的な所有者を保持します。VM の型昇格、範囲を検査する縮小変換、オーバーフローの動作を維持します。ユーザー型の `++` と `--` のオーバーロードは未対応です。これらの型には明示的な更新メソッドを使用してください。

open generic 型の constructor field initializer list では、C++ ターゲットが
サポートするのは `T` から `T` への直接初期化だけです。制約のない型パラメーターを
0 個または複数の引数で構築する形式は AOT 生成時に拒否されます。具体的なフィールド型を
使うか、事前に構築した `T` 値を渡してください。

動的ロード、デバッグ、hot reload には VM を使用し、AOT の
callback 寿命と同期は対象プロジェクトで検証してください。

## 現在の構文対応

C++ AOT は signed 8-bit `char` literal、同一型の local declaration group、
`do`/`while`、classic `for` の initializer / step expression list も出力します。
lexical shadowing を保持するため、各 declaration initializer は新しい binding が
見える前に、直前の VeroScript environment で評価されます。この source rule を
保つため generated C++ が hygiene temporary や別の local name を使うことがありますが、
それらの implementation name は AOT ABI の一部でも source-level behavior の変更でもありません。

## ランタイムのメモリ機能

独立 AOT は現在、`std::memory` の照会、バッファー、ビュー、および関連する型に対応していません。実際の呼び出しやこれらの型の使用には明示的な生成エラーを返します。未使用の `memory.vs` または `core.vs` の import は引き続き可能です。

## 参照戻り値と評価時の寿命

<a id="reference-return-lifetime"></a>

参照を返す呼び出しを値として読み取る場合、AOT は保存したレシーバーを解放する前に値をコピーします。引数のない呼び出しも同様です。参照束縛は値変換およびジェネリック型推論と分離されます。数値参照には通常の値と同じ型昇格、縮小変換チェック、オーバーフローチェックを適用します。参照を返すメソッド経由の代入は、レシーバーと引数を評価し、メソッドを一度だけ呼び出してから右辺を評価します。

クラスフィールドへの直接アクセス、または自身の非 static・非参照フィールドを直接返す、解決済みのオーバーライド不能なメソッドの呼び出しでは、ローカルの別名がレシーバーの格納領域を保持できます。レシーバー、基底、フィールド、既知の派生型は、スクリプトのクリーンアップを必要とせず、不透明なリソースを所有しないことが条件です。元のレシーバーを再束縛しても、この別名は有効です。通常のグローバル領域と直接の構造体レシーバーへの参照も引き続き対応します。

VM ではフィールドの格納領域を保持しても、スクリプトのデストラクター実行は延期されません。そのため、管理されたクリーンアップが必要な上記のクラス参照経路は、AOT が明示的に拒否します。ローカルに保持した別名の返却、参照元を証明できない参照、保持した callable の格納領域から外へ渡す参照にも VM バックエンドが必要です。生成器は未対応のケースを診断します。

長期に保持する添字付きの別名と、添字付き参照の返却には管理された格納経路が必要です。一時的な値型レシーバーから取得した参照の長期保持にも管理された所有者が必要です。AOT はこれらを明示的に拒否します。VM バックエンドを使用してください。

暗黙の構造体フィールド、ジェネリックフィールド、およびデフォルト初期化される固定長配列の要素は、通常のデフォルトコンストラクター選択に従い、その本体を実行します。明示的なフィールド初期化子は、先にデフォルト構築することなく値を直接構築します。

## コンパイル処理とソースメタデータ

`FCodegenOptions::CompileProcessing` でソース・宣言プロセッサーを設定します。準備中は各フェーズでインスタンスを保持し、準備済みプログラムの出力では再実行しません。コンパイル時メタデータと生成宣言は C++ AOT に利用できます。実行時ソースメタデータ検索（注釈、コメント、宣言・ソースノード、注釈定義）には VM が必要です。独立 C++ 出力は明示的なエラーを返します。

## スクリプト拡張とソースオーバーレイ

`FCppCodegenBackend` は `FCodegenOptions::ScriptCompileExtensions`、`SourceOverlays`、`StdlibSearchPaths` を Core ローダーに渡します。`EmitFromFile` は Core/Session と同じ入口オーバーレイ解決を使用し、メモリだけに存在する入口も扱います。空のパスは拒否されます。`EmitFromSource` は明示したソース引数を入口とし、依存モジュールにはオーバーレイを使用します。

コンパイルスクリプトは生成時だけ動作します。出力する業務 C++ はその VM を保持せず、実行時のコンパイル専用バインディングも不要です。業務バインディングには対応する対象実装が必要です。コンパイルバインディング、制御、制限、依存関係の設定は[ホスト統合](embedding.md)を参照してください。実行時のソースメタデータ照会には引き続き VM が必要です。

## ユーザー定義 pair テンプレート

ユーザー定義の `pair<T, U>` は通常のジェネリックフィールドとメソッドを使用します。この2引数テンプレートがソフト組み込み型を置き換える場合、単体 AOT はマップの `entries()` とキー・値ペアの反復を明示的に拒否します。これらの操作には VM バックエンドを使用してください。ユーザー定義 pair 型をマップの値として反復することは引き続き可能です。

<a id="cleanup-container-operations"></a>

構造体 `T` がフィールドや基底型を含めてスクリプトによるクリーンアップを必要とする場合、単体 C++ AOT は `array<T>.remove` / `remove_at` と `map<K,T>` / `ordered_map<K,T>` への添字代入を明示的に拒否します。この制限はこれらの操作に適用され、VM、Mixed、JIT では完全にサポートされます。

単体 C++ AOT は、構築が成功するクラスの `this` の保持や外部への公開をサポートします。構築が失敗し、別の参照がまだそのオブジェクトを保持している場合、生成プログラムは致命的エラーを報告します。サブオブジェクトの解放が遅れた状態でスクリプトの catch から実行を再開することはできません。この場合に管理された復旧が必要なら、VM または Core AOT バックエンドを使用してください。スタック巻き戻し中に解放された一時参照は、この制限の対象になりません。

<a id="standalone-file-io"></a>

対応するスタンドアロン C++ ファイル操作は UTF-8 パスを受け入れ、埋込み NUL を拒否します。Windows の長い絶対パス（完全な UNC を含む）はネイティブの長いパス処理を使います。相対パスは相対のままで、拡張パス接頭辞は自動付加されません。ファイルシステム・権限・OS の制限は残ります。字句的なパス問い合わせとは別であり、規則は [基礎リファレンス](../../../../../../../VeroScript/Resources/Docs/User/ja-JP/standard-library/foundation.md)を参照してください。

コンテナ要素を参照引数として渡す場合も、Core による要素の同一性管理が必要です。独立 C++ ソース AOT は、別のコンテナへの誤接続や、後続引数の実行後に初めて存在する要素への接続を防ぐため、この呼び出しを明示的に拒否します。Core AOT、VM、Mixed または JIT を使用してください。通常の添字による読み取りと代入は引き続き利用できます。
