# VS Code 用 VeroScript

一部のエディターでは、ワークスペースが空の場合にターミナルプロセスが制限されます。実行・チェック時にスクリプトの作業ディレクトリが拒否されたら、そのディレクトリをワークスペースとして開いてください。ドメインへのアタッチはターミナルを使用しません。

## はじめに

デスクトップ版 VS Code 1.106.0 以降でローカル VSIX をインストールします。拡張ホストの OS とアーキテクチャに対応する 対応する Runtime を展開し、**VeroScript: Runtime を選択**で三つのプログラム、stdlib、localization を含むルートを選びます。

.vs ファイルを保存して **ファイルを実行**、**ファイルを検査**、**ファイルをデバッグ**を使います。基本的な色付けとスニペットは Runtime なしでも動作します。WSL、SSH、コンテナーではリモートホスト上の Runtime が必要です。

## 設定と実行

信頼済みのワークスペースでは `veroscript.lsp.executablePath` でホストの stdio 言語サーバーを選択できます。パスには共通のパス規則が適用されます。`veroscript.lsp.arguments` は空白や空文字列を含む配列の各要素をそのまま一つの引数として渡します。設定されていないコンパイルオプションにはホストの既定値を使用します。実行ファイルのパスが空の場合は Runtime の言語サーバーが使用されます。パスや引数を変更するとサーバーが再起動します。 カスタムサーバーは拡張機能ホストの環境変数を継承します。初期化の制限時間は 10 秒です。

名前空間の補完を確定すると、入れ子の名前空間を含むメンバー候補を表示します。editor.suggestOnTriggerCharacters が無効なら自動では続けません。VeroScript は editor.wordBasedSuggestions を既定で off にします。[veroscript] の設定で変更できます。組み込みテンプレートは接頭辞と保守的な字句コンテキストで絞り込みます。インポートとエントリーポイントはファイルスコープ、宣言は対応する宣言スコープ、ループは文の開始位置で候補になります。コメント、文字列、未完成の式では表示せず、ユーザースニペットは引き続き VS Code が管理します。ネイティブのフィルターと並べ替えのフィールドを保持し、VS Code も入力された接頭辞を照合します。

ホバーのシグネチャは VeroScript のコードブロックで表示し、オーバーロード、説明、定義位置を分けます。補完の詳細ではシグネチャの重複を避け、既存の説明、リンク、例を保持します。色は VS Code のテーマに従い、シグネチャヘルプのアクティブな引数は引き続きネイティブサーバーが決定します。

veroscript.importPaths、implicitImportPaths、defines、predefinedMacros、bindingCatalogPaths などを設定します。相対パスは所属ワークスペース、なければソースのディレクトリが基準です。共有パスは workspaceFolder と環境変数を使用でき、不足するコンテキストはエラーになります。

各ルート、入れ子のルート、ワークスペース外のファイルには個別の言語コンテキストがあります。問題は **出力を表示**で確認し、Runtime の置換後は言語サーバーを再起動します。

設定済みのインポート・標準ライブラリのディレクトリと明示的な暗黙インポートにある、開いているファイルの未保存内容も参照側のサーバーに同期します。編集機能と診断は所属コンテキストが提供します。対応する Runtime は編集したファイルの診断を更新します。別の参照元ファイルの診断は、そのファイルの編集・保存などによる再解析時に更新されます。

実行・検査コマンドは関連する変更済みソースの保存を提案します。直接実行するタスクは task.saveBeforeRun に従います。引数と終了コードはネイティブプロセスのまま保持します。配列と明示したタスク env は継承値を置き換えます。インポートには VERO_PATH、VERO_STDLIB_PATH ではなくパス設定を使用してください。

## デバッグ

F5 は VM DAP を起動します。stopOnEntry、args、input、cwd、env とコンパイル設定を使用できます。コンソールは式の評価用で、input は初期標準入力です。対話入力やデバッグなしの実行には通常の実行タスクを使います。

program モードの attach は待ち受け中の TCP DAP ホストに program、host、port で接続します。ローカル Runtime は不要で、起動設定、cwd、env は注入しません。ホストに新しいプログラムを読み込み、実行中の VM/PID に接続する機能ではありません。両側で有効なソースパスが必要です。関数・例外・ログ・ヒット回数ブレークポイント、逆実行、inlay hints、CodeLens は未対応です。

コマンドパレットまたは .vs ファイルのメニューから **VeroScript: ホストに接続** を実行できます。選択中または開いている保存済みスクリプトを使い、該当ファイルがなければファイル選択を表示した後、アドレスとポートを尋ねます（既定値 127.0.0.1:4711）。どちらかをキャンセルすると開始しません。関連ソースの保存を確認し、エントリーで停止します。IPv6 は角括弧なしで入力します。F5 の設定生成と launch.json 補完にも attach テンプレートがあります。固定のスクリプト、引数、明示的なコンパイル設定は launch.json に保存してください。

ホストアプリが提供する互換 TCP DAP 接続先を使用します。編集用の `bindingCatalogPaths`、インポート、マクロ、標準ライブラリの版をホストに合わせてください。シンボル情報だけではローカル Runtime でホスト API を実行できません。必要なコンパイル設定は `launch.json` で明示し、設定したソース／インポート範囲外の依存ソースは自分で保存してください。接続先のアドレスはリモート環境を含む拡張ホスト側で解決されます。ネイティブコードは対応するデバッガーで、スクリプトはこのプラグインでデバッグします。

### 実行ドメインへの接続

**VeroScript: 実行ドメインに接続** または launch.json テンプレートを使用します。request は attach、attachMode は domain、host/port と任意の domainId を指定します。空または省略時は接続先のドメインを使用します。ファイルやローカル Runtime は不要です。スクリプトの保存、読み込み、再起動は行わず、program、コンパイル/実行の上書き、debugServer は拒否します。複数のホスト呼び出しで同じ接続を維持できます。 ホストがデバッグセッションを終了した場合、プラグインはスクリプト実行のキャンセルを要求せずに切断を完了します。

接続先が実行ドメインへの接続をサポートしている必要があります。未対応ならプログラムを読み込まず接続に失敗します。初回接続と初期化の期限は 10 秒です。出力のホスト／ドメイン識別情報とソース／バインディングのリビジョンを確認してください。リビジョンは不透明な識別子です。自動比較や LSP 同期はないため、ソースと API 情報を手動で確認します。切断しても実行と取消はホストが管理します。接続喪失時はデバッグを終了し、自動再接続しません。JIT コード実行中の VM は引き継げません。

一時停止、ステップ実行、式の評価、条件付きブレークポイント、変数編集はホストの対応機能に依存します。未対応の要求はエラーになります。通常のブレークポイントは使用できます。停止／切断はデバッグ接続を終了します。スクリプトの取消が必要ならホストアプリで操作してください。


## 任意の JIT モジュール

Runtime と JIT バックエンドは別配布です。veroscript.run.jitBackendPath は通常実行用の互換ライブラリファイルまたはディレクトリを任意で固定します。空欄なら CLI のパス上書きを省略し、モジュール環境の選択を継承します。バックエンド未設定時の既定は auto です。JIT が無効、または利用可能な自動候補がない場合、mixed は VM を使用し、強制 jit は実行前に失敗します。タスクの jitBackendPath で上書きでき、空文字列で継承値を解除します。相対パスは所属ワークスペースまたはソースディレクトリが基準で、cwd に依存せず、実行パス変数を使用できます。検査、LSP、ローカル VM デバッグでは読み込まず、launch/attach は jitBackendPath を拒否します。ライブドメインの選択はホストが管理します。ディレクトリ探索と ABI 検証はネイティブローダーが行い、LSP/DAP の jitCapability はインストール済みバックエンドではなくコアサービス契約を示します。

## メモリ型とデバッグ時の検査

対応する Runtime を使用すると、`std::memory` の型とジェネリック呼び出しの補完、ホバー、引数ヒントはネイティブツールが提供します。変数パネルでバッファとビューの検査項目を展開できます。これらの項目は読み取り専用で、再開またはステップ実行後に古いハンドルは無効になります。ホストのメモリメタデータは変更せずに転送します。任意のメモリ読み書き要求や専用メモリエディターはサポートしていません。

## 現在の言語ツールとモジュールソース

生文字列 `r"..."` は複数行に対応し、バックスラッシュをそのまま扱い、次の引用符で終了します。着色とテンプレートの絞り込みは Runtime がなくてもこの規則に従います。大文字の拡張子を含め、`.vslib` ライブラリの変更を言語サーバーへ通知します。

サーバーがモジュール環境とソース取得メソッドを公開した場合、定義への移動で `veroscript-module:` ドキュメントを読み取り専用のソーススナップショットとして開きます。同じネイティブパスもワークスペースごとに区別します。サーバーの再起動やコンパイルスナップショットの変更後は、元のソースファイルから移動し直してください。古いビューは以前のテキストを保持します。これらのビューはソース表示と構文着色を提供し、編集やスナップショット内の追加言語クエリは提供しません。

ネイティブのコンパイル／アノテーション処理器とモジュール環境は LSP／DAP ホストが提供します。既定の Runtime サーバーはホストアプリの処理器や CLI パッケージ環境を自動的に取り込みません。`bindingCatalogPaths` は拡張作成用にエクスポートしたコンパイルサービスカタログなどのメタデータを提供し、コールバックや処理器は登録しません。必要なプロジェクトでは対応するホストサービスを使用してください。

アノテーション名はホスト定義またはカタログの `caseSensitive` に従い、大文字と小文字を区別しない比較は ASCII のみに適用します。プラグインは正規名とネイティブの引数ラベルを保持し、引数名は引き続き大文字と小文字を区別します。既存の `bindingCatalogPaths` ファイルを更新すると、サーバーを再起動せずにメタデータを再読み込みします。インポートの整理はサーバーの正確な編集を適用し、コメント、生文字列、非アクティブな分岐、改行形式を保持します。

## 波括弧の配置と型のホバー

空の宣言ブロックまたは制御ブロック内で Enter を押すと、同じ行の開き波括弧が独立した行に移り、カーソルがインデントされます。入力途中の `void a{}` にも対応します。既に改行された括弧、コメント、文字列、曖昧な初期化式では通常の Enter を使用します。VS Code のインデント、改行コード、元に戻す操作と同条件の複数カーソルに対応し、位置の条件が異なる場合は通常の Enter を使用します。候補一覧、スニペット、インライン候補の Enter 動作は維持します。`veroscript.bracesOnNewLine` を無効にすると全位置で通常の Enter に戻ります。Runtime は不要で、文書全体の整形方針は変更しません。組み込み型のホバーは翻訳された分類と型名を一つの見出しにまとめ、説明を保持します。

既定では有効です。ユーザー設定またはワークスペース設定で切り替えられます。複数行の宣言ヘッダーやコンストラクターの初期化リストでは、継続行のインデントを適用しないよう通常の Enter を使用します。

タブとエクスプローラーで、VeroScript ファイルにライト／ダークテーマ用の簡潔な V アイコンを提供します。表示と独自アイコンの適用は選択中のファイルアイコンテーマに従い、拡張機能はテーマを変更しません。

int などの基本型と array などの組み込みコンテナーは、同じ簡潔な型見出しを使用します。補完の組み込み説明とメタデータは説明文として表示し、実際の宣言は VeroScript コードブロックを維持します。ソースの型エイリアス、オーバーロード、リンク、例は保持します。

バックスラッシュで継続されたプリプロセッサディレクティブや行コメント内では組み込みテンプレートを表示せず、終了後に表示を再開します。継続された行コメントではコメントの色付けと通常の Enter 動作も維持します。

対応する言語ツールでは、クラスや構造体の本体で、実装可能な継承仮想メソッドやインターフェイスメンバーの実装を補完から挿入できます。空白の挿入位置では、refactor.rewrite による同じ実装のコードアクションも利用できます。拡張機能はネイティブのシグネチャ、ジェネリック型の置換、挿入範囲、編集可能なスニペット本体を維持し、実装済み、final、アクセス不可のメンバーはサーバーが除外します。

再エクスポートを経由する移動でも推移的な依存先を維持し、所有するサーバーが提供する読み取り専用のモジュールソースを開きます。

## 数値と変数の編集

対応する Runtime またはホストでは、VS Code は各変数の DAP `presentationHint.attributes` を使って読み取り専用の状態を示します。対象には不変の `variant` の検査子項目、入れ子の値、ウォッチ結果も含まれます。拡張機能は、セッションの変数編集機能とは独立してこれらの情報を保持します。書き込みの検証はネイティブデバッガーが行い、ホストが省略した情報を拡張機能が推測することはありません。

`std::bigint`、`std::rational`、`std::numeric::rounding_mode` などの数値型は、言語サービスの結果でネイティブの名前を保持します。デバッグ値はネイティブの表示文字列のまま扱い、JavaScript の数値へ変換しません。利用できる API は対応する Runtime と標準ライブラリによって決まります。

## GUI コンパニオン

任意の [VeroScript GUI 拡張](../../../../../VeroScriptGuiVSCode/Resources/Docs/User/ja-JP/index.md)を追加すると `.vswml`／`.vswcss` と明示的なネイティブチェック・コンパイル・プレビューを利用できます。ツール API 1 が必要なため対応ローカル版を一緒に導入してください。GUI Runtime とプロバイダーは別途必要で、`.vs`／LSP／DAP は基本拡張の担当です。

展開した Runtime は、同梱のインタープリターモジュール `Vm/` と依存ファイルを含めて一式を保持してください。CLI、LSP、DAP は Runtime の既定の VM 構成を使用し、`run.backend: "vm"` は実行方針を選択します。対応する Runtime ファイルをまとめて移動・更新した後、言語サーバーを再起動してください。
