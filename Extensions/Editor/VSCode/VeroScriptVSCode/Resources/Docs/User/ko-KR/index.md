# VS Code용 VeroScript

일부 편집기 버전은 빈 작업 영역에서 터미널 프로세스를 제한합니다. 실행/검사 시 스크립트의 작업 디렉터리가 거부되면 해당 디렉터리를 작업 영역으로 여세요. 도메인 연결은 터미널을 사용하지 않습니다.

## 시작하기

데스크톱 VS Code 1.106.0 이상에서 로컬 VSIX를 설치합니다. 확장 호스트의 OS와 아키텍처에 맞는 호환되는 Runtime을 압축 해제하고 **VeroScript: Runtime 선택**에서 세 프로그램, stdlib, localization이 포함된 루트 디렉터리를 선택합니다.

.vs 파일을 저장하고 **파일 실행**, **파일 검사**, **파일 디버그**를 사용합니다. 기본 구문 색상과 코드 조각은 Runtime 없이 작동합니다. WSL, SSH, 컨테이너에서는 원격 호스트에 Runtime이 필요합니다.

## 설정과 실행

신뢰할 수 있는 작업 영역에서는 `veroscript.lsp.executablePath`로 호스트의 stdio 언어 서버를 선택할 수 있습니다. 실행 파일 경로에는 공통 경로 규칙이 적용됩니다. `veroscript.lsp.arguments`의 각 배열 항목은 공백이나 빈 문자열을 그대로 유지하여 하나의 인수로 전달됩니다. 명시하지 않은 컴파일 설정은 호스트 기본값을 유지합니다. 경로가 비어 있으면 Runtime 언어 서버를 사용하며 경로나 인수가 바뀌면 서버가 다시 시작됩니다. 사용자 지정 서버는 확장 호스트의 환경 변수를 상속하며 초기화 제한 시간은 10초입니다.

네임스페이스 완성을 확정하면 중첩 네임스페이스를 포함한 멤버 제안을 이어서 표시합니다. editor.suggestOnTriggerCharacters를 끄면 자동으로 이어서 표시하지 않습니다. VeroScript는 editor.wordBasedSuggestions의 기본값을 off로 설정하며 [veroscript] 설정에서 변경할 수 있습니다. 기본 템플릿은 접두사와 보수적인 어휘 문맥 검사로 필터링합니다. 가져오기와 진입점은 파일 범위, 선언은 지원되는 선언 범위, 반복문은 문장 시작 위치에서 제안합니다. 주석, 문자열, 미완성 표현식에서는 표시하지 않으며 사용자 코드 조각은 계속 VS Code가 관리합니다. 네이티브 필터 및 정렬 필드는 유지하며 VS Code도 입력 접두사를 기준으로 일치도를 평가합니다.

호버 시그니처는 VeroScript 코드 블록으로 표시하고 오버로드, 설명, 정의 위치를 구분합니다. 완성 상세 정보는 중복 시그니처를 피하고 기존 설명, 링크, 예제를 유지합니다. 색상은 VS Code 테마를 따르며 시그니처 도움말의 활성 매개변수는 계속 네이티브 서버가 결정합니다.

veroscript.importPaths, implicitImportPaths, defines, predefinedMacros, bindingCatalogPaths 등을 설정합니다. 상대 경로는 해당 작업 영역을 기준으로 하며 작업 영역이 없으면 소스 디렉터리를 사용합니다. 공유 경로에서 workspaceFolder와 환경 변수를 사용할 수 있고 필요한 컨텍스트가 없으면 오류가 발생합니다.

각 루트, 중첩 루트, 작업 영역 외부 파일은 별도의 언어 컨텍스트를 사용합니다. 오류는 **출력 표시**에서 확인하고 Runtime을 교체하면 언어 서버를 다시 시작합니다.

설정된 가져오기/표준 라이브러리 디렉터리와 명시적 암시적 가져오기에 있는 열린 파일의 저장되지 않은 내용도 참조하는 서버에 동기화됩니다. 편집 기능과 진단은 원래 컨텍스트가 담당합니다. Runtime은 편집한 파일의 진단을 갱신하며, 이를 참조하는 다른 파일의 진단은 해당 파일을 편집하거나 저장하는 등 다시 분석할 때 갱신됩니다.

실행 및 검사 명령은 관련 변경된 소스의 저장을 제안합니다. 직접 실행하는 작업은 task.saveBeforeRun을 따릅니다. 네이티브 프로세스의 인수 경계와 종료 코드를 유지합니다. 배열 및 명시적 작업 env는 상속 값을 대체합니다. VERO_PATH와 VERO_STDLIB_PATH 대신 명시적인 경로 설정을 사용하세요.

## 디버깅

F5는 VM DAP를 시작합니다. stopOnEntry, args, input, cwd, env 및 컴파일 옵션을 사용할 수 있습니다. 콘솔은 식을 평가하며 input은 초기 표준 입력입니다. 대화형 입력이나 디버깅 없는 실행에는 일반 실행 작업을 사용합니다.

program 모드의 attach는 program, host, port를 사용하여 수신 대기 중인 TCP DAP 호스트에 연결합니다. 로컬 Runtime이 필요하지 않으며 실행 설정, cwd, env를 주입하지 않습니다. 호스트에 새 프로그램을 로드하며 실행 중인 VM/PID에 연결하는 기능이 아닙니다. 양쪽에서 소스 경로가 유효해야 합니다. 함수, 예외, 로그, 적중 횟수 중단점, 역방향 실행, inlay hints 및 CodeLens는 지원하지 않습니다.

명령 팔레트 또는 .vs 파일 메뉴에서 **VeroScript: 호스트에 연결**을 실행하세요. 선택되거나 활성화된 저장된 스크립트를 사용하며, 해당 파일이 없으면 파일 선택기를 연 뒤 주소와 포트를 묻습니다(기본값 127.0.0.1:4711). 어느 입력이든 취소하면 세션을 시작하지 않습니다. 관련 소스 저장을 확인하고 진입점에서 멈춥니다. IPv6 주소는 대괄호 없이 입력하세요. F5 구성 생성 및 launch.json 완성에도 attach 템플릿이 있습니다. 고정 진입 파일, 인수, 명시적 컴파일 옵션은 launch.json에 저장하세요.

호스트 앱이 제공하는 호환 TCP DAP 연결점에 접속하세요. 편집용 `bindingCatalogPaths`, 가져오기 경로, 매크로와 표준 라이브러리 버전을 호스트와 맞추세요. 심볼 메타데이터만으로 로컬 Runtime에서 호스트 API를 실행할 수는 없습니다. 필요하면 `launch.json`에 컴파일 옵션을 명시하고 설정된 소스/가져오기 범위 밖의 의존 소스는 직접 저장하세요. 주소는 원격 환경을 포함한 확장 호스트에서 해석됩니다. 네이티브 코드는 해당 디버거로, 스크립트는 이 플러그인으로 디버깅하세요.

### 실행 도메인 연결

**VeroScript: 실행 도메인에 연결** 또는 launch.json 템플릿을 사용하세요. request는 attach, attachMode는 domain이며 host/port와 선택적인 예상 domainId를 지정합니다. domainId를 비우거나 생략하면 연결점의 도메인을 사용합니다. 열린 파일이나 로컬 Runtime이 필요 없습니다. 스크립트를 저장, 불러오기 또는 재시작하지 않으며 program, 컴파일/실행 재정의와 debugServer를 거부합니다. 여러 호스트 호출이 같은 연결을 유지할 수 있습니다. 호스트가 디버그 세션을 종료하면 플러그인은 스크립트 실행 취소를 요청하지 않고 연결 해제를 완료합니다.

연결점은 라이브 도메인 연결을 지원해야 합니다. 미지원이면 프로그램을 불러오지 않고 연결에 실패합니다. 초기 연결과 초기화 제한은 10초입니다. 출력에서 호스트/도메인 식별 정보와 소스/바인딩 리비전을 확인하세요. 리비전은 불투명한 식별자입니다. 자동 비교나 LSP 동기화가 없으므로 소스와 API 메타데이터를 직접 확인하세요. 연결 해제 후에도 실행과 취소는 호스트가 관리합니다. 연결이 끊기면 디버깅을 종료하며 자동 재연결하지 않습니다. 이미 JIT 코드를 실행 중인 VM을 인계받을 수는 없습니다.

일시 정지, 단계별 실행, 표현식 평가, 조건부 중단점 및 변수 편집은 호스트 지원 기능에 따라 달라집니다. 미지원 요청은 오류를 표시합니다. 일반 중단점은 계속 사용할 수 있습니다. 중지/연결 해제는 디버그 연결을 종료합니다. 스크립트 취소가 필요하면 호스트 앱에서 요청하세요.


## 선택적 JIT 모듈

Runtime과 JIT 백엔드는 별도로 배포됩니다. veroscript.run.jitBackendPath로 일반 실행용 호환 라이브러리 파일 또는 디렉터리를 선택적으로 고정합니다. 비워 두면 CLI 경로 덮어쓰기를 생략하고 모듈 환경의 선택을 상속하며 백엔드 미설정 시 기본값은 auto입니다. JIT가 비활성화되었거나 사용 가능한 자동 후보가 없으면 mixed는 VM을 사용하고 강제 jit는 실행 전에 실패합니다. 작업의 jitBackendPath로 덮어쓸 수 있으며 빈 문자열은 상속 값을 지웁니다. 상대 경로는 소속 작업 영역 또는 소스 디렉터리를 기준으로 하며 cwd와 무관하고 실행 경로 변수를 지원합니다. 검사, LSP, 로컬 VM 디버깅에서는 로드하지 않으며 launch/attach는 jitBackendPath를 거부합니다. 라이브 도메인의 백엔드는 호스트가 선택합니다. 디렉터리 검색과 ABI 검증은 네이티브 로더가 담당합니다. LSP/DAP의 jitCapability는 설치된 백엔드가 아닌 코어 서비스 계약을 나타냅니다.

## 메모리 타입과 디버깅 검사

호환되는 Runtime을 사용하면 네이티브 도구가 `std::memory` 타입과 제네릭 호출의 자동 완성, 호버 및 매개변수 힌트를 제공합니다. 변수 패널에서 버퍼와 뷰의 검사 필드를 펼칠 수 있습니다. 이 필드는 읽기 전용이며 실행을 재개하거나 단계 실행하면 이전 핸들이 만료됩니다. 호스트의 메모리 메타데이터는 변경 없이 전달합니다. 임의의 메모리 읽기/쓰기 요청이나 전용 메모리 편집기는 지원하지 않습니다.

## 현재 언어 도구와 모듈 소스

원시 문자열 `r"..."`은 여러 줄을 지원하며 백슬래시를 그대로 취급하고 다음 따옴표에서 끝납니다. 색상과 템플릿 필터는 Runtime 없이도 이 규칙을 따릅니다. 대문자 확장자를 포함한 `.vslib` 라이브러리 변경을 언어 서버에 전달합니다.

서버가 모듈 환경과 소스 요청 메서드를 공개하면 탐색 시 `veroscript-module:` 문서를 읽기 전용 소스 스냅샷으로 엽니다. 같은 네이티브 경로도 작업 영역별로 구분합니다. 서버 재시작이나 컴파일 스냅샷 변경 후에는 해당 소스 파일에서 다시 이동하세요. 이전 뷰는 기존 텍스트를 유지합니다. 이 뷰는 소스 표시와 구문 색상을 제공하며 편집이나 스냅샷 내 추가 언어 쿼리는 제공하지 않습니다.

네이티브 컴파일/주석 처리기와 모듈 환경은 LSP/DAP 호스트가 제공해야 합니다. 기본 Runtime 서버는 호스트 앱의 처리기나 CLI 패키지 환경을 자동으로 가져오지 않습니다. `bindingCatalogPaths`는 확장 작성용으로 내보낸 컴파일 서비스 카탈로그 등의 메타데이터를 제공하며 콜백이나 처리기를 설치하지 않습니다. 프로젝트에 필요하면 일치하는 호스트 서비스를 사용하세요.

어노테이션 이름은 호스트 정의나 카탈로그의 `caseSensitive` 정책을 따르며, 대소문자를 무시하는 비교는 ASCII에만 적용됩니다. 플러그인은 표준 이름과 네이티브 시그니처 매개변수 라벨을 유지하며 인수 이름은 대소문자를 구분합니다. 기존 `bindingCatalogPaths` 파일을 수정하면 서버 재시작 없이 메타데이터를 다시 불러옵니다. 가져오기 정리는 서버의 정확한 편집을 적용하며 주석, 원시 문자열, 비활성 분기 및 기존 줄바꿈을 유지합니다.

## 중괄호 배치와 형식 호버

빈 선언 또는 제어 블록 안에서 Enter를 누르면 같은 줄의 여는 중괄호를 별도 줄로 옮기고 커서를 들여씁니다. 입력 중인 `void a{}`도 지원합니다. 이미 별도 줄에 있는 중괄호, 주석, 문자열 및 모호한 초기화 구문에는 일반 Enter를 사용합니다. VS Code의 들여쓰기, 줄바꿈, 실행 취소와 동일 조건의 다중 커서를 지원하며, 커서 위치의 조건이 다르면 일반 Enter를 사용합니다. 제안 목록, 코드 조각 및 인라인 제안은 기존 Enter 동작을 유지합니다. `veroscript.bracesOnNewLine`을 끄면 모든 위치에서 일반 Enter로 돌아갑니다. Runtime은 필요 없으며 문서 전체 서식 정책을 변경하지 않습니다. 기본 제공 형식 호버는 현지화된 범주와 형식 이름을 한 제목으로 합치고 설명을 유지합니다.

기본적으로 켜져 있으며 사용자 또는 작업 영역 설정에서 바꿀 수 있습니다. 여러 줄 선언 헤더와 생성자 초기화 목록에서는 선언 들여쓰기를 유지하도록 일반 Enter를 사용합니다.

탭과 탐색기의 VeroScript 파일에 밝은 테마와 어두운 테마용 간결한 V 아이콘을 제공합니다. 표시 여부와 사용자 지정 아이콘 적용은 선택한 파일 아이콘 테마를 따르며, 확장 기능은 테마를 변경하지 않습니다.

int 같은 기본 형식과 array 같은 기본 제공 컨테이너는 동일한 간결한 형식 제목을 사용합니다. 완성 항목의 기본 제공 설명과 메타데이터는 설명문으로 표시하고, 실제 선언은 VeroScript 코드 블록을 유지합니다. 소스 형식 별칭, 오버로드, 링크와 예제는 보존합니다.

백슬래시로 이어진 전처리기 지시문과 줄 주석 전체에서 기본 제공 템플릿을 숨기고, 해당 구문이 끝나면 다시 표시합니다. 이어진 줄 주석에서는 주석 색상과 일반 Enter 동작도 유지합니다.

지원하는 언어 도구에서는 클래스 또는 구조체 본문의 완성 목록에서 구현 가능한 상속 가상 메서드와 인터페이스 멤버의 구현을 삽입할 수 있습니다. 빈 삽입 위치에서는 refactor.rewrite 코드 작업으로 같은 구현을 추가할 수 있습니다. 확장은 네이티브 시그니처, 제네릭 형식 치환, 삽입 범위와 편집 가능한 코드 조각 본문을 보존하며, 서버는 이미 구현되었거나 final 또는 접근할 수 없는 멤버를 제외합니다.

재내보내기를 통한 탐색도 전이 종속성 대상을 보존하고, 해당 서버가 제공하는 읽기 전용 모듈 소스를 엽니다.

## 수치와 변수 편집

지원하는 Runtime 또는 호스트에서 VS Code는 각 변수의 DAP `presentationHint.attributes`를 사용해 읽기 전용 상태를 표시합니다. 변경 불가능한 `variant`의 검사 하위 항목, 중첩 값과 조사식 결과도 포함됩니다. 확장은 세션의 변수 편집 기능과 별개로 이 정보를 보존합니다. 쓰기 검증은 네이티브 디버거가 담당하며, 호스트가 생략한 읽기 전용 정보를 확장이 추측하지 않습니다.

`std::bigint`, `std::rational`, `std::numeric::rounding_mode` 같은 수치 형식은 언어 서비스 결과에서 네이티브 이름을 유지합니다. 디버그 값은 네이티브 표시 문자열을 유지하며 JavaScript 숫자로 변환하지 않습니다. 사용 가능한 API는 일치하는 Runtime과 표준 라이브러리를 기준으로 합니다.

## GUI 동반 확장

선택적인 [VeroScript GUI 확장](../../../../../VeroScriptGuiVSCode/Resources/Docs/User/ko-KR/index.md)은 `.vswml`／`.vswcss` 편집과 명시적 네이티브 검사ㆍ컴파일ㆍ미리 보기 작업을 제공합니다. 도구 API 1에 의존하므로 일치하는 로컬 버전을 함께 설치하세요. GUI Runtime과 공급자는 별도이며 `.vs`／LSP／DAP는 기본 확장이 담당합니다.

배포된 인터프리터 모듈 `Vm/`과 의존 파일을 포함해 압축 해제한 Runtime 전체를 유지하세요. CLI, LSP, DAP는 Runtime의 기본 VM 구성을 사용하며 `run.backend: "vm"`은 실행 정책을 선택합니다. 서로 맞는 Runtime 파일을 함께 이동하거나 업데이트한 뒤 언어 서버를 다시 시작하세요.
