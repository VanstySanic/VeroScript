# VeroScript GUI VS Code 開発

## アーキテクチャ

ネイティブ GUI の検証には対応した Core、Tooling、VM、プロバイダーのビルドが必要です。製品バージョンの一致だけでは ABI 互換性を確認できません。エディターのメタデータ確認と、実際の検査、アプリケーションコンテナーのコンパイル、フレーム数を制限したプレビューを個別に検証してください。

成果物の回帰テストでは、プロバイダーを使用する `gui-check`、独立した通常の `--check`、ソースプロジェクトの環境とコンパイル引数を引き継ぐ通常の `--check` で `.vsapp` を検証します。明示的な標準ライブラリパスと `--path` を併用し、ネイティブ側の標準ライブラリルート重複排除も検証します。全体の期限はネイティブタスクとアーカイブ検証を含み、各コマンドにも期限を設けます。Core／ABI の構成が変わったら、インストール済みテスト環境を再生成してください。

Runtime／LSP／DAP は基本拡張に置きます。依存を有効化して `Public/api.d.ts` の API 1 を使い、明示的な実行要求時だけツールチェーンを解決します。ソース URI は変数、所属フォルダーは設定を決定します。編集や自動タスク列挙では原生ツールを解決・起動しません。設定タスクの解決では CLI バージョンを照会する場合があります。ネイティブ GUI ソースは独立管理です。

文書バージョン別モデルをキャッシュし解析を制限します。編集・取消後の非同期メタデータ／パス結果は破棄します。キャッシュと監視は解決設定で分離します。名前・Mark の大文字小文字を保持し曖昧別名を省き、共有祖先を重複走査しません。ヒントをコンパイラの意味判断にしないでください。

## ビルドと検証

Node.js 22.18+、デスクトップ VS Code 1.106+ が必要です。各モジュールで下記を実行します。共有宣言が基本拡張の SDK 型を参照するため、両方の依存を導入します。開発テストは両拡張を読み込み、VSIX テストは隔離プロファイルにローカル両パッケージを順番に導入します。未公開の依存を Marketplace から取得しないでください。

```sh
# VeroScriptVSCode
npm ci
npm run typecheck
npm run package
# VeroScriptGuiVSCode
npm ci
npm run typecheck
npm run test:unit
npm run test:integration
npm run package
npm run package:contents
node Resources/Tools/test.mjs --packaged --skip-build
```

デスクトップの Extension Host スイートは一つずつ実行します。複数の VS Code テストウィンドウを同時に開くと、補完の確定、元に戻す操作、Enter のテストで必要な編集フォーカスを奪い合う場合があります。

ネイティブ GUI の受入テストはチェック、コンパイル、プレビューの各タスクに 600 秒を割り当て、そのテストだけ全体の期限をタスク列に合わせます。編集プロバイダーの待機期限は短いままです。明示的な GUI コマンドはフレームワーク全体を初回コンパイルし、正常終了まで 1 分以上かかる場合があります。製品のタスクは非同期で、VS Code から停止できます。非ゼロ終了、出力欠落、テスト期限超過は引き続き受入失敗です。

単体テストは構造、UTF-16、CSS、メタデータ、曖昧性・循環、CLI 順序、TextMate を対象にします。Extension Host は依存、言語、補完、ホバー、リンク、タグ、診断、原生サービス休止を対象にします。`VEROSCRIPT_TEST_RUNTIME` に対応 GUI Runtime を指定し `VEROSCRIPT_GUI_TEST_NATIVE=1` で実際のチェック／コンパイルを要求します。対応プロバイダーのあるデスクトップで `VEROSCRIPT_GUI_TEST_PREVIEW=1` を加えると2フレームのマークアッププレビューも要求します。Windows／Linux／macOS、空白・Unicode パス、フォルダーなし、複数ルート、リモート、本物のウィンドウを個別に検証してください。スキップは原生合格ではありません。

`VEROSCRIPT_TEST_DIRECTORY` は、基本拡張と同様に隔離テストのワークスペースとプロファイルの絶対親ディレクトリを指定します。ネイティブパッケージ環境の検証では、生成 GUI ソースがその環境に属するよう、`VEROSCRIPT_GUI_TEST_ENVIRONMENT_PATH` で選ぶプロジェクト内に配置してください。無関係な一時ワークスペースはネイティブのソース所属チェックで拒否されるため、テスト構成の不一致を回避する目的でコンパイラーのアクセス範囲を広げないでください。

原生検証の各実行で Runtime のソース／リリースを記録し、古い記録を新コードの証拠にしないでください。CLI のタイムアウトは検証失敗です。編集で自動プレビューしません。

## 編集メタデータ

例を `demo.veroscript-gui.json` として保存し `veroscriptGui.schemaFiles` に追加します。ヒントだけであり実際の型とプロセッサーはホストが登録します。後のスキーマは同じ正式名の型全体を置き換えるため、その型自身の全メンバーを指定します。基底は正式名、共通イベントは任意の `routedEvents` です。

```json
{
	"schemaVersion": 1,
	"types": [{
		"name": "Demo::Card",
		"mark": "card",
		"bases": ["VS::Gui::Widget"],
		"properties": [{ "name": "Title", "mark": "title", "type": "string", "bindable": true }],
		"events": [{ "name": "Selected", "mark": "selected", "type": "std::multicast_delegate<void()>" }]
	}]
}
```

組み込みメタデータはネイティブ `VeroScriptGui.vs` エントリからローカルの `export import` をたどり、入力を `builtin.json` に記録します。`Mark` 別名のない注釈付きウィジェットも保持し、複合コントロールの継承を維持します。`npm run schema:update` で更新し、ネイティブリテラルと style／bindable を確認してください。通常ビルドは一致するスナップショットを要求し、型の重複・基底型の不足を拒否します。単体・Extension Host 回帰テストは複合タグ、継承プロパティ／イベント、配置値、CSS 候補、選択色を対象にします。これはネイティブ実行の検証を代替しません。 ネイティブ名前空間の再構成後も、完全修飾された `VS::Gui::Internal` の基底型を保持し、継承ヒントを維持します。

メタデータ抽出は `@GuiWidget` と `@ GuiWidget` のような、`@` と注釈名の間の言語上有効な空白を受け入れ、同じプロパティ・イベント・継承情報を生成します。ソースの整形後は `npm run schema:check` を再実行します。抽出したメタデータが変わった場合は `npm run schema:update` を使います。`builtin.json` はソースパスとメタデータを記録し、ソース内容のハッシュは保持しません。

## 配布

機能パッケージは bundle、マニフェスト、翻訳、文法、スキーマ、アイコン、MIT 表示のみで、ネイティブバイナリ、ツール、テスト、開発文書は含めません。GUI 実行コードの外部 JavaScript 依存は現在なく、追加時は表示を更新します。LICENSE はリポジトリと一致させ6言語を同期します。独立 VSIX パッケージに加え、統合 IDE パッケージでは GuiVSCode を独立製品として登録し、基本拡張もビルドして両方のローカル VSIX を一緒に検証します。

静的回帰レビューは EOF／タグ境界、数値範囲、空白付き代入、閉じ引用符後の重複、埋め込み XML コメント、空のアウトラインを対象にします。CSS URL はキャッシュしたスタイル解析で一度読み、原生の大文字小文字とエスケープを扱います。リンク要求は範囲を再利用します。設定タスクの準備は CLI バージョンを照会する場合がありますが、編集と自動タスク検出は GUI コマンドを起動しません。原生検証は VS Code 登録プロバイダーから設定タスクを取得し、導入済み拡張を使います。必要なら `VEROSCRIPT_GUI_TEST_ENVIRONMENT_PATH` に準備済みパッケージ環境の絶対パスを指定します。JavaScript のプロトタイプメンバーと同名のカスタムタグについても、属性補完の回帰ケースを追加しています。隔離テスト設定では単語候補を無効化し、対応するエディター終了コマンドを使います。原生検証には一致する Runtime と、チェック・コンパイル・プレビューの成功が必要です。

[エディタ統合の保守](../../../../../../../../Resources/Docs/Developer/ja-JP/editors.md#acceptance-evidence) を参照してください。
publisher は `package.json` の宣言に従い、GUI の依存は基本拡張の識別子と一致させます。ルート README を詳細ページとして同梱し、除外したリポジトリファイルへリンクしないでください。機能パッケージの文書例外は `extension/readme.md` のみです。Marketplace 公開には登録済み publisher の権限と検証完了が必要で、マニフェストの変更では publisher は登録されません。
