# Rider で VeroScript GUI を使う

## インストールと設定

**VeroScript** を先にインストールし、互換性のある **VeroScript GUI** を **Settings → Plugins → Install Plugin from Disk** から追加します。求められたら再起動してください。Rider の要件と Runtime の選択は、下記の基本プラグインガイドに従います。

[基本プラグインのガイド](../../../../../VeroScriptJetBrains/Resources/Docs/User/ja-JP/index.md)
に従い「言語とフレームワーク → VeroScript」で Runtime を設定してください。
実行には対応する GUI 版 CLI、GUI スクリプトライブラリ、ネイティブプロバイダーが必要です。
プラグインはそれらをインストールしません。Runtime がなくてもローカルの強調表示と組み込み補完は使えます。

## マークアップとスタイル

組み込み候補には `ListView`、`TreeView`、`TableView`、`ComboBox`、`TabView`、`Menu`、
`Dialog` と、継承された選択/ポップアップのプロパティ、独自イベント、スタイルプロパティを含みます。
データ項目や仮想化は GUI スクリプト API で設定します。これらのコントロールを含む対応する
GUI Runtime を使用してください。

`.vswml` はネイティブ GUI マークアップ、`.vswcss` は GUI スタイル言語です。
HTML や完全な CSS ではありません。`bind:` と `on:` に `xmlns` は不要です。
組み込みウィジェット、継承プロパティ、ゲッターバインディング、イベント、スタイル、対応する疑似状態を補完します。
大文字と小文字、および Rider の先頭候補選択設定を尊重します。
ディレクティブの `src` はローカルパスの移動・補完に対応します。相対パスは宣言元ファイルを基準にし、
実行中の OS が絶対パスと認識するパスはファイルシステムのルートを基準にします。
区切り文字はその OS の規則に従い、`?` などのファイル名の文字を保持します。
不透明なホストリソース識別子、SDK が除去する前後の空白や実体参照（`&...;`）を含むパスはローカル移動の対象外です。
通常のパス参照は Rider のファイル/フォルダー名変更に対応し、挿入する名前をマークアップ用にエスケープします。

属性を `=`、スタイル属性を `:` で確定すると、既存の記号を重複させず値へ移動します。
既存の値は保持します。Tab はハイフンや `bind:`/`on:` 接頭辞を含む完全な名前を置換します。

インライン `<script>` / `<style>` と CDATA は字句強調表示に対応します。
通常の VS セマンティック編集には外部 `.vs` を使い、
`<script src="logic.vs" type="App::Logic" />` から参照します。
外部スクリプトは基本プラグインの LSP を使用します。インラインコードやバインディングの意味解析、
独自 Schema の解析、整形、自動コンパイル診断はこのアドオンの機能ではありません。
正式な検証は **GUI を検査** で実行してください。独自タグをカタログにないという理由だけでエラーにしません。
GUI API の意味解析とデバッグは設定された LSP/DAP とホストの対応に依存し、このアドオンは実行用バインディングを生成しません。

`page.vswml`:

```xml
<Stack Width="100%" Height="100%">
	<style src="page.vswcss" />
	<Text Text="Hello, VeroScript GUI!" />
</Stack>
```

`page.vswcss`:

```css
:root {
    padding: 16px;
    gap: 12px;
    color: #edf4fc;
    background-color: #101927;
    font-size: 18px;
}
```

## 検査、プレビュー、ベイク

ローカルの `.vswml`、`.vs`、`.vsapp` を右クリックして **VeroScript GUI** を選びます。
`.vswcss` は参照元のマークアップを検査し、直接実行しません。

| タスク | 動作 |
| --- | --- |
| GUI を検査 | `gui-check`。検査／コンパイルを行い、アプリケーションの入口呼出しやプレビューウィンドウ作成は行いません。 |
| GUI をプレビュー | `gui-preview`。別のネイティブウィンドウで実行。Rider の停止またはウィンドウを閉じて終了します。 |
| GUI アプリのベイクを設定 | 出力とリソースの設定画面を開きます。確認後「実行」で `gui-compile` を呼び出します。 |

ソースの検査やベイクでは、スクリプトで実装したコンパイルプロセッサーを実行する場合があります。VM と GUI スクリプトライブラリーを含む完全な対応 Runtime を使用してください。これらのタスクに実行用 JIT プロバイダーは不要です。

実行構成に **VeroScript GUI** を追加できます。`.vswml` はコンテキストからプレビュー構成を作成可能です。
通常の `.vs` の実行とデバッグは基本プラグインが担当します。GUI タスクは「実行」のみで、
GUI 対応 DAP 起動は提供しません。ホストが用意したデバッグドメインには基本プラグインの手順でアタッチできます。
プレビューは明示操作です。埋め込みデザイナーや自動再読み込みはありません。

## 構成

- コンテキスト操作は GUI 構成テンプレートを継承し、タスク/入口に適用できない設定を除去します。
  適用できる独自ベイク出力は保持します。
- Runtime、言語、プロジェクトのコンパイラー設定を継承します。実行時 JSON 上書きは編集設定を変えません。
  継承パスは元のプロジェクトを基準にし、実行上書きの相対パスは作業ディレクトリを基準にします。
- コンテキストの入口は `$PROJECT_DIR$` を使用。作業ディレクトリの空欄はプロジェクトルートです。
  ML/CSS 内部の相対参照は宣言元のファイル基準です。
- パッケージ環境は `--path`。バックエンド欄が空なら上書きを渡さず、Runtime/パッケージの既定値を継承します。
  `auto` はネイティブ側のプロバイダー選択、`none` はサービスの無効化です。プレビューに必須のサービスを
  無効にするとエラーになります。ネイティブ環境に明示的に保存した空のバックエンド値は `none` であり、
  ここでの空欄とは異なります。必要なプロバイダーは環境にインストールするか GUI Runtime で提供してください。
- 標準 `Context` ファクトリはコンストラクター、呼び出し設定、ファクトリ既定値のすべてが GUI バックエンドを
  未指定の場合だけ `rmlui` を使います。明示的な `auto`/`none` は維持されます。6 欄は GUI サービス専用で、
  VM/JIT 実行オプションは別のものです。
- 検査とベイクは VM を使用します。プレビューはネイティブ側の実行既定値を保ちます。
- 保存する入口パスは実行 OS の区切り文字だけを正規化します。POSIX ファイル名のバックスラッシュは保持されます。
- プレビュー引数は `--` の後へ渡します。正の `int64` フレーム数は `.vswml` 専用で、空欄または `0` は無制限。
  `.vs` と `.vsapp` は自身の実行ループを使います。
- ベイクは `.vswml` / `.vs` と `.vsapp` 出力が必須。名前とリソース配列（例 `["assets/logo.png"]`）は任意です。
  入口や指定リソースの上書きは拒否します。既定出力は `.tmp/gui/`。永続保存には出力先を変更してください。
- 環境変数は文字列値を持つ JSON オブジェクトです。親環境の継承を設定できます。
  ローカルファイルを指す診断は行リンクを表示。未対応コマンドやプロバイダー不足もコンソールに表示します。
