# Rider에서 VeroScript GUI 사용

## 설치와 설정

**VeroScript**를 먼저 설치한 뒤 호환되는 **VeroScript GUI**를 **Settings → Plugins → Install Plugin from Disk**로 추가합니다. 요청하면 다시 시작합니다. Rider 요구 사항과 Runtime 선택은 아래 기본 플러그인 가이드를 따릅니다.

[기본 플러그인 안내](../../../../../VeroScriptJetBrains/Resources/Docs/User/ko-KR/index.md)에 따라
언어 및 프레임워크의 VeroScript에서 Runtime을 설정합니다. 실행에는 일치하는 GUI CLI,
GUI 스크립트 라이브러리와 네이티브 공급자가 필요합니다. 플러그인이 이를 설치하지는 않습니다.
Runtime이 없어도 로컬 마크업/스타일 강조와 내장 자동 완성을 사용할 수 있습니다.

## 마크업과 스타일 편집

내장 제안에는 `ListView`, `TreeView`, `TableView`, `ComboBox`, `TabView`, `Menu`, `Dialog`와
상속된 선택/팝업 속성, 사용자 지정 이벤트 및 스타일 속성이 포함됩니다.
데이터 항목과 가상화는 GUI 스크립트 API로 설정합니다. 해당 컨트롤이 포함된 호환 GUI Runtime을 사용하세요.

`.vswml`은 네이티브 GUI 마크업이고 `.vswcss`는 GUI 스타일 언어입니다. HTML이나 전체 CSS가 아닙니다.
`bind:`와 `on:`에 `xmlns` 선언은 필요하지 않습니다. 내장 위젯, 상속 속성, 게터 바인딩,
이벤트, 스타일 속성과 지원되는 의사 상태를 제안합니다. 대소문자 규칙과 Rider의 첫 항목 선택 설정을 따릅니다.
지시문의 `src`는 로컬 경로 탐색과 자동 완성을 지원합니다. 상대 경로는 선언 파일을 기준으로 하며,
실행 중인 OS가 절대 경로로 인식하는 경로는 파일 시스템 루트를 기준으로 합니다.
구분자는 현재 OS 규칙을 따르며 `?` 같은 파일 이름 문자를 보존합니다.
호스트의 불투명 리소스 식별자와 SDK가 제거하는 앞뒤 공백 또는 엔티티 이스케이프(`&...;`)가 있는 경로는 로컬 탐색 대상이 아닙니다.
일반 경로 참조는 Rider의 파일/폴더 이름 변경에 참여하며 삽입하는 이름은 마크업에 맞게 이스케이프합니다.

속성은 `=`, 스타일 속성은 `:`로 확정하면 기존 구두점을 중복하지 않고 값으로 이동합니다.
기존 값은 보존합니다. Tab은 하이픈과 `bind:`/`on:` 접두사를 포함한 전체 이름을 교체합니다.

인라인 `<script>`와 `<style>`, CDATA에 어휘 강조를 제공합니다. 일반적인 VS 의미 편집에는
외부 `.vs` 파일을 사용하고 `<script src="logic.vs" type="App::Logic" />`로 참조하세요.
외부 스크립트는 기본 플러그인의 LSP 기능을 유지합니다. 인라인 스크립트/바인딩 의미 분석,
사용자 정의 Schema 분석, 서식 지정과 자동 컴파일 진단은 이 추가 기능에서 구현하지 않습니다.
정확한 검증은 **GUI 검사**를 실행하세요. 내장 목록에 없는 사용자 정의 위젯을 바로 오류로 표시하지 않습니다.
GUI API 의미 분석과 디버깅은 구성한 네이티브 LSP/DAP 및 호스트 지원에 따르며, 이 추가 기능은 실행 가능한 바인딩을 생성하지 않습니다.

`page.vswml`:

```xml
<Stack Width="100%" Height="100%">
	<style src="page.vswcss" />
	<Text Text="Hello, VeroScript GUI!" />
</Stack>
```

`page.vswcss`:

```css
:root {
    padding: 16px;
    gap: 12px;
    color: #edf4fc;
    background-color: #101927;
    font-size: 18px;
}
```

## 검사, 미리 보기 및 베이크

로컬 `.vswml`, `.vs`, `.vsapp` 파일에서 마우스 오른쪽 버튼으로 **VeroScript GUI**를 선택합니다.
`.vswcss`는 이를 참조하는 마크업 진입 파일을 통해 검사하며 직접 실행하지 않습니다.

| 작업 | 동작 |
| --- | --- |
| GUI 검사 | `gui-check`. 앱 진입점을 호출하거나 미리 보기 창을 열지 않고 검사/컴파일합니다. |
| GUI 미리 보기 | `gui-preview`. 독립 네이티브 창에서 실행합니다. Rider에서 중지하거나 창을 닫아 종료하세요. |
| GUI 앱 베이크 구성 | 출력과 리소스 구성을 엽니다. 확인 후 실행을 눌러 `gui-compile`을 호출합니다. |

소스 검사나 베이크는 스크립트 기반 컴파일 처리기를 실행할 수 있습니다. VM과 GUI 스크립트 라이브러리를 포함한 완전한 호환 Runtime을 사용하세요. 이 작업에는 실행용 JIT 공급자가 필요하지 않습니다.

실행 구성에서 **VeroScript GUI**를 추가할 수 있습니다. `.vswml`은 컨텍스트에서 미리 보기 구성을 생성합니다.
일반 `.vs` 실행과 디버깅은 기본 플러그인에 속합니다. GUI 작업은 실행만 지원하며 GUI 전용 DAP 시작 기능은 없습니다.
호스트에서 준비한 디버그 도메인에는 기본 플러그인의 연결 절차를 사용하세요.
미리 보기는 명시적 작업입니다. 내장 시각적 디자이너나 자동 다시 불러오기는 없습니다.

## 구성 세부 사항

- 컨텍스트 작업은 GUI 구성 템플릿을 상속하고 선택한 작업/진입 파일에 맞지 않는 옵션을 지웁니다.
  적용 가능한 사용자 지정 베이크 출력은 유지합니다.
- Runtime, 언어와 프로젝트 컴파일러 설정을 상속합니다. 실행별 JSON 재정의는 편집 설정을 바꾸지 않습니다.
  상속 경로는 원래 프로젝트를 기준으로 하며 실행 재정의의 상대 경로는 작업 디렉터리를 기준으로 합니다.
- 컨텍스트 진입 파일은 `$PROJECT_DIR$`를 사용합니다. 빈 작업 디렉터리는 프로젝트 루트입니다.
  ML/CSS 내부 상대 참조는 선언 파일을 기준으로 합니다.
- 패키지 환경은 `--path`에 대응합니다. 빈 백엔드 필드는 재정의를 전달하지 않고 Runtime/패키지 기본값을 상속합니다.
  `auto`는 네이티브 공급자 선택, `none`은 서비스 비활성화를 뜻합니다. 미리 보기에 필수인 서비스를 끄면 오류가 납니다.
  네이티브 환경에 명시적으로 저장한 빈 백엔드 값은 `none`이며 이 설정의 빈 필드와 다릅니다.
  필요한 공급자는 환경에 설치하거나 GUI Runtime이 제공해야 합니다.
- 표준 `Context` 팩터리는 생성자, 호출 설정, 팩터리 기본값 모두 GUI 백엔드를 지정하지 않을 때만 `rmlui`를 사용합니다.
  명시적인 `auto`/`none`은 유지됩니다. 여섯 필드는 GUI 서비스용이며 VM/JIT 실행 옵션은 별개입니다.
- 검사와 베이크는 VM을 사용하며 미리 보기는 네이티브 실행 기본값을 유지합니다.
- 저장하는 진입 경로는 실행 OS의 구분자만 정규화하며 POSIX 파일명의 역슬래시는 그대로 유지합니다.
- 미리 보기 스크립트 인수는 `--` 뒤에 전달합니다. 양의 `int64` 프레임 제한은 `.vswml` 전용입니다.
  빈 값 또는 `0`은 무제한입니다. `.vs`와 `.vsapp`은 자체 실행 루프를 관리합니다.
- 베이크에는 `.vswml` / `.vs` 소스와 `.vsapp` 출력이 필요합니다. 이름과 `["assets/logo.png"]` 같은
  리소스 배열은 선택 사항입니다. 진입 파일이나 나열한 리소스를 덮어쓸 수 없습니다.
  기본 출력은 `.tmp/gui/`에 있으므로 영구 보관하려면 변경하세요.
- 환경은 문자열 값을 가진 JSON 객체이며 부모 환경 상속을 제어합니다. 로컬 파일 진단은 줄 링크를 제공합니다.
  지원하지 않는 Runtime 명령이나 누락된 공급자는 콘솔에 표시됩니다.
