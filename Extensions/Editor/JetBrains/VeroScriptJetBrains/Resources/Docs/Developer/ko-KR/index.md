# 개발자 문서 — Rider

에디터/네이티브 공통 책임과 여섯 언어 유지보수는 [공통 에디터 통합](../../../../../../../../Resources/Docs/Developer/ko-KR/editors.md)에서 관리합니다.

`VeroScriptBundle` / `DynamicBundle`과 현지화된 `.properties` 리소스를 사용합니다. `MessageFormat` 자리표시자와 이스케이프한 아포스트로피를 확인하고 실행이 허용될 때 실제 인수 치환도 검증합니다.

JDK/JVM 25, Gradle 9.5.0, Kotlin 2.4.0, IntelliJ Platform plugin 2.19.0을 사용합니다. SDK는 Rider 2026.2.2로 고정됩니다. `sinceBuild=262.10315.191`, `strict-until-build=262.*`로 설치 대상을 262 브랜치로 제한합니다. 다른 브랜치는 별도 검증이 필요합니다. `VEROSCRIPT_TEST_RUNTIME`으로 현재 네이티브 테스트를 활성화하며 미설정 시 명시적으로 건너뜁니다. 선택적 `VEROSCRIPT_TEST_JIT_BACKEND`는 실제 모듈 테스트를 활성화합니다. SDK 구조 검사/ZIP은 Rider UI 검증을 대체하지 않습니다.

```sh
./gradlew test verifyPluginProjectConfiguration verifyPluginStructure buildPlugin
./gradlew verifyPlugin
```

`gradlew.bat` (Windows) · `bash ./gradlew` (Linux) · `-PlocalIdePath=/absolute/path/to/Rider`

[Standards](../../../../../../../../Resources/Docs/Standards/ko-KR/GENERAL.md)


네이티브 회귀 테스트는 `std::memory` 네임스페이스 및 멤버 완성, 소스 표기, 호버, 진단 및 동일 버전 의미 토큰 delta를 검사합니다. DAP 테스트는 플러그인의 LSP4J 전송으로 buffer, view 및 감시를 펼치고 검사 항목 수정 거부와 스텝 후 객체 ID 유지 및 이전 참조 만료를 확인합니다. 메타데이터 숫자는 프로토콜 문자열로 유지합니다. `variablesReference`는 불투명 핸들이며 메모리 주소가 아닙니다.

자식 개수가 있으면 제한된 DAP 페이지를 요청하고 짧은 응답에서 펼치기를 종료합니다. 개수가 없으면 전체 스냅샷을 한 번 받아 로컬에서 나눕니다. 100개 응답만으로 페이지 지원을 판단하지 않습니다. 비동기 응답과 캐시 페이지 콜백 모두 현재 일시 중지 세대와 노드 수명을 확인해야 합니다. 회귀 테스트는 빈 목록, 99/100/101/250개 항목, 짧은 응답, 재개 후 이전 스냅샷 및 실제 Runtime의 100개 요소 배열을 검사합니다.

디버거의 자동 툴팁은 세션이 속한 프로젝트의 편집기만 추적합니다. 계속, 스텝 및 일시 중지 요청의 오류는 해당 요청의 세대에만 적용되며 이전 세대의 실패는 새 중단 상태에 영향을 주지 않습니다. 현재 일시 중지 요청의 실패는 연결을 유지한 채 보고하고, 전송 연결이 끊어지면 별도로 세션을 종료합니다. 프로토콜 및 팝업 테스트 픽스처는 일시 중지 실패 응답과 중단 알림의 두 가지 도착 순서를 포함해 이 경계를 검증합니다.

내보낸 별칭 회귀 테스트는 소스 파사드를 통한 `export using` 및 `export typedef`의 완성, 비공개 별칭 제외, 호버 및 정의 탐색을 검증합니다. CLI Run/Check는 같은 Runtime으로 빌드한 `.vslib`를 파사드에서 가져오는 경우도 검증합니다. 이는 네이티브 프로토콜 및 프로세스 테스트이며 Rider UI 수락 검증을 대체하지 않습니다.

로컬 렉서는 코어의 `constexpr` 키워드를 인식합니다. DAP 변수의 `presentationHint.attributes`에 `readOnly`가 있으면 수정 기능을 제공하지 않습니다. 다른 표시 속성은 쓰기 가능 여부를 바꾸지 않으며 호스트 및 실행 도메인의 기능 제한도 유지합니다. 회귀 사례는 키워드 경계와 읽기 전용, 쓰기 가능 및 다른 표시 속성을 가진 자식 변수를 다룹니다.

## 컴파일 확장과 생성 소스

DAP `stackTrace` 프레임의 `column`은 이미 1부터 시작하는 UTF-16 열이며 로컬 파일, 양수 `sourceReference`의 읽기 전용 스냅샷 및 live domain에 동일하게 적용됩니다. 편집기 줄 텍스트를 사용할 수 있으면 클라이언트는 시작 기준을 0으로 바꾸고 해당 줄 범위로 제한하며 서로게이트 쌍을 나누지 않습니다. UTF-8 바이트에서 다시 변환하면 안 됩니다. 좌표 및 컨트롤러 회귀 사례는 CJK, 보충 문자와 CRLF를 포함합니다.

초기 및 다음 페이지의 스택 프레임을 표시하기 전에 소스 참조를 비동기로 해석합니다. 로컬 경로가 함께 제공되어도 양수 참조별로 연결 내에서 변경할 수 없는 읽기 전용 파일을 캐시합니다. 스냅샷은 프로젝트 작업과 LSP에서 제외합니다. 읽기 실패 시 중지 상태를 유지하고, 세대 검사로 늦게 도착한 중지 결과를 무시하며, 해제 시 캐시를 비웁니다. 네이티브 회귀는 컴파일 확장 가져오기, 생성된 완성/호버/탐색, 생성 본문으로 단계 진입 및 공개 매크로 가져오기를 검증합니다. 네이티브 레지스트리와 `ModuleEnvironment`는 호스트 API 옵션이며 LSP JSON 설정이 아닙니다. `veroscript/moduleSource`는 호스트 모듈을 제공합니다. 플러그인은 독립 LSP를 시작하며 호스트 LSP에 연결하지 않습니다. 실패한 소스 요청은 캐시에서 제거하여 이후 스택을 불러올 때 다시 시도할 수 있습니다. 같은 스택 페이지의 중복 참조는 한 번만 요청합니다.

주석 이름 일치는 Tooling/Core에서 처리하며 클라이언트는 소스 표기와 서버 레이블을 유지합니다. 네이티브 회귀 테스트는 재시작 없이 카탈로그 정의의 `caseSensitive` 정책 변경, LSP/DAP에서 대소문자를 혼합한 컴파일 주석, `matches_name`/`case_sensitive` 완성 및 호출 가능 타입 매개변수 레이블을 검증합니다. 도메인 프로토콜 픽스처는 attach 응답 전에 도착한 중단 이벤트, 기능 정보의 가용성 및 이후 실행 재개도 검증합니다.

## 편집기 표시

원본 편집기 렉서는 전처리기와 같이 백슬래시 바로 뒤의 LF／CRLF만 줄 주석 연속으로 처리하며 끝의 가로 공백을 제거하지 않습니다. 회귀 검사는 token 재시작, 잘린 범위, 선형 문자 읽기 횟수, GUI 인라인 색상 표시, 주석 및 끝난 지시문 뒤의 빈 블록 Enter를 검증합니다. 네이티브 LSP 회귀는 중첩 호출 가능 값, 제네릭, 별칭, 배열／map, 암시적 수신자 체인과 private 멤버 가림을 다룹니다. DAP 회귀는 variant 검사·감시 자식의 읽기 전용 속성을 보존하고 일반 지역 변수는 계속 수정할 수 있는지 검증합니다.

문서 대상은 공개 LSP 전송으로 비동기 요청을 수행하며 인식된 Markdown 제목만 정리하고 서버의 시그니처와 설명을 유지합니다. 중복을 피하기 위해 이 설명자의 기본 호버 대상을 비활성화합니다. 문서 수정 스탬프, 파일 유효성 및 클라이언트 상태로 오래된 결과를 거부하고 취소를 전달합니다. IDE Markdown 렌더러가 테마에 맞는 코드 블록을 표시하며 디버거 값 팝업은 별도로 유지됩니다. 모든 서버 결과 구역에서 네이티브 형식 분류에 연결된 인식 가능한 현지화된 기본 제공 형식 메타데이터만 통합하며 소스 형식 별칭과 펜스로 구분된 예제의 내용은 유지합니다.

Enter 대리자는 IDE 명령 안에서 한 번 교체하여 실행 취소를 유지하고 프로젝트 들여쓰기를 사용합니다. 렉서가 주석과 문자열을 제외하며 지시문, 여러 줄 헤더, 선택 영역, 여러 커서 및 현재 줄의 뒷부분을 포함해 처음 1 MiB를 넘는 분석은 일반 Enter로 돌아갑니다. 중괄호 설정만 변경하면 LSP를 다시 시작하지 않습니다. 서식과 진단은 서버가 담당합니다. 테스트는 렌더링, 비동기 결과 만료, 커서, 실행 취소 및 함수 입력 전후의 네이티브 진단을 검증합니다. Rider UI 수락 검증은 별도로 필요합니다.

## 컨텍스트 설정

컨텍스트 구성은 저장된 로컬 파일만 대상으로 상속된 템플릿을 Run/Check로 정리하고 연결 전용
필드를 지웁니다. Check는 스크립트 인수, 입력 및 JIT 경로도 지우며 적용 가능한 작업 디렉터리,
환경과 컴파일러 설정은 유지합니다. 구성 검증은 IDE 취소 예외를 구성 오류로 감싸지 않고 그대로 전달합니다.

Check는 항상 `--backend=vm`을 전달하며 저장된 Run 백엔드 설정은 변경하지 않습니다.

<a id="rider-platform-sdk"></a>

`localIdePath`가 없으면 두 Rider 프로젝트는 `rider(platformVersion) { useInstaller = false }`로 다중 OS SDK 아카이브를 해석합니다. 플랫폼 설치 프로그램은 개발 SDK가 아닙니다. `-PlocalIdePath=<directory>`는 기존 로컬 IDE를 선택합니다. 위의 고정 Rider/빌드 분기, 플러그인 의존성과 JDK 요구 사항을 유지하고 OS마다 별도로 검증하세요.
