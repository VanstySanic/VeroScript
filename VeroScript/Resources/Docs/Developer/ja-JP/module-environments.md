# 解決済みモジュール環境とネイティブ拡張

## 責務とエントリーポイント

Core は解決済みで有効な候補を含む不変のスナップショットを受け取り、共通のバックエンド選択契約を提供します。プロジェクト設定の読み取り、バージョン解決、インストール済み候補の提供はクライアントとホストが担当します。Core はダウンロード、展開、インストール、インストール先やシステムパスの探索を行いません。インストールだけですべての宣言を暗黙にインポートすることはありません。

`FModuleEnvironmentDesc` を作成し、`FModuleEnvironment::Create` を呼びます。返された共有の不変環境を `FCompileOptions::ModuleEnvironment` に設定し、実行前に `VeroScriptVm::SetModuleEnvironment` に渡します。ソース出力には `FCodegenOptions::ModuleEnvironment` を使います。ビルド可能な公開 SDK サンプルは `Resources/Examples/ModuleEnvironment` にあります。

## モジュールとスコープ

`Scopes` は所有者と直接依存を定義し、`EntryOwnerId` はエントリのスコープを指定します。`bHostProvided` は全モジュールからホストスコープへのアクセスを明示的に許可します。`SourceRoots` は所有者を持つ正規化済み絶対パスです。`Modules` は公開インポート名をモジュール ID、所有者、内容の識別情報、ファイルへ正確に対応付けます。`Source` を持つ `veroscript-module:/...` のメモリモジュールも指定できます。

通常のインポートは正確な対応表を参照し、競合するローカル候補があればエラーにします。明示的な `./` または `../` はインポート元からの相対パスだけを使い、ルートと依存の検証も受けます。対象がなくても別の検索ルートへ移りません。無効な対応を同名ファイルで代替しません。`import`、`include`、再エクスポートのインポート、マクロ探索は同じローダーを使います。既定ではソース範囲を厳密に制限し、環境や作業ディレクトリからの暗黙探索を無効にします。標準ライブラリにも検索ルートと所属スコープを明示してください。

モジュールは自身のソースと宣言された直接依存を使用できます。再エクスポートされたインターフェイスには通常の言語可視性規則が適用されます。ネイティブ宣言は `FBindingOrigin` を持ち、コンパイル時に所有者とインポート可視性を検証します。公開 API の署名は戻り値の利用に必要なネイティブ型を公開できます。これは依存の分離であり、信頼できないネイティブコードを実行するサンドボックスではありません。

カタログとリソース契約は一度公開し、その後は宣言とコールバックの識別情報を変更しません。`Apply` はコンパイル入力をトランザクションとして統合し、競合するアクティブなカタログを拒否します。同じ基底レジストリから共通のスナップショットを構築し、独立した型 ID 空間を持つバインディング同士を直接連結しないでください。明示的なソースの上書きは引き続き正確なパスに適用されます。

## リソースサービスとローカライズ

`FResourceProviderBinding` にはプロバイダー、所有者、安定した契約識別情報、必要ならリソース専用の `ModuleIds` を設定します。`IResourceProvider` は論理要求 `(ProviderId, ModuleId, Group, Path)`、キャンセル確認、バイト上限を受け取ります。パスはディレクトリ横断のない移植可能な相対パスです。正常な「存在しない」という結果と、I/O またはプロバイダーの失敗は区別します。存在するリソースには内容の識別情報が必須です。任意の物理絶対パスは診断情報であり、プロバイダーを迂回する権限ではありません。

実行時は `FModuleEnvironment::ReadResource`、コンパイルプロセッサーは `Context.ReadResource`、スクリプトコンパイル拡張は `read_resource(provider,module,group,path)` を使います。読み取った内容と不存在の観測は通常の依存記録に保存され、変更時に準備済み結果を無効にします。プロバイダーはスレッド安全で、上限とキャンセルを守り、無制限な読み取りを避ける必要があります。Core は出力上限と識別情報を再検証します。`MaxResourceBytes` は単一読み取りを制限し、コンパイルには入力合計と依存数の予算も適用されます。

環境を通じて既存の `I18n::FI18nServices`、型付きメッセージ、コンテキスト、制限を再利用します。パッケージのメタデータ JSON はクライアントが解釈し、Core は別のローカライズ形式を追加しません。ネイティブ拡張は `GetService(id,version)` でホストの型付きサービスを要求できます。決定的なサービスの識別情報はプロセッサーのキャッシュキーに含まれます。

## ネイティブ登録と有効期間

パッケージ管理対象のネイティブ ID（`entries.native[].id`）は `[a-z0-9]+(?:-[a-z0-9]+)*` に従います。スキーマは 2～64 文字を許可しますが、NUL 終端の `Descriptor.Id[64]` に収まる ID は最大 63 ASCII 文字です。記述子、マニフェスト、`ExpectedId` は一致させ、`entries.backends[].module` と静的登録キー `package:ID` も同じ ID を参照します。Core の低水準ローダーは長さ制限付き UTF-8 契約を検証し、パッケージ名の文法までは強制しません。同梱モジュールは `veroscript-sdl3`、`veroscript-rmlui`、`veroscript-stb`、`veroscript-font-backend`、`veroscript-gui-tools` を使用します。ID 変更時はライブラリー、カタログ、環境を一緒に再構築してください。

サービス ID、バックエンドの選択値、インターフェースの契約 ID はそれぞれのプロトコルに従います。特にネイティブ拡張 `veroscript-gui-tools` が要求するホストサービス `veroscript.gui.tools` は別の識別子であり、`ToolServiceId` の検索キーとして維持されます。

`VeroScriptNativeExtensionLoader.h` をインクルードします。`LoadNativeExtension` は明示的な絶対ライブラリファイルを要求し、パッケージ名、PATH、作業ディレクトリから探索しません。静的リンクのモジュールは同じ問い合わせ関数と所有者を指定して `QueryNativeExtension` を使います。C エクスポートシンボルは `veroscript_extension_query`、`NativeExtensionApiVersion` は **0.1.1** です。登録前に期待する ID、バージョン、ロールを検証します。

固定レイアウトの問い合わせ記述子は公開 SDK ABI、Core 実装の識別情報、コンパイラー/STL/ランタイム、アーキテクチャー/プラットフォーム、RTTI と例外モードが一致しなければなりません。C の問い合わせ後に渡す C++ オブジェクトまで安定した C ABI になるわけではありません。MSVC の動的拡張には共有 CRT が必要です。iOS と WebAssembly は静的登録を使います。バイナリーハッシュはキャッシュの識別情報であり、真正性や署名の検証ではありません。クライアントが信頼する成果物を検証し、不変ファイルのリースを保持します。

`FNativeExtensionRegistry::Add` でモジュールを準備します。`Create` は `INativeExtensionHost` を受け取り、関数、型/メンバー、ジェネリックテンプレート、別名、注釈、コンパイルプロセッサー、サービスプロバイダーを登録します。拡張はホストの仮想関数テーブルを使い、独自の静的 Core をリンクしません。登録はアトミックで、失敗時は以前のスナップショットを保持します。`GetBindings`、`GetProcessors`、`GetProviders`、`GetOwners`、`GetDependencies`、`GetFingerprint` で解決済み環境を構築します。利用可能な契約はパッケージバージョンから推測せず、検証済み記述子とバイナリー識別情報を返す `GetDependencies` から設定します。そのバージョンはネイティブコンポーネントのもので、配布パッケージのバージョンに自動置換されません。ネイティブバインディングの各プロバイダーには正確な外部依存契約が必要です。

ホストサービスは所有権を持つバージョン付きインターフェイスです。宣言を変更できるのは登録中だけです。登録後も保持したサービスはホストオブジェクトの作成、リソース読み取り、ブリッジ経由のコンパイル操作送信ができます。`MakeHostObject`/`MakeHostObjectNamed` と例外を送出しない破棄関数を使い、所有権の制御ブロックは Core に割り当てさせます。コールバック、プロセッサーのファクトリー/インスタンス、プロバイダー、サービス、外部へ渡したオブジェクトが存続する間は強参照でコードを保持します。同じ登録を所有するオブジェクトへの逆向きの強参照を保持せず、弱参照を使ってください。ファクトリーとデストラクターはエラーと所有権の契約に従い、デストラクターは例外を送出しません。

プロバイダーの登録では GUI やサービスを初期化しません。Core より上位で `(ServiceId, BackendId)` を選び、契約を検証して `CreateNativeService` を呼びます。返されたインスタンスは破棄まで環境とコードを保持します。JIT は既存の `LoadJitBackend` プロトコルを使います。

ネイティブのジェネリックテンプレートは既存のレジストリ契約に従います。不変カタログの公開前に、準備用のレジストリで `FHostBindingRegistry::InstantiateGenericHostType` を使い必要な具体型を生成します。実行中に公開済みカタログを変更しません。スクリプトのジェネリックは通常のコンパイラーによってインスタンス化されます。

## キャッシュ、パッケージ、再読み込み

コンパイルのフィンガープリントにはグラフ所有権、ソース識別情報、バインディング、プロセッサーのバージョンと設定、注釈、コンパイラーポリシーが含まれます。ホストの設定フィンガープリントを別に指定しなくても、ネイティブ登録の設定項目はプロセッサーの識別情報に自動的に入ります。リソースは実際の読み取り依存を追加します。実行専用の設定は別の実行識別情報を持ちます。識別不能または非決定的なネイティブホストサービスはプロセッサーのキャッシュを無効にします。他の不透明なコールバックや設定が出力に影響する場合も、ホストが安定した識別情報を提供してください。

`FExternalDependency` は正確な ID/バージョン/ABI/ビルド/内容識別情報を記録し、Core はバージョン解決をせず検証、統合、直列化します。要求契約はバイトコード、`.vslib`/`.vsapp`、リンク後にも保持されます。実行契約が不足または不一致なら初期化子や JIT の実行前に失敗します。未特殊化ジェネリックのパッケージソースは生成元のスコープを保持し、取り込むホストが互換バインディングと対応する要件を提供します。パッケージ内の補助モジュールの所有者も、ソースがライブラリに内包されていても、有効環境のスコープと直接依存を必要とします。製品とバイトコードのバージョンは **0.1.1** で、古い開発版バイトコードは受け付けません。

独立 AOT は同じ環境と生成宣言を使って純粋なスクリプト結果を出力できます。実行に必要なネイティブパッケージ契約は、対象ランタイムのアダプターが配備とバインディングを提供するまで出力を拒否します。拡張コールバックを無関係な extern 宣言に黙って置き換えません。

再読み込みは実行が休止した境界で新しい環境を公開します。進行中の処理は古いスナップショットとファイルリースを保持します。`NativeExtensionParallelRegistrations` を持たないモジュールの再登録にはプロセスの再起動が必要です。読み込み済みライブラリーの上書きは拒否し、不変のバージョン別パスを使います。ネイティブオブジェクトは登録識別情報を持つため、型名が同じでも古いオブジェクトを新しい登録のコールバックへ渡せません。VM/セッションのスレッド規則とキャンセル規則は引き続き適用され、ブロック中のネイティブコールバックを強制中断できません。既存ワーカーは元の環境を維持します。

## 検証と統合

`VeroScriptModuleEnvironmentTests`、`VeroScriptNativeExtensionTests`、公開ヘッダーのテスト、`VeroScriptModuleEnvironmentExample` が Core 契約を検証します。動的テストライブラリーは意図的に Core をリンクしません。各配布対象で個別に読み込みとデバイスの検証が必要です。インストールと環境選択はパッケージクライアント、CLI、Interop/各言語のアダプターが担当し、Core は解決済みスナップショットを受け取ります。

## コマンドラインのホストサービス

`CommandLine` ロール（`0x8`、パッケージ表記は `cli`）は対応 SDK の `veroscript.cli` バージョン `0.1.1` を使います。CLI は `ICommandLineExtensionService` を提供し、ネイティブモジュールは Create 中に `GetService` で取得して登録終了前に記述子を登録します。複数ロールのモジュールは通常の SDK ホストでサービスがなくても動作できる必要があります。パッケージクライアントは解析時およびサービスを持たないホストで CLI 専用項目を読み込みません。オプション解析とコマンド実行は CLI の責務です。

## バックエンド選択と環境アダプター

`VeroScriptBackendSelection.h` は `ResolveBackendSelection`、`SelectServiceBackend`、`ResolveExecutionBackends` を定義します。要求の省略は `SelectedBackends` を継承し、保存された空値は `none` を意味します。明示的な `auto` は設定済みの選択を上書きします。候補を ID 順に並べ、空、予約、重複 ID は拒否します。自動候補の再試行はファクトリ作成／準備失敗時だけです。キャンセルは伝播し、実行中の処理を再送しません。

`FBackendSelectionResult` は `Selected`、`Disabled`、`Unavailable`、`Failed` を区別し、`BackendId`、拒否された試行、エラーを保持します。任意の自動サービスが利用不可でも環境構築は成功し得るため、成功値と返されたファクトリの両方を確認します。`FInstalledEnvironment::GetBackendCandidates` はメタデータだけを読み、無効なパッケージを除外します。`LoadJitBackend` / `LoadVmBackend` は任意で選択結果を返し、`BackendDiagnostics` は自動提供者モジュールの利用不可診断を保持します。

`FModuleEnvironmentDesc` は `SelectedBackends`、`ServiceProviders`、`BackendDiagnostics`、`ExecutionBackends` を保持します。パッケージアダプターは不変の解決コールバックと `ExecutionBackends.Identity` を提供し、インストール済みスナップショットとコードの所有権を維持します。`AnalysisOnly` は実行リゾルバーを設定しません。`FNativeServiceProviderDesc` は選択ヘッダーで宣言され、ネイティブヘルパーは作成前にサービス／バックエンド／契約／バージョンを照合します。C、C++、C#、Python はネイティブ Session の解決を共有し、独自のパッケージ探索を実装しません。

`ResolveExecutionBackends` は確定前に出力コピーを準備します。明示的な `VmBackendFactory` / `VmBackendPath` は環境より優先し、ファクトリ、パス、明示的な解除は排他的です。`FallbackVmBackendFactory` / `FallbackVmBackendPath` は製品の組み立て入力で、自動選択で利用できる VM がない場合だけ使います。明示選択の失敗や無効化は上書きしません。`bDisableJitBackend` は環境の JIT 既定値を抑止します。Session は製品の代替 VM を保持し、`SetFallbackVmBackendFactory` で変更し、実行前の `SetVmBackendPath("auto")` で復元できます。JIT を含む実行開始で VM ドメインは固定され、Clear/reload でも解除されません。ファクトリ、インスタンス、保持コードの存続中はモジュールと環境を維持します。

モジュール環境では `Origin.ProviderId` を持つプロセッサーは、その提供者へアクセスできるソース所有者、または可視な公開 `Origin.ModulePath` のイベントだけを受信します。パッケージの生産者情報と捕捉済み所有者情報は物理パス検索に優先します。提供者のないグローバルなホスト処理と環境のないホストは従来の範囲を保ちます。スクリプト処理は引き続き `import compiler` または設定したルートで明示的に有効化します。イベントの選別はソース、リソース、ネイティブ依存へのアクセス権を与えません。
