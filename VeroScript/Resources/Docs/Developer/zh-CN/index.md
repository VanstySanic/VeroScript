# VeroScript 核心技术文档

[可替换 VM 后端](vm-backends.md)

本目录面向核心维护者与模块作者，说明由实现、公共头文件、构建目标和测试约束的技术契约；它不是用户教程，也不替代 API 参考。

## 编译管线

核心依次解析源、覆盖层、导入和包，进行词法分析、预处理、公共 AST 构建、语义/类型/泛型检查，生成带调试信息的字节码，最后建立模块或包并通过 VM 或 JIT 执行。每个阶段都必须保留可定位的结构化诊断，失败不会生成可部分使用的产物。

模块加载器以显式策略处理导入、隐式导入、循环关系和项目范围访问。导入路径、隐式导入、stdlib 搜索根、源覆盖层、`-D` 定义、预定义宏、宿主类型名称、循环导入策略和项目范围访问策略均为显式输入；路径、覆盖层和宏定义会规范化并参与输入指纹。宿主类型应在解析前注册。新增 stdlib 根目录时可合并相邻 `localization/` 树，因此打包的 stdlib 与其诊断资源仍是单一资源单元。

## 运行时不变量

`VeroScriptVm`、`FValue`、对象/容器句柄、函数值、宿主值和引用构成同一个所有权模型。析构、引用、变更事件、外部序列化及保留可调用对象都必须保持对象身份和生命周期。容器变更回调观察的是已完成的变更；回调异常不会回滚该变更。VM 所有权、字节码元数据、异常和控制流必须对所有后端一致。每个工作线程隔离脚本全局变量和静态字段，`channel<T>` 是跨工作线程共享状态的显式同步机制；任务注册表与任务 ID 也是 worker 本地的。会话和保留可调用对象的创建线程限制属于嵌入契约。宿主回调及可达宿主状态可能并发，生命周期和同步责任仍属于宿主。

## 执行后端与治理

参阅[核心架构与编译管线 — 公共/私有边界](architecture-and-pipeline.md#core-vm-ownership)。

`FJitPolicy` 和 `FJitStats` 描述自适应编译及最近一次执行。普通自由函数调用可按受限资格跨新 VM 复用会话代码；`FSessionJitCacheLimits` 的默认值为 8 MiB 原生代码和 32 MiB 总保留载荷，零禁止对应保留。缓存统计是当前上下文的累计、稳定计量，不是实时或进程峰值。

## 公共与私有边界

`Public/` 是受支持的原生 include 接口；`Private/` 包含 compiler、parser、VM、JIT 和实现细节。外部消费者和语言适配器必须使用公共头文件。源码树内目前只有少量 embedding/tooling/AOT 实现目标由 CMake 显式取得私有 include 路径；它们是需要核心负责人审查的 friend 依赖，不是安装或支持的 API，也不能随意扩大。

原生 C++ SDK 是要求构建匹配的静态库契约：消费者必须使用完全匹配的头文件、库、架构、运行库和 build identity 重新构建，不承诺跨构建的 C++ 二进制布局兼容。稳定的进程 ABI 仅指 C11 `VeroScriptInterop` 接口。公共 C++ 布局、enum 值、bytecode 格式、宿主绑定记录、诊断标识符或包元数据变更仍需兼容性审查。静态状态、泛型实例化和闭包捕获的所有权规则由核心定义，语言适配器不能重写。

## 本地化与运行时资源

部署必须包含标准库和本地化目录。加载器要求 `en-US` 基线、BCP 47 文化目录、匹配且唯一的 JSON 键，并可从多个模块根目录合并目录。语言集合动态发现；宿主 UI 文本与运行时诊断目录仍是独立资产。

## 会话、包与绑定

会话在运行期间拒绝会改变配置、加载、提交、重载、清理或绑定的操作。文件加载建立可重载路径，源字符串加载不会。包和重载采用暂存、验证、提交流程，失败始终保留上一可工作模块。反射、外部序列化、可保留可调用对象、字段/全局访问、拦截器和变更回调分别拥有其生命周期与空闲状态条件。

## 执行治理与 JIT 可观测性

VM 通过 `FExecutionLimits`、`FExecutionControl` 和 `FScriptCapabilities` 提供协作式执行治理。指令与墙钟限制为零表示执行不限。取消是协作式的：`RequestCancel` 标记共享控制对象，但不能强制终止已在宿主线程执行的原生或托管回调。

能力策略控制文件、环境、控制台和任务等标准库副作用。活动限制必须由 VM 强制实施，不能被 JIT 代码绕过。请求后端是 `Vm`、`Mixed` 或 `Jit`；调试器附加、保留初始化区间、有界清理以及需要解释器的执行治理会选择有效 VM 路径。

JIT 策略和 `FJitStats` 是公共可观测性契约。统计会区分编译、缓存、调度、回退/失败、预算、入口种类和快速路径活动。未受支持的编译是正常回退决定，除非执行本身失败，否则不是语言诊断。

## 编译器模型更新

parser/compiler 模型会把 static 类型修饰符和 static 数据成员保留为模块拥有的后备全局变量。静态访问通过声明类型层级和 interface 解析，泛型实例化会获得各自的替换后静态存储。static 类型限制是 compiler 强制的语义规则，不是 emitter 约定。

AST 还保留 lambda 捕获元数据、泛型类型参数与边界、alias、声明 annotation，以及诊断和工具链所需的源范围。任何消费 AST 的 lowering 路径都必须保持这些身份和源位置；不支持的捕获或泛型形式必须明确失败，不能近似。

## 变更时的依据

语言行为以公共头文件、核心实现、模块 CMake 文件、专门测试和发布资源清单为准。修改编译模型、后端、并发、包、本地化或稳定契约时，必须在同一变更中更新这些文档。标识符、路径、目标名、诊断 ID、JSON 键和版本值均按源码原样书写，不翻译。
