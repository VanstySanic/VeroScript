# バージョン管理と互換性


バージョン情報は、ソース ファイル、バイトコード キャッシュ、アプリケーション パッケージ、ライブラリ パッケージ、およびホスト バインディングに影響します。導入では、これらすべてのコンポーネントに対して相互互換性のある言語とランタイム バージョンを使用する必要があります。

次のコマンドを使用して、インストールされているバージョンを検査します。

```powershell
veroscript --version
```

## ファイル形式の互換性

製品、バイトコード、Interop ABI、WebAssembly ABI は初期バージョン `0.1.1` に統一されています。バイトコードの読み込みには形式バージョンとマジック値の完全一致が必要です。古い開発ビルドの `.vsbc`、`.vsapp`、`.vslib` はソースから再ビルドしてください。これらの古いバイナリとの互換性は提供しません。

- `.vs` はソースであり、通常は一致するコンパイラによって再チェックされる必要があります。
- `.vsbc` はバイトコード キャッシュであり、クロスバージョン配布形式として扱うべきではありません。
- `.vsapp` は実行可能なアプリケーション パッケージであり、そのランタイムとパッケージのバージョンが一致する必要があります。
- `.vslib` は、パブリック宣言、パッケージ バージョン、およびランタイムの互換性を維持する必要があるライブラリ パッケージです。

バージョンのアップグレード後、AOT またはホスト バインディングを使用する場合は、`--check` を再度実行し、パッケージを再構築し、ネイティブ アーティファクトを再生成または検証します。

現在の長さと線形インデックスの API は `int64` を使います。`--version` が同じ製品バージョンを示す場合も、この変更前のバイナリパッケージとバイトコードキャッシュは再ビルドしてください。更新時には対応する標準ライブラリを使用し、AOT 出力も再生成します。

## 言語の境界

現在の実装では、スクリプト ポインターのセマンティクスやスタンドアロンの C++ 概念の構文は提供されていません。可変個引数マクロの `__VA_OPT__`、ラムダ参照キャプチャ、参照の戻り、およびランタイム リフレクションはパブリック機能です。グラフィカル ユーザー インターフェイスはコア ランタイムの外部にあります。 C++ 構文が自動的に利用可能であると仮定するのではなく、実装された機能リストとバージョン ノートを信頼できるものとして扱います。

## ホストバインディングの互換性

ホスト バインディングは、関数名だけでなく、パラメーターの型、戻り値の型、コンテナー要素の型、キー/値の型、およびホスト オブジェクトの有効期間にも依存します。これらの境界が変更された場合は、バインディング カタログ、ホスト コード、およびスクリプト呼び出し元をまとめて更新し、チェックと実行時検証を繰り返します。
