# 診断とエラー

VeroScript の問題は通常、コンパイル診断と実行時エラーに分類されます。コンパイル診断は実行前に修正する必要があります。実行時エラーは、関連するパスが実行された場合にのみ発生します。

## コンパイル診断

コンパイルでは、字句および構文の構造、名前の検索、変換、オーバーロード、汎用制約、インターフェイスの実装、モジュールの可視性、および宣言規則がチェックされます。 `--check` を使用して、スクリプトを実行せずにコンパイルします。

```powershell
veroscript --check script.vs
```

チェック モードでは `main` が呼び出されないため、保存時のエディター チェック、CI 検証、パッケージ前の検証に適しています。通常、診断にはファイル、行と列の情報、および説明が含まれます。 1 つの根本原因により、関連する複数の診断が生成される可能性があるため、最初に発生したエラーを最初に修正してください。

## 実行時エラー

実行時のエラーは次の原因で発生する可能性があります。

- 範囲外の配列、文字列、またはコンテナーのインデックス。
- 条件が `false` の `assert`。
- バインドされていないデリゲートの呼び出し、またはその他の無効なランタイム操作。
- 失敗したファイル、ディレクトリ、または作業ディレクトリの操作。
- 閉じられたチャネルでの無効な操作。
- 再帰の深さ、タイプ操作、またはホストバインディングの制限。

実行時エラーは現在の実行を終了するか、ホストの実行結果とエラー ストリームを通じて報告されます。埋め込みホストは、`FRunResult` を検査し、必要に応じてエラー テキストと診断の場所を保存する必要があります。

VM、mixed、JIT の実行は同じ言語診断を使用します。JIT カーネルが算術または変換の
失敗を報告すると、ランタイムは利用可能な最適なソース位置に対応付け、より具体的な
ヘルパー診断があればそれを保持します。ホストはローカライズされた表示文字列を比較せず、
構造化された診断と位置を使用してください。

## スクリプト例外

`throw` は呼び出しを越えて伝播できるスクリプト値を送出し、`try`/`catch` で処理できます。
型付きハンドラーや `catch (...)` はスクリプト例外を処理できますが、失敗した `assert` を
含むエンジンまたはランタイムの障害は捕捉できません。どちらの失敗が伝播する場合でも
`finally` は実行されます。完全な構文と照合規則については、[制御フロー](../language-basics/control-flow.md#%E4%BE%8B%E5%A4%96)を参照してください。

## 言語と出力

コマンドライン ツールは診断言語を選択できます。

```powershell
veroscript --lang en --check script.vs
```

`VERO_LANG` ではデフォルトの言語も選択できます。スクリプトの標準出力と診断エラー出力は別個のストリームであり、ホスト統合では別個のままにする必要があります。

## 調査命令

参照ページでは、最初に宣言、スコープ、型、およびモジュールの可視性を確立する必要があります。実際のエラーの場合は、`--check` を使用してコンパイルの問題を排除し、最小限の入力で実行時のエラーを再現してから、ホストのアクセス許可、インポート パス、および標準ライブラリの検索パスを検査します。
