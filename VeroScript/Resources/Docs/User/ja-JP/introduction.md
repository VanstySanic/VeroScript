# VeroScript の概要

VeroScript は、組み込みでの使用を目的としたクロスプラットフォームのスクリプト言語です。使い慣れた C++ スタイルの構文を使用しますが、独自の型システム、モジュール システム、およびランタイムを持っています。ソース ファイルには `.vs` 拡張子が使用されます。

ネイティブ Runtime と SDK は Windows、Linux、macOS を対象としています。ブラウザーや JavaScript ホストでは [WebAssembly SDK](../../../../../Extensions/Platform/WebAssembly/Resources/Docs/User/ja-JP/index.md)、Android と iOS では[実験的なモバイルアダプター](../../../../../Extensions/Platform/Mobile/VeroScriptMobile/Resources/Docs/User/ja-JP/index.md)を使用します。利用できるコンポーネント、実行バックエンド、パッケージは対象環境と製品バージョンによって異なります。配置要件は[インストールと配布](../../../../../VeroScriptInstaller/Resources/Docs/User/ja-JP/index.md)および該当する SDK ガイドを参照してください。

VeroScript は、アプリケーションのロジックの一部をホスト プログラムとは独立して開発、チェック、実行、および再ロードする必要がある場合に役立ちます。典型的な例には、ゲーム ロジック、エディタ ツール、自動化タスク、アプリケーション拡張機能などがあります。

VeroScript は C++ のサブセットではなく、任意の C++ ソースを実行できるインタプリタでもありません。その構文とオブジェクト モデルは C++ の影響を受けていますが、この言語は独自の型セマンティクス、メモリ モデル、およびランタイム機能を定義しています。

## 実行モデル

スクリプトは通常、ソースから実行まで次のパスに従います。

```text
.vs ソース ファイル
  -> プリプロセス
  -> 字句解析と構文解析
  -> セマンティック分析とコンパイル
  -> バイトコード
  -> VeroScript VM による実行
```

プリプロセッサは、条件付きコンパイル、オブジェクト形式および関数形式のマクロ、文字列化、トークンの貼り付け、およびファイルのインクルードをサポートしています。コンパイラは、型チェック、オーバーロード解決、汎用インスタンス化、継承チェック、およびその他のセマンティック分析を実行します。モジュールは `import` および `export` で構成されます。モジュール ローダーは、モジュール パス、暗黙的なインポート、パッケージの依存関係、およびインポート サイクルを解決します。

通常の実行は仮想マシンに基づいており、デフォルトで混合バックエンドを使用します。サポートされているプラットフォームでは、より高速な実行バックエンドを使用でき、VM はフォールバックとして引き続き使用できます。 VeroScript はバイトコード キャッシュを生成して、後の起動時のコンパイル作業を軽減することもできます。

## 言語範囲

以下の表は、この言語の概要を示しています。詳細な構文と規則は、対応する言語リファレンスに記載されています。

|エリア |主な特長 |
| --- | --- |
|プリミティブ値 |整数、浮動小数点値、ブール値、文字列、ワイド文字列、列挙型、および `nullptr` |
|データ構造 |配列、マップ、セット、キュー、スタック、デキュー、優先キュー、チャネル |
|型システム | `struct`、`class`、`interface`、ネームスペース、タイプ エイリアス、およびアクセス制御 |
|オブジェクト指向 |継承、インターフェイス、仮想メソッド、オーバーライド、静的メンバー、コンストラクター、デストラクター |
|ジェネリックとオーバーロード |ジェネリック型と関数、`where` 制約、デフォルトの型パラメーター、関数/メソッド/演算子のオーバーロード |
|機能 |デフォルト引数、可変長引数、参照パラメータ、参照戻り値、参照別名、関数値、ラムダ、および参照キャプチャ |
|制御フロー |条件、ループ、`foreach`、`switch`、ジャンプ、ラベル、および return ステートメント |
|標準ライブラリ |文字列、パス、数学、書式設定、ファイル、入出力、同時実行性 |

値セマンティクスを持つデータには `struct` を使用し、ID と有効期間が共有されるデータには `class` を使用します。インターフェイス、継承、仮想ディスパッチ、およびジェネリックは、スクリプトで再利用可能な抽象化を構築するための主なメカニズムです。

[コマンドラインツール — バックエンドの選択](../../../../../VeroScriptCli/Resources/Docs/User/ja-JP/index.md#cli-backend-policy) を参照してください。

性能を測定するときはデバッグではない通常実行を使い、入力とバックエンドを固定し、通常のウォームアップを待ってから比較してください。バイトコード キャッシュは初回のコンパイル時間を減らしますが、スクリプトの実処理量は変えません。

## スクリプトの実行

コマンドライン ツールを使用してスクリプトを直接実行します。

```powershell
veroscript hello.vs
```

一般的なコマンドは次のとおりです。

```powershell
# Check without executing
veroscript --check hello.vs

# Start debugging mode
veroscript --debug hello.vs

# Package as a runnable application
veroscript --emit-package app.vsapp hello.vs
```

スクリプトは `main` エントリ ポイントを提供する必要があります。エントリ ポイントは `int` または `void` を返す場合があります。戻り値がプロセスの終了コードになるため、`int main` が推奨されます。 `void main` は引き続きサポートされ、正常終了として扱われます。一般的な形式は次の 2 つです。

```VeroScript
int main()
{
	print("Hello, VeroScript!");
	return 0;
}
```

```VeroScript
int main(string[] args)
{
	print(len(args));
	return 0;
}
```

コマンドライン引数は、`args` を通じて使用できます。スクリプト パス自体は `args` には含まれません。

VeroScript は 3 つの一般的なファイル形式を使用します。`.vsapp` は実行可能なアプリケーション パッケージ、`.vslib` は他のスクリプトによってインポートされたライブラリ パッケージ、`.vsbc` はバイトコード キャッシュ ファイルです。ライブラリ パッケージをアプリケーションとして直接実行することはできません。

## C++ ホストへの埋め込み

VeroScript の主な使用例の 1 つは、C++ アプリケーションに VeroScript を埋め込むことです。ホストは、スクリプトのロードまたはコンパイル、スクリプト関数、メソッド、およびコンストラクターの呼び出し、およびホスト機能をスクリプトに公開できます。使用可能なバインディングには、ネイティブ関数、ホスト型、フィールド、メソッド、演算子、ジェネリック型、型エイリアスが含まれます。

`VeroScriptEngine` は、スクリプトをチェックして実行するための高レベルのエントリ ポイントを提供します。 `VeroScriptSession` は、モジュール、バインディング、およびランタイム状態をより詳細に制御する必要がある統合を対象としています。ホストは、診断、出力、およびデバッグのコールバックを受信し、スクリプト タイプ、フィールド、およびグローバルを検査または変更することもできます。

非 C++ ホストは、`VeroScriptInterop` C11/C++17 ABI を使用できます。 C++ オブジェクト レイアウトを必要とせずに、言語間呼び出し、ホスト バインディング、パッケージ、リフレクション JSON、シリアル化、および不透明なセッションおよび値ハンドルを介したコールバックを提供します。ブラウザーと WebAssembly の統合では、別個の `VeroScriptWebAssembly` SDK を使用します。これは、TypeScript ラッパー、言語カタログ検出、メモリ内ソースのチェック/実行、および仮想インポート ファイルを提供します。

ホットリロードは明示的に有効化する機能で、既定では無効です。関数の識別子、キャプチャ名と型が互換なら、グローバル、オブジェクト、コンテナー、クロージャとキャプチャされた `this` を移行できます。活動中のチャネル、互換性のない型変更やキャプチャ構成の変更は拒否されます。ネイティブホストの外部副作用はスクリプト状態のトランザクションに含まれません。

## ツールと AOT

言語ツールは、コンパイラーの前処理と意味分析の基礎を共有します。これらは、診断、ドキュメントのアウトライン、セマンティック トークン、ナビゲーション、ホバー情報、補完、署名ヘルプ、参照検索、名前変更、および書式設定を提供できます。デバッガーは DAP を使用し、VM パスを通じて実行されます。

動的読み込みを必要としない展開の場合、AOT バックエンドは C++17 ソースを生成し、結果をネイティブ コンパイラーに渡すことができます。 AOT と VM の実行は、展開の選択肢が異なります。適切なものは、ホスト アプリケーションのビルド、配布、およびデバッグの要件によって異なります。

## バージョンに関するメモ

この文書では、VeroScript の現在の公開機能について説明します。スクリプト、バイトコード キャッシュ、パッケージ、およびホスト バインディングは、互換性のあるバージョンを使用する必要があります。

VeroScript は、独自の実行時の境界を意図的に維持します。現在のリリースでは、スクリプト ポインターのセマンティクスやスタンドアロンの C++ 概念構文は提供されていません。可変個引数マクロの `__VA_OPT__`、参照キャプチャ、参照戻り、およびランタイム リフレクションは、VeroScript 独自の型と有効期間のルールに従うパブリック機能です。グラフィカル ユーザー インターフェイスはコア ランタイムの外部にあります。

[ドキュメント ホーム](../../../../../Resources/Docs/User/ja-JP/index.md) から始めます。構文とセマンティクスについては [言語の基本](language-basics/index.md)、ライブラリ API については [標準ライブラリ リファレンス](standard-library/index.md)、コマンド ライン、デバッグ、AOT、ホスト統合、WebAssembly/WASM、および Interop SDK については [ツールチェーン](../../../../../Resources/Docs/User/ja-JP/toolchain/index.md) を参照してください。

## サービスのバックエンド選択

ホストまたは CLI がインストール済み／配備済みモジュール環境を渡す場合、省略したバックエンドは `services.<service>.backend` を継承します。設定もない場合、`auto` は有効な候補をバックエンド ID の昇順で試し、互換性があり作成できる最初のファクトリを選択します。明示した ID、ファクトリ、ファイル／ディレクトリが優先され、失敗時に別の ID へ切り替えません。`asmjit` はバックエンド ID、`vs-asmjit` はインストール用パッケージ名です。

明示的な `auto` は環境の既定値を上書きします。`none` と、設定に明示的に保存された空のバックエンド値はサービスを無効化します。未設定とは異なります。製品に組み込んだ VM は自動パッケージ選択で使用可能なインタープリタが見つからない場合のフォールバックです。任意の JIT がない場合、Mixed は VM を使用し、強制 JIT は互換バックエンドを必要とします。必須サービスの候補が全て失敗した場合はエラーです。

選択はファクトリ作成と準備時に行い、業務処理の実行中には変更しません。実行開始後のエラーで処理を再実行しません。インタープリタの実行ドメインは開始後に固定されます。制限、キャンセル、有界クリーンアップ、デバッグ、ホットリロードの規則は変わりません。インスタンスはモジュールと環境の所有者を保持します。
