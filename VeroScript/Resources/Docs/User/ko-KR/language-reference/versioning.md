# 버전 관리 및 호환성


버전 정보는 소스 파일, 바이트코드 캐시, 애플리케이션 패키지, 라이브러리 패키지 및 호스트 바인딩에 영향을 미칩니다. 배포에서는 이러한 모든 구성 요소에 대해 상호 호환되는 언어 및 런타임 버전을 사용해야 합니다.

다음을 사용하여 설치된 버전을 검사합니다.

```powershell
veroscript --version
```

## 파일 형식 호환성

제품, 바이트코드, Interop ABI 및 WebAssembly ABI는 초기 버전 `0.1.1`을 사용합니다. 바이트코드 로더는 형식 버전과 매직 값의 정확한 일치를 요구합니다. 이전 개발 빌드의 `.vsbc`, `.vsapp`, `.vslib` 파일은 소스에서 다시 빌드하십시오. 이전 바이너리와의 호환성은 제공하지 않습니다.

- `.vs`은 소스이며 일반적으로 일치하는 컴파일러에서 다시 확인해야 합니다.
- `.vsbc`은 바이트코드 캐시이므로 버전 간 배포 형식으로 처리하면 안 됩니다.
- `.vsapp`는 실행 가능한 애플리케이션 패키지이며 런타임 및 패키지 버전과 일치해야 합니다.
- `.vslib`은 공개 선언, 패키지 버전 및 런타임이 호환되어야 하는 라이브러리 패키지입니다.

버전 업그레이드 후 `--check`을 다시 실행하고, 패키지를 다시 빌드하고, AOT 또는 호스트 바인딩을 사용할 때 기본 아티팩트를 재생성하거나 유효성을 검사하십시오.

현재 길이와 선형 인덱스 API는 `int64`를 사용합니다. `--version`이 같은 제품 버전을 표시하더라도 이 변경 이전의 바이너리 패키지와 바이트코드 캐시는 다시 빌드하세요. 업그레이드할 때 일치하는 표준 라이브러리를 사용하고 AOT 결과물도 다시 생성하세요.

## 언어 경계

현재 구현에서는 스크립트 포인터 의미 체계나 독립형 C++ 개념 구문을 제공하지 않습니다. 가변 매크로용 `__VA_OPT__`, 람다 참조 캡처, 참조 반환 및 런타임 반영은 공개 기능입니다. 그래픽 사용자 인터페이스는 핵심 런타임 외부에 있습니다. C++ 구문을 자동으로 사용할 수 있다고 가정하는 대신 구현된 기능 목록과 버전 참고 사항을 신뢰할 수 있는 것으로 간주하십시오.

## 호스트 바인딩 호환성

호스트 바인딩은 함수 이름뿐만 아니라 매개변수 유형, 반환 유형, 컨테이너 요소 유형, 키/값 유형 및 호스트 개체 수명에 따라 달라집니다. 이러한 경계가 변경되면 바인딩 카탈로그, 호스트 코드 및 스크립트 호출자를 함께 업데이트한 다음 확인 및 런타임 유효성 검사를 반복하세요.
