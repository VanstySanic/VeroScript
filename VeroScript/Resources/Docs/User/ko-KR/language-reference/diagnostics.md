# 진단 및 오류

VeroScript 문제는 일반적으로 컴파일 진단 및 런타임 오류에 속합니다. 실행 전에 컴파일 진단을 수정해야 합니다. 런타임 오류는 해당 경로가 실행될 때만 발생합니다.

## 진단 컴파일

컴파일은 어휘 및 구문 구조, 이름 조회, 변환, 오버로드, 일반 제약 조건, 인터페이스 구현, 모듈 가시성 및 선언 규칙을 확인합니다. 스크립트를 실행하지 않고 컴파일하려면 `--check`을 사용하십시오.

```powershell
veroscript --check script.vs
```

확인 모드는 `main`을 호출하지 않으므로 저장 시간 편집기 확인, CI 유효성 검사 및 사전 패키지 확인에 적합합니다. 진단에는 일반적으로 파일, 행 및 열 정보, 설명이 포함됩니다. 하나의 근본 원인으로 인해 여러 가지 관련 진단이 생성될 수 있으므로 가장 빠른 오류를 먼저 수정하세요.

## 런타임 오류

런타임 오류는 다음에서 발생할 수 있습니다.

- 범위를 벗어난 배열, 문자열 또는 컨테이너 인덱스
- 조건이 `false`인 `assert`
- 바인딩되지 않은 대리자 호출 또는 기타 잘못된 런타임 작업
- 실패한 파일, 디렉터리 또는 작업 디렉터리 작업
- 닫힌 채널에서의 유효하지 않은 작업
- 재귀 깊이, 유형 연산 또는 호스트 바인딩 제한.

런타임 오류는 현재 실행을 종료하거나 호스트의 실행 결과 및 오류 스트림을 통해 보고됩니다. 포함 호스트는 `FRunResult`을 검사하고 필요한 경우 오류 텍스트와 진단 위치를 보존해야 합니다.

VM, 혼합 및 JIT 실행은 동일한 언어 진단을 사용합니다. JIT 커널이 산술 또는 변환 실패를
보고하면 런타임은 사용 가능한 최선의 소스 위치로 매핑하고 더 구체적인 헬퍼 진단을 유지합니다.
호스트는 지역화된 표시 문자열을 비교하지 말고 구조화된 진단과 위치를 사용해야 합니다.

## 스크립트 예외

`throw`는 호출을 넘어 전파되어 `try`/`catch`로 처리할 수 있는 스크립트 값을 던집니다.
형식이 지정된 처리기 또는 `catch (...)`는 스크립트 예외를 처리할 수 있지만, 실패한 `assert`를
포함한 엔진/런타임 오류는 가로챌 수 없습니다. 어느 종류의 실패가 전파되더라도 `finally` 블록은
실행됩니다. 전체 구문과 일치 규칙은 [제어 흐름](../language-basics/control-flow.md#%EC%98%88%EC%99%B8)을 참조하세요.

## 언어 및 출력

명령줄 도구는 진단 언어를 선택할 수 있습니다.

```powershell
veroscript --lang en --check script.vs
```

`VERO_LANG`은 기본 언어도 선택할 수 있습니다. 스크립트 표준 출력과 진단 오류 출력은 별도의 스트림이므로 호스트 통합에서 별도로 유지되어야 합니다.

## 조사명령

참조 페이지에서는 선언, 범위, 유형 및 모듈 가시성을 먼저 설정해야 합니다. 실제 오류의 경우 `--check`을 사용하여 컴파일 문제를 제거하고 최소한의 입력으로 런타임 오류를 재현한 다음 호스트 권한, 가져오기 경로 및 표준 라이브러리 검색 경로를 검사합니다.
