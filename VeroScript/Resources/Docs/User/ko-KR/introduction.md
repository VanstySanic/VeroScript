# VeroScript 소개

VeroScript는 임베디드용으로 만들어진 크로스 플랫폼 스크립팅 언어입니다. 익숙한 C++ 스타일 구문을 사용하지만 자체 유형 시스템, 모듈 시스템 및 런타임이 있습니다. 소스 파일은 `.vs` 확장자를 사용합니다.

네이티브 Runtime과 SDK는 Windows, Linux, macOS를 대상으로 합니다. 브라우저와 JavaScript 호스트는 [WebAssembly SDK](../../../../../Extensions/Platform/WebAssembly/Resources/Docs/User/ko-KR/index.md)를 사용하고 Android와 iOS는 [실험적 모바일 어댑터](../../../../../Extensions/Platform/Mobile/VeroScriptMobile/Resources/Docs/User/ko-KR/index.md)를 사용합니다. 사용 가능한 구성 요소, 실행 백엔드 및 패키지는 대상과 제품 버전에 따라 달라집니다. 배포 요구 사항은 [설치와 배포](../../../../../VeroScriptInstaller/Resources/Docs/User/ko-KR/index.md) 및 해당 SDK 가이드를 참조하세요.

VeroScript는 응용 프로그램 논리의 일부를 호스트 프로그램과 독립적으로 개발, 확인, 실행 및 다시 로드해야 할 때 유용합니다. 일반적인 예로는 게임 로직, 편집기 도구, 자동화 작업 및 애플리케이션 확장이 있습니다.

VeroScript는 C++의 하위 집합이 아니며 임의의 C++ 소스를 실행할 수 있는 인터프리터도 아닙니다. 구문과 개체 모델은 C++의 영향을 받지만 언어는 고유한 유형 의미, 메모리 모델 및 런타임 기능을 정의합니다.

## 실행 모델

스크립트는 일반적으로 소스에서 실행까지 다음 경로를 따릅니다.

```text
.vs 소스 파일
  -> 전처리
  -> 어휘 및 구문 분석
  -> 의미 분석 및 컴파일
  -> 바이트코드
  -> VeroScript VM 실행
```

전처리기는 조건부 컴파일, 객체형 및 함수형 매크로, 문자열화, 토큰 붙여넣기 및 파일 포함을 지원합니다. 컴파일러는 유형 검사, 오버로드 해결, 일반 인스턴스화, 상속 검사 및 기타 의미 체계 분석을 수행합니다. 모듈은 `import` 및 `export`로 구성됩니다. 모듈 로더는 모듈 경로, 암시적 가져오기, 패키지 종속성 및 가져오기 주기를 해결합니다.

일반 실행은 가상 머신을 기반으로 하며 기본적으로 혼합 백엔드를 사용합니다. 지원되는 플랫폼에서는 더 빠른 실행 백엔드를 사용할 수 있으며 VM은 대체 수단으로 계속 사용할 수 있습니다. VeroScript는 나중에 실행 시 컴파일 작업을 줄이기 위해 바이트코드 캐시를 생성할 수도 있습니다.

## 언어 범위

아래 표는 언어에 대한 간략한 개요를 제공합니다. 자세한 구문과 규칙은 해당 언어 참조에 속합니다.

| 면적 | 주요 기능 |
| --- | --- |
| 원시 값 | 정수, 부동 소수점 값, 부울, 문자열, 넓은 문자열, 열거형 및 `nullptr` |
| 데이터 구조 | 배열, 맵, 세트, 큐, 스택, 데크, 우선순위 큐 및 채널 |
| 유형 시스템 | `struct`, `class`, `interface`, 네임스페이스, 유형 별칭 및 액세스 제어 |
| 객체지향 | 상속, 인터페이스, 가상 메서드, 재정의, 정적 멤버, 생성자 및 소멸자 |
| 제네릭 및 오버로드 | 일반 유형 및 함수, `where` 제약 조건, 기본 유형 매개변수 및 함수/메서드/연산자 오버로드 |
| 기능 | 기본 인수, 가변 인수, 참조 매개변수, 참조 반환, 참조 별칭, 함수 값, 람다 및 참조 캡처 |
| 제어 흐름 | 조건, 루프, `foreach`, `switch`, 점프, 레이블 및 반환 문 |
| 표준 라이브러리 | 문자열, 경로, 수학, 형식 지정, 파일, 입력/출력 및 동시성 |

값 의미 체계가 있는 데이터에는 `struct`을 사용하고 공유 ID 및 수명이 있는 데이터에는 `class`을 사용합니다. 인터페이스, 상속, 가상 디스패치 및 제네릭은 스크립트에서 재사용 가능한 추상화를 구축하기 위한 주요 메커니즘입니다.

[명령줄 도구 — 백엔드 선택](../../../../../VeroScriptCli/Resources/Docs/User/ko-KR/index.md#cli-backend-policy)을 참조하세요.

성능을 측정할 때는 디버그가 아닌 일반 실행을 사용하고 입력과 백엔드를 고정한 뒤 정상적인 워밍업을 기다리세요. 바이트코드 캐시는 초기 컴파일 비용만 줄이며 스크립트가 실제로 수행하는 작업은 바꾸지 않습니다.

## 스크립트 실행

명령줄 도구를 사용하여 스크립트를 직접 실행합니다.

```powershell
veroscript hello.vs
```

일반적인 명령은 다음과 같습니다.

```powershell
# Check without executing
veroscript --check hello.vs

# Start debugging mode
veroscript --debug hello.vs

# Package as a runnable application
veroscript --emit-package app.vsapp hello.vs
```

스크립트는 `main` 진입점을 제공해야 합니다. 진입점은 `int` 또는 `void`를 반환할 수 있습니다. `int main`은 반환 값이 프로세스 종료 코드가 되므로 권장됩니다. `void main`는 계속 지원되며 성공적인 종료로 처리됩니다. 두 가지 일반적인 형태는 다음과 같습니다.

```VeroScript
int main()
{
	print("Hello, VeroScript!");
	return 0;
}
```

```VeroScript
int main(string[] args)
{
	print(len(args));
	return 0;
}
```

명령줄 인수는 `args`을 통해 사용할 수 있습니다. 스크립트 경로 자체는 `args`에 포함되지 않습니다.

VeroScript는 세 가지 일반적인 파일 형식을 사용합니다. `.vsapp`은 실행 가능한 애플리케이션 패키지이고, `.vslib`은 다른 스크립트에서 가져온 라이브러리 패키지이며, `.vsbc`는 바이트코드 캐시 파일입니다. 라이브러리 패키지는 애플리케이션으로 직접 실행할 수 없습니다.

## C++ 호스트에 포함

VeroScript의 주요 사용 사례 중 하나는 이를 C++ 애플리케이션에 포함하는 것입니다. 호스트는 스크립트를 로드 또는 컴파일하고, 스크립트 함수, 메서드 및 생성자를 호출하고, 호스트 기능을 스크립트에 노출할 수 있습니다. 사용 가능한 바인딩에는 기본 함수, 호스트 유형, 필드, 메소드, 연산자, 일반 유형 및 유형 별칭이 포함됩니다.

`VeroScriptEngine`은 스크립트 확인 및 실행을 위한 상위 수준 진입점을 제공합니다. `VeroScriptSession`은 모듈, 바인딩 및 런타임 상태를 보다 세밀하게 제어해야 하는 통합을 위해 고안되었습니다. 호스트는 진단, 출력 및 디버깅 콜백을 수신하고 스크립트 유형, 필드 및 전역을 검사하거나 수정할 수도 있습니다.

C++ 이외의 호스트는 `VeroScriptInterop` C11/C++17 ABI를 사용할 수 있습니다. C++ 개체 레이아웃이 필요 없이 불투명 세션 및 값 핸들을 통해 언어 간 호출, 호스트 바인딩, 패키지, 반사 JSON, 직렬화 및 콜백을 제공합니다. 브라우저 및 WebAssembly 통합은 TypeScript 래퍼, 언어 카탈로그 검색, 메모리 내 소스 확인/실행 및 가상 가져온 파일을 제공하는 별도의 `VeroScriptWebAssembly` SDK를 사용합니다.

핫 리로드는 명시적으로 활성화하며 기본값은 비활성입니다. 함수 식별자와 캡처 이름·타입이 호환되면 전역 상태, 객체, 컨테이너와 캡처된 `this`를 포함한 클로저를 이전할 수 있습니다. 활성 채널, 호환되지 않는 타입 변경 및 캡처 구성 변경은 거부됩니다. 네이티브 호스트의 외부 부작용은 스크립트 상태 트랜잭션에 포함되지 않습니다.

## 툴링 및 AOT

언어 도구는 컴파일러의 전처리 및 의미 분석 기반을 공유합니다. 진단, 문서 개요, 의미 체계 토큰, 탐색, 가리키기 정보, 완성, 서명 도움말, 참조 검색, 이름 바꾸기 및 서식 지정을 제공할 수 있습니다. 디버거는 DAP를 사용하고 VM 경로를 통해 실행됩니다.

동적 로딩이 필요하지 않은 배포의 경우 AOT 백엔드는 C++17 소스를 생성하고 결과를 기본 컴파일러에 전달할 수 있습니다. AOT와 VM 실행은 서로 다른 배포 선택입니다. 적절한 것은 호스트 애플리케이션의 빌드, 배포 및 디버깅 요구 사항에 따라 다릅니다.

## 버전 참고

이 문서에서는 VeroScript의 현재 공개 기능에 대해 설명합니다. 스크립트, 바이트코드 캐시, 패키지 및 호스트 바인딩은 호환되는 버전을 사용해야 합니다.

VeroScript는 의도적으로 자체 런타임 경계를 유지합니다. 현재 릴리스에서는 스크립트 포인터 의미 체계나 독립형 C++ 개념 구문을 제공하지 않습니다. 가변 매크로, 참조 캡처, 참조 반환 및 런타임 반영을 위한 `__VA_OPT__`은 VeroScript의 자체 유형 및 수명 규칙이 적용되는 공개 기능입니다. 그래픽 사용자 인터페이스는 핵심 런타임 외부에 있습니다.

[문서 홈](../../../../../Resources/Docs/User/ko-KR/index.md)으로 시작합니다. 구문 및 의미 체계는 [언어 기본 사항](language-basics/index.md), 라이브러리 API는 [표준 라이브러리 참조](standard-library/index.md), 명령줄, 디버깅, AOT, 호스트 통합, 웹/WASM 및 Interop SDK는 [도구 체인](../../../../../Resources/Docs/User/ko-KR/toolchain/index.md)을 참조하세요.

## 서비스 백엔드 선택

호스트나 CLI가 설치 또는 배포된 모듈 환경을 제공하면 생략한 백엔드는 `services.<service>.backend`를 상속합니다. 환경에도 설정이 없으면 `auto`가 활성 후보를 백엔드 ID 오름차순으로 시도하여 호환되며 생성 가능한 첫 팩토리를 선택합니다. 명시한 ID, 팩토리, 파일/디렉터리가 우선하며 실패해도 다른 ID로 바꾸지 않습니다. `asmjit`는 백엔드 ID이고 `vs-asmjit`는 설치 패키지 이름입니다.

명시적인 `auto`는 환경 기본값을 재정의합니다. `none`과 설정에 명시적으로 저장된 빈 백엔드 값은 서비스를 비활성화합니다. 설정 생략과는 다릅니다. 제품에 조립된 VM은 자동 패키지 선택으로 사용 가능한 인터프리터를 찾지 못했을 때만 사용됩니다. 선택적 JIT가 없으면 Mixed는 VM을 사용하지만 강제 JIT는 호환 백엔드를 요구합니다. 필수 서비스에 사용 가능한 후보가 없으면 오류를 보고합니다.

선택은 팩토리 생성과 준비 단계에서만 수행되며 업무 실행 중에는 백엔드를 교체하지 않습니다. 진입 후 오류로 작업을 재실행하지 않습니다. 인터프리터 실행 도메인은 실행 시작 후 고정됩니다. 제한, 취소, 유한 정리, 디버깅 및 핫 리로드 규칙은 유지됩니다. 인스턴스는 모듈과 환경 소유자를 유지합니다.
