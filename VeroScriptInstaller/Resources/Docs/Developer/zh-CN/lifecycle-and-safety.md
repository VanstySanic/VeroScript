# 安装程序生命周期与安全性

## 组件与暂存

`Core/` 负责清单验证、捆绑归档、包元数据、路径安全、平台信息、重试和安装引擎。`App/` 负责图形宿主和本地化进度；`Tool/` 负责捆绑/构建入口。核心可以脱离图形应用使用。

安装会为选定组件暂存内容、验证复制的文件、写入安装记录，再提交状态转换。记录跟踪产品标识、组件根目录、归属文件、清单指纹及运行时 `PATH` 变更。

在变更 `PATH` 或活动组件目录前，引擎会在每个受影响组件根目录旁写入原子事务日志，并持有每父目录的独占事务锁。之后的安装、修复、卸载或 `LoadRecordAsync` 会恢复中断的已准备事务，或完成已持久提交事务的清理。日志副本按保守规则协调，因此在最终提交标记持久化期间崩溃不会回滚已完成提交。按确定性选中的副本是持久权威，最后才删除；提交后备份清理失败由后续操作重试，且不会把成功安装报告为回滚。成功回滚也会在移除日志前记录终止状态，以免部分删除日志后，在新安装完成时重放 `PATH` 变更。

因此，`LoadRecordAsync` 不是只读检查 API：它会在打开 `.veroscript-install.json` 前，恢复所请求组件根目录旁的事务。GUI 修复/卸载启动和 Tool 记录加载走同一路径，所以在中断操作中移入备份的记录可在界面展示前还原。活动中的并发安装程序可能造成锁定错误；恢复不得绕过该锁。

安装会在加载旧记录前检查选定的目标根目录，以及提供 `ExistingInstallRecordPath` 时该路径所包含的根目录。这允许即使新的目标不同，仍可通过旧记录根目录重试中断的迁移。状态为 `prepared`、`committed`、`rolledback`；终止日志只是清理标记，绝不能重放 `PATH` 变更。

## 安全边界

目标根目录不得与受保护负载或彼此重叠。受管目标及其祖先会检查链接。相对路径在目标根目录下解析；路径遍历、绝对路径逃逸、外来条目和含义不明确的所有权都必须安全失败。重试文件系统操作不得把部分操作报告为成功。

## 修复、迁移与卸载

修复要求记录中的产品版本、平台、架构和清单指纹匹配。迁移会在移动前验证现有/同级记录、所有权、目标安全性和暂存路径。卸载先暂存全部非归属文件，再移除归属 `PATH` 条目，并把所有组件作为一个可恢复事务提交。它只移除记录文件和归属的 `PATH` 条目，保留非归属文件。持久提交前失败会回滚；回滚失败会留下日志/备份供下一次恢复。持久提交后的清理失败不会把成功报告为失败。

操作活动或等待恢复时，不要手动删除事务日志、暂存目录或备份。应使用原始记录/根目录重新打开相同产品操作。恢复再次失败时应保留文件，检查报告的文件系统或 `PATH` 错误后再重试。

## 回归覆盖

测试套件覆盖安装、更新、迁移、可选组件移除、修复、卸载、用户文件保留和 `PATH` 所有权。恢复用例包括多父目录日志协调、陈旧终止日志、GUI 启动前记录加载以及通过旧记录根目录重试迁移。按[发行验收流程](release-validation.md)验证候选产物并记录结果，区分引擎测试与人工 GUI 测试。
